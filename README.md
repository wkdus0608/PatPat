# PatPat

## 사용자 가이드

오늘 있었던 일과 녹음본을 사용해 **아이별 알림장을 확정하고, 관찰일지 한 건을** Word로 내려받는 것까지 진행하면 됩니다.

### 1. 회원가입

로그인 화면에서 회원가입을 통해 계정을 만듭니다

### 2. 반 정보, 아동 명단, 말투 설정

1. **반 정보** 입력

2. **자주 쓰는 장소**와 **자주 쓰는 시간**은 아래 값을 한 줄에 하나씩 입력한 뒤 **다음**을 누릅니다.

   **자주 쓰는 장소 (MVP 발표에 사용했던 예시)**

   ```text
   유희실
   바깥놀이터
   교실 역할놀이 영역
   교실 쌓기놀이 영역
   ```

   **자주 쓰는 시간 (MVP 발표에 사용했던 예시)**

   ```text
   오전 모임
   오전 바깥놀이
   오전 자유놀이
   ```

3. **아동 명단**에서 아이를 한 명씩 입력하고 **아동 추가**를 누릅니다.&#x20;

4. **아이별 특성**에서 성별과 생년월일을 선택하고, 특성을 붙여 넣습니다. **(MVP 발표에 사용했던 예시)**

   | 아동 | 성별 | 생년월일       | 특성                                                                                |
   | -- | -- | ---------- | --------------------------------------------------------------------------------- |
   | 도윤 | 남  | 2022-06-14 | 자연물의 색과 모양을 비교하기 좋아하고, 자신이 정한 기준을 말이나 손짓으로 설명합니다.                                 |
   | 서아 | 여  | 2022-08-23 | 역할놀이를 좋아하고 친구에게 어떤 역할을 하고 싶은지 먼저 물어보는 편입니다.                                       |
   | 하준 | 남  | 2022-09-07 | 블록으로 다리를 만들고, 무너지면 받침을 바꿔 다시 시험해 봅니다. 친구와 같은 물건을 쓰고 싶을 때 말로 차례를 부탁하는 연습을 하고 있습니다. |

5. **내 말투 알려주기**의 **알림장 예시** 칸에 아래 문장을 붙여 넣고 **일지 작성 시작**을 누릅니다. 나중에 알림장이 `~했어요`, `~했답니다`, `^^` 같은 표현을 참고하는지 확인합니다.

   ```text
   오늘은 아이들과 창가에서 빗방울이 유리에 맺히는 모습을 살펴보았어요^^
   지우는 빗방울이 지나간 길을 손가락으로 따라가며 친구에게 보여 주었답니다^^
   집에서도 아이와 함께 창밖 풍경을 이야기 나누어 보시면 좋을 것 같아요^^
   ```

### 3. 준비된 녹음 파일 올리기

1. 하단 **녹음** 탭에서 **녹음 파일 올리기**를 누릅니다. (직접 녹음하셔도 됩니다)
2. 녹음은 **올린 날짜**에 등록됩니다. 아래에서 알림장 날짜를 같은 날로 맞춰야 파일을 선택할 수 있습니다.

### 4. 공통 활동과 아이별 관찰 입력

**일지 작성 → 알림장**을 열고 날짜를 녹음 파일을 올린 날로 맞춥니다. 세 아이 모두 출석한 상황입니다.

| 입력 칸     | 장소         | 시간      | 선택할 영역     |
| -------- | ---------- | ------- | ---------- |
| 공통 내용    | 유희실        | 오전 모임   | —          |
| 도윤 관찰 내용 | 바깥놀이터      | 오전 바깥놀이 | 자연탐구, 의사소통 |
| 서아 관찰 내용 | 교실 역할놀이 영역 | 오전 자유놀이 | 의사소통, 사회관계 |
| 하준 관찰 내용 | 교실 쌓기놀이 영역 | 오전 자유놀이 | 자연탐구, 사회관계 |

**공통 내용**

```text
햇살반 아이들과 가을 그림책을 함께 읽었다. 책을 읽은 뒤 그림 속 나뭇잎을 보며 어떤 색이 있는지 이야기했다.
```

**도윤 관찰 내용**

```text
바깥놀이터 화단 옆에서 낙엽을 주워 바구니에 담았다. 낙엽을 바닥에 펼쳐 빨간 잎과 노란 잎을 따로 모았다.
```

**서아 관찰 내용**

```text
역할놀이 영역에서 종이빵을 접시에 진열하고 계산대 옆에 종이봉투를 놓았다.
```

**하준 관찰 내용**

```text
쌓기놀이 영역에서 받침 블록 위에 긴 판을 놓고 자동차가 지나갈 다리를 만들었다.
```

화면 아래 **녹음 목록**을 열고 방금 올린 파일 3개를 선택합니다. 파일이 보이지 않으면 **녹음 새로고침**을 누르고 날짜를 확인합니다. **입력 저장 → 다음**을 누른 뒤, **아이별 영역 확인** 화면에서 선택한 영역과 녹음 3개를 확인하고 **초안 만들기**를 누릅니다.



녹음-도윤

도윤이는 빨간 잎과 노란 잎을 따로 모았어요. 두 가지 색이 함께 있는 잎을 발견하고는 “이건 두 색이 다 있으니까 가운데에 놓을래요”라고 말했어요. 그리고 잎을 친구에게 보여 주면서 색이 바뀌는 부분을 손가락으로 짚었어요.

녹음-서아

서아는 종이 빵을 접시에 놓고 친구에게 “손님 할래요, 빵 만드는 사람 할래요?”라고 물었어요. 친구가 빵을 만들겠다고 하자 그릇을 건네고, 자기는 주문을 받겠다고 했어요. 이후 바깥놀이터에서 빨간 삽 손잡이를 잡고 있다가 손을 놓으면서 뒤로 주저앉았어요. 오른손 손바닥이 살짝 쓸렸어요.

녹음-하준

하준이는 받침 블록 두 개 위에 긴 판을 놓고 자동차를 굴렸어요. 판이 기울어 떨어지자 다리 밑을 살펴보고 가운데에 받침을 하나 더 놓았어요. 자동차가 끝까지 건너가자 “이번에는 안 떨어졌어요”라고 말했어요. 이후 바깥놀이터에서 친구가 잡고 있던 빨간 삽 손잡이를 자기 쪽으로 당겼어요. 선생님이 차례를 말로 부탁해 보자고 안내하자 친구에게 “미안해”라고 말했어요.



### 5. 확인 질문에 답하기

예시를 그대로 따라간다면 녹음에는 하준과 서아가 다툰 장면이 들어 있습니다. 상황을 이해하는 데 필요한 정보가 부족하면 **작성 전에 확인할 내용**이 표시됩니다.

- 누가 어떤 행동을 했는지, 누가 다쳤는지, 교사가 어떻게 도왔는지 묻고 사용자의 답변을 요구합니다. 확인할 수 없는 내용은 **건너뛰기**를 선택합니다.
- 사건을 보호자에게 어떻게 전달할지 묻고 **부드럽게** 선택지가 나오면, 해당 선택지를 눌러 봅니다.
- 녹음 속 관찰 대상을 고르는 질문이면 아이를 선택하고 **확인하고 계속**을 누릅니다. 상황에 대한 질문에 답한 뒤에는 **답변하고 초안 만들기**를 누릅니다.

입력 내용에 따라 질문의 순서나 개수가 달라질 수 있습니다. 바로 초안이 나왔다면 다음 단계로 진행합니다.

### 6. 알림장 검토, 수정, 확정

**아이별 알림장**에서 세 아이의 글을 차례로 읽습니다. 발표에 사용했던 예시로 진행하셨다면 아래와 같이 나옵니다.

- 도윤은 **낙엽 분류**, 서아는 **빵집 역할놀이**, 하준은 **자동차 다리 만들기**가 각각 자기 글에 들어갔는지 확인합니다. 메모에 쓰지 않고 녹음에서만 말한 행동도 찾아봅니다.
- 서아와 하준의 다툼은 누가 무엇을 했는지, 교사가 어떻게 도왔는지가 상황 확인표와 맞는지 봅니다. 보호자에게 전달하는 글에서 상대 아이의 이름이 드러나거나, 확인하지 않은 행동이나 조치가 추가됐다면 수정합니다.
- 말투 예시의 표현이 글에 반영됐는지 확인합니다. 빗방울이나 지우처럼 말투 예시에만 등장한 내용은 오늘 활동에 들어가면 안 됩니다.

한 아이의 글에서 **직접 수정**을 눌러 문장 하나를 다듬고 **수정 저장**을 누릅니다. 검토한 글은 아이별로 **확정**을 눌러 `완료` 상태로 바꿉니다. \*\*관찰일지도 새롭게 업데이트할까요?\*\*가 나오면 이번 체험에서는 **업데이트**를 누릅니다. 완료된 알림장의 **복사**를 눌러 메모장에 붙여 넣어 봅니다.

### 7. 관찰일지 확인 및 Word 다운로드

1. **일지 작성 → 관찰일지**에서 **시작 날짜**와 **종료 날짜**를 알림장 날짜로 맞춥니다.
2. 아이별 관찰일지를 확인합니다. 알림장은 보호자에게 하루를 전하는 말투로, 관찰일지는 `~함`, `~음` 같은 사무적인 말투로 작성됐는지 비교합니다. 관찰영역은 별도 항목에서 확인하고, 본문에서는 그 영역에 해당하는 행동과 배움이 드러나는지 봅니다. 예를 들어 도윤이의 일지에서 **색을 기준으로 낙엽을 나누고, 두 색이 있는 잎을 어디에 둘지 설명한 모습**을 확인합니다.
3. 화면 상단의 **설정 → 관찰일지 기록 양식 → Word 양식 업로드**에서 워드 양식 파일을 올립니다. 업로드한 파일 이름이 보이면 설정을 닫습니다.
4. 다시 **일지 작성 → 관찰일지**로 가서 원하는 아이의 **출력하기** 또는 **재출력하기**를 누릅니다. 미리보기 아래 **Word로 출력하기**를 눌러 파일을 내려받습니다. 버튼이 비활성이라면 설정에서 Word 양식이 올라갔는지 확인합니다.
5. 내려받은 `.docx`를 열어 **양식의 배치가 유지됐는지**, **이름·날짜·관찰내용이 해당 칸에 들어갔는지** 확인하면 체험이 끝납니다.



**10번 팀 쓰담쓰담**

`main` 구현은 알림장 작성, 연결 관찰일지 조회·편집과 Word 출력을 지원합니다. 녹음 전사는 서버에 설정한 외부 STT API를 사용합니다.

## 프로젝트 소개

어린이집 교사는 하루 동안 여러 아동을 관찰하고 활동 내용, 특이사항, 식사·수면, 또래관계와 행동 등을 기록한다. 알림장은 그날의 일상을 보호자와 공유하고, 관찰일지는 대상 기간의 아동 관찰을 남긴다. 여러 아동의 일을 되찾아 구분하는 과정은 시간이 들며, 관찰일지는 작성 간격이 길어 그간의 일을 회상하기 더 어렵다.

PatPat은 어린이집 담임 교사가 남긴 관찰을 바탕으로 아동별 알림장과 연결 관찰일지 초안 작성을 돕는다. 교사는 생성 결과를 직접 검토하고 수정한 뒤 기록을 확정한다.

PatPat의 목표는 교사의 관찰과 판단을 대신하는 것이 아니라, 반복적인 문서화 작업을 줄여 교사가 아동 관찰과 상호작용에 더 집중할 수 있도록 돕는 것이다.

## 지원하는 두 기록

| 구분 | 알림장 | 관찰일지 |
|---|---|---|
| 주기 | 사용하는 기관에서 매일 전송하며, 작성하지 않는 기관도 있음 | 월 1~2회 이상 작성 |
| 내용 | 당일의 사소한 일·활동·특이사항과 안부인사 등 소통 문구 | 대상 기간에 실제로 확인한 아동의 말·행동·반응과 상황 |
| 현재 지원 방식 | 대상일의 반 공통·아동별 관찰로 초안 작성 | 연결 일지를 아동·날짜별로 조회·편집하고 Word로 출력 |

알림장을 쓰지 않는 기관을 위한 독립 관찰일지 작성은 후속 구현 범위다. 기관의 알림장 전송은 교사가 기존 수단으로 수행한다.

## 해결하려는 문제

- 여러 아동의 관찰 내용을 기억하고 정리해 개별 기록으로 옮기는 데 시간이 많이 든다.
- 동일한 활동이라도 아동별 참여 정도와 행동을 다르게 기록해야 한다.
- 기록 작성이 보육 업무 이후로 밀리면 업무시간 외 부담으로 이어질 수 있다.
- 반복적인 문서 작성 과정에서 관찰 정보가 누락되거나 비슷한 표현이 반복될 수 있다.

## 핵심 사용 흐름

교사는 날짜와 반을 선택해 공통·아동별 관찰을 입력하고, 필요한 추가 질문에 답한 뒤 알림장 초안을 검토·수정·확정한다. 녹음을 선택하면 서버가 외부 STT API로 전사한다. 관찰일지는 아동·기간을 선택해 등록한 Word 양식의 서식을 유지한 채 내용을 채운 `.docx` 파일로 출력할 수 있다.

## 계획된 MVP

### 포함할 기능

- 음성·텍스트 기반 관찰 내용 입력
- 음성 전사문·텍스트 메모의 관찰을 아동별로 분류·정리
- 관찰 메모 누적 저장과 대상일·기간의 근거 선택
- 알림장 및 관찰일지 초안 생성
- 동일한 활동에 참여한 아동들의 개별 기록 생성
- 교사의 생성 결과 검토·수정
- 최종 기록 저장 또는 복사
- 등록한 Word 양식으로 관찰일지 출력

### 범위 밖

- 사진·이미지 업로드·저장·분석, 이미지 기반 아동 식별·분류, 사진 연결·관리
- 교사의 관찰·판단을 대신하는 완전 자동 기록
- 교사 검토 없이 보호자에게 자동 발송
- 아동의 발달 진단이나 전문적 판단
- 기존 어린이집 플랫폼과의 연동
- 상담 기록, 발달 기록, 가정통신문 등 추가 문서 유형

현재 구현과 후속 요구의 차이는 [SPEC의 범위와 인터페이스](docs/SPEC.md)를 따른다.

## 목표 및 평가 방법

아래 수치는 사용자 조사와 프로토타입 평가를 거치며 조정할 수 있는 **잠정 목표**이며, 현재 달성된 결과가 아니다.

| 평가 지표 | 잠정 목표 |
|---|---:|
| AI 생성 기록의 핵심 정보 반영률 | 90% 이상 |
| 입력에 없는 사실을 생성하는 오류율 | 10% 이하 |
| 기존 수기 작성 대비 기록 작성 시간 | 30% 이상 단축 |
| 전반적인 사용 편의성 | 5점 만점 4점 이상 |
| 교사가 수정한 뒤 실제 활용 가능한 기록 비율 | 80% 이상 |

### 평가 방법

- 알림장은 당일, 관찰일지는 여러 날짜의 누적 관찰을 사용해 기존 방식과 PatPat의 작성 시간을 기록 유형별로 비교한다. 확인된 관찰의 입력·작성·검토 시간을 비교하며, 사진 정리·분류 시간은 제품의 개선 효과 평가에서 제외한다.
- 어린이집 교사가 생성 결과의 정확성, 자연스러움, 아동별 개별성, 수정 편의성, 만족도를 평가한다.
- 사전 인터뷰에서 확인한 요구사항이 서비스에 반영되었는지 점검한다.
- GPT 계열 모델과 Claude 계열 모델을 동일한 입력으로 비교하고, 정보 반영 정도·자연스러움·개인화 수준·오류를 기준으로 검토한다.

## 연구 및 개발 로드맵

1. **발견(Discover)** — 최근 알림장·관찰일지를 작성한 교사를 대상으로 해결책을 먼저 제시하지 않는 과거 행동 중심 인터뷰를 10건 이상 진행하고, 실제 작성 흐름을 관찰한다.
2. **정의(Define)** — 인터뷰 로그와 관찰 기록을 근거로 핵심 문제, 미니 온톨로지, 제품 스펙과 수용 기준을 작성한다.
3. **구축(Develop)** — 음성·텍스트 입력, 정보 정리, 아동별 초안 생성, 교사 검토·수정의 최소 흐름을 프로토타입으로 구현한다.
4. **검증 및 전달(Verify & Deliver)** — 기능 테스트와 교사 대상 사용성 평가를 수행하고, 시간·품질·오류 지표를 측정해 프롬프트와 화면을 개선한다.

인터뷰 결과와 평가 결과에 따라 문제 정의, 기능 범위, 모델 선택은 변경될 수 있다.

## AI 활용 및 검증 원칙
- **제품 AI 역할:** 외부 STT API는 선택 녹음을 전사하고, 텍스트 AI는 전사문과 교사 입력으로 초안을 작성한다. 두 API의 설정은 서버에서 관리한다.
- **사람의 책임:** 인터뷰 원문, 문제의 우선순위, 범위 결정, 수용 기준은 팀이 직접 정하고 근거를 확인한다.
- **Human in the loop:** AI가 만든 기록은 교사가 반드시 확인·수정한 뒤 사용한다.
- **사실성:** 입력에 없는 아동의 행동·감정·사실을 AI가 임의로 추가하지 않도록 설계하고 평가한다.
- **개인정보 보호:** 원음은 STT 입력에만 사용한다. 텍스트 AI에는 작업에 따라 전사문·교사 입력·아동 정보가 전달될 수 있다. API 키는 서버에서 관리하고 저장소와 테스트에는 가상 예시만 사용한다. [현재 처리 범위](docs/SPEC.md)
- **개발 과정의 AI 사용:** 문서·코드·테스트 초안 작성에 AI를 활용할 수 있지만, 생성 범위와 사람의 검증 범위를 저장소에 기록하고 최종 결과는 팀이 설명할 수 있어야 한다.
