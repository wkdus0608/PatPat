# PatPat

> 교사의 관찰은 그대로, 반복적인 기록 작성은 AI가 돕는 보육 기록 지원 서비스

**10번 팀 쓰담쓰담**

알림장 작성과 연결 관찰일지 조회·편집 흐름을 구현했습니다. 실제 음성 전사를 위한 서버 연결은 개발 중입니다.

## 프로젝트 소개

어린이집 교사는 하루 동안 여러 아동을 관찰하고 활동 내용, 특이사항, 식사·수면, 또래관계와 행동 등을 기록한다. 알림장은 그날의 일상을 보호자와 공유하고, 관찰일지는 대상 기간의 아동 관찰을 남긴다. 여러 아동의 일을 되찾아 구분하는 과정은 시간이 들며, 관찰일지는 작성 간격이 길어 그간의 일을 회상하기 더 어렵다.

PatPat은 어린이집 담임 교사가 남긴 관찰을 바탕으로 아동별 알림장과 연결 관찰일지 초안 작성을 돕는다. 교사는 생성 결과를 직접 검토하고 수정한 뒤 기록을 확정한다.

PatPat의 목표는 교사의 관찰과 판단을 대신하는 것이 아니라, 반복적인 문서화 작업을 줄여 교사가 아동 관찰과 상호작용에 더 집중할 수 있도록 돕는 것이다.

## 지원하는 두 기록

| 구분 | 알림장 | 관찰일지 |
|---|---|---|
| 주기 | 사용하는 기관에서 매일 전송하며, 작성하지 않는 기관도 있음 | 월 1~2회 이상 작성 |
| 내용 | 당일의 사소한 일·활동·특이사항과 안부인사 등 소통 문구 | 대상 기간에 실제로 확인한 아동의 말·행동·반응과 상황 |
| 현재 지원 방식 | 대상일의 반 공통·아동별 관찰로 초안 작성 | 확정된 알림장에 연결된 일지를 아동·날짜별로 조회·편집 |

알림장을 쓰지 않는 기관을 위한 독립 관찰일지 작성은 후속 구현 범위다. 기관의 알림장 전송은 교사가 기존 수단으로 수행한다.

## 해결하려는 문제

- 여러 아동의 관찰 내용을 기억하고 정리해 개별 기록으로 옮기는 데 시간이 많이 든다.
- 동일한 활동이라도 아동별 참여 정도와 행동을 다르게 기록해야 한다.
- 기록 작성이 보육 업무 이후로 밀리면 업무시간 외 부담으로 이어질 수 있다.
- 반복적인 문서 작성 과정에서 관찰 정보가 누락되거나 비슷한 표현이 반복될 수 있다.

## 핵심 사용 흐름

교사는 날짜와 반을 선택해 공통·아동별 관찰을 입력하고, 필요한 추가 질문에 답한 뒤 알림장 초안을 검토·수정·확정한다. 연결 관찰일지는 아동·날짜별로 조회하고 편집할 수 있다. 녹음은 기기에 저장한 뒤 서버에 업로드하며, 녹음에서 초안을 만드는 경로에는 전사 결과가 필요하다.

## 계획된 MVP

### 포함할 기능

- 음성·텍스트 기반 관찰 내용 입력
- 음성 전사문·텍스트 메모의 관찰을 아동별로 분류·정리
- 관찰 메모 누적 저장과 대상일·기간의 근거 선택
- 알림장 및 관찰일지 초안 생성
- 동일한 활동에 참여한 아동들의 개별 기록 생성
- 교사의 생성 결과 검토·수정
- 최종 기록 저장 또는 복사

### 범위 밖

- 사진·이미지 업로드·저장·분석, 이미지 기반 아동 식별·분류, 사진 연결·관리
- 교사의 관찰·판단을 대신하는 완전 자동 기록
- 교사 검토 없이 보호자에게 자동 발송
- 아동의 발달 진단이나 전문적 판단
- 기존 어린이집 플랫폼과의 연동
- 상담 기록, 발달 기록, 가정통신문 등 추가 문서 유형

현재 구현과 후속 요구의 차이는 [SPEC의 범위와 인터페이스](docs/SPEC.md)를 따른다.

## 목표 및 평가 방법

아래 수치는 사용자 조사와 프로토타입 평가를 거치며 조정할 수 있는 **잠정 목표**이며, 현재 달성된 결과가 아니다.

| 평가 지표 | 잠정 목표 |
|---|---:|
| AI 생성 기록의 핵심 정보 반영률 | 90% 이상 |
| 입력에 없는 사실을 생성하는 오류율 | 10% 이하 |
| 기존 수기 작성 대비 기록 작성 시간 | 30% 이상 단축 |
| 전반적인 사용 편의성 | 5점 만점 4점 이상 |
| 교사가 수정한 뒤 실제 활용 가능한 기록 비율 | 80% 이상 |

### 평가 방법

- 알림장은 당일, 관찰일지는 여러 날짜의 누적 관찰을 사용해 기존 방식과 PatPat의 작성 시간을 기록 유형별로 비교한다. 확인된 관찰의 입력·작성·검토 시간을 비교하며, 사진 정리·분류 시간은 제품의 개선 효과 평가에서 제외한다.
- 어린이집 교사가 생성 결과의 정확성, 자연스러움, 아동별 개별성, 수정 편의성, 만족도를 평가한다.
- 사전 인터뷰에서 확인한 요구사항이 서비스에 반영되었는지 점검한다.
- GPT 계열 모델과 Claude 계열 모델을 동일한 입력으로 비교하고, 정보 반영 정도·자연스러움·개인화 수준·오류를 기준으로 검토한다.

## 연구 및 개발 로드맵

1. **발견(Discover)** — 최근 알림장·관찰일지를 작성한 교사를 대상으로 해결책을 먼저 제시하지 않는 과거 행동 중심 인터뷰를 10건 이상 진행하고, 실제 작성 흐름을 관찰한다.
2. **정의(Define)** — 인터뷰 로그와 관찰 기록을 근거로 핵심 문제, 미니 온톨로지, 제품 스펙과 수용 기준을 작성한다.
3. **구축(Develop)** — 음성·텍스트 입력, 정보 정리, 아동별 초안 생성, 교사 검토·수정의 최소 흐름을 프로토타입으로 구현한다.
4. **검증 및 전달(Verify & Deliver)** — 기능 테스트와 교사 대상 사용성 평가를 수행하고, 시간·품질·오류 지표를 측정해 프롬프트와 화면을 개선한다.

인터뷰 결과와 평가 결과에 따라 문제 정의, 기능 범위, 모델 선택은 변경될 수 있다.

## AI 활용 및 검증 원칙
- **제품 AI 역할:** 서버가 전사 결과와 교사 입력을 바탕으로 초안 생성을 요청한다. 실제 외부 STT는 공급자 연결이 필요하고 외부 텍스트 AI는 서버 설정이 필요하다.
- **사람의 책임:** 인터뷰 원문, 문제의 우선순위, 범위 결정, 수용 기준은 팀이 직접 정하고 근거를 확인한다.
- **Human in the loop:** AI가 만든 기록은 교사가 반드시 확인·수정한 뒤 사용한다.
- **사실성:** 입력에 없는 아동의 행동·감정·사실을 AI가 임의로 추가하지 않도록 설계하고 평가한다.
- **개인정보 보호:** 원음은 STT 입력에만 사용한다. 텍스트 AI에는 작업에 따라 전사문·교사 입력·아동 정보가 전달될 수 있다. API 키는 서버에서 관리하고 저장소와 테스트에는 가상 예시만 사용한다. [현재 처리 범위](docs/SPEC.md)
- **개발 과정의 AI 사용:** 문서·코드·테스트 초안 작성에 AI를 활용할 수 있지만, 생성 범위와 사람의 검증 범위를 저장소에 기록하고 최종 결과는 팀이 설명할 수 있어야 한다.

## 로컬 테스트 — 터미널 2개로 실행

휴대전화와 컴퓨터 같은 Wi-Fi에 연결.

### 터미널 1 — 서버

```bash
cd BE
source .venv/bin/activate
python -m app.manage create-teacher --login-id teacher-demo --display-name "가상 교사"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 터미널 2 — Expo Go

```bash
cd FE
PATPAT_HOST_IP="$(ipconfig getifaddr en0)"
EXPO_PUBLIC_API_BASE_URL="http://${PATPAT_HOST_IP}:8000" pnpm exec expo start --clear --port 8081
```

IP를 가져오지 못하면 Wi-Fi 설정에서 IP 주소를 확인해 `PATPAT_HOST_IP`에 직접 넣는다. PC 브라우저에서 테스트할 때는 마지막 명령 대신 아래를 실행한다.

```bash
EXPO_PUBLIC_API_BASE_URL=http://127.0.0.1:8000 pnpm exec expo start --web --clear --port 8081
```

녹음 서버 저장·재생에는 서버 PC에서 `ffprobe`·`ffmpeg` 명령을 실행할 수 있어야 한다. 새 녹음은 저장 직후 연결되어 있으면 바로 서버에 저장된다. 연결 실패 시 기기 원음을 보존하고 앱이 자동으로 재시도하며(10초부터 최대 5분 간격, 앱 복귀 시 즉시), **보관함 → 녹음 파일 → 새로고침**으로 바로 확인·재시도할 수도 있다.

## 로컬 테스트 — Windows PowerShell

Python 3.11 이상과 Node.js·pnpm이 설치된 환경에서 PowerShell 터미널 2개를 연다. 각 터미널은 프로젝트 루트에서 시작한다. 휴대전화로 확인할 때는 컴퓨터와 같은 Wi-Fi에 연결한다.

### 터미널 1 — 서버

처음 한 번은 아래 명령을 순서대로 실행해 가상환경·필요 패키지·테스트 계정을 준비한다. 이미 `BE/`에 있다면 `cd BE`는 생략한다.

```powershell
cd BE
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m app.manage create-teacher --login-id teacher-demo --display-name "가상 교사"
```

계정 생성 시 비밀번호를 두 번 입력한다. 입력 중 글자가 보이지 않는 것은 정상이다. 이미 `teacher-demo` 계정을 만들었다면 계정 생성 명령은 생략한다.

준비가 끝나면 같은 `BE/` 폴더에서 서버를 실행하고 터미널을 열어 둔다. 다음 실행부터는 이 서버 명령만 실행하면 된다. 가상환경의 Python을 직접 사용하므로 `source`나 별도의 활성화 명령은 필요 없다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 터미널 2 — Expo Go

프로젝트 루트에서 아래 명령을 실행한다. 패키지 설치는 처음 실행하거나 의존성이 변경됐을 때 필요하다.

```powershell
cd FE
pnpm.cmd install --store-dir .pnpm-store
ipconfig
```

`ipconfig` 출력에서 Wi-Fi의 IPv4 주소를 확인한다. 아래 `192.168.0.10`을 실제 컴퓨터 주소로 바꾼 뒤 실행하고, 표시되는 QR 코드를 휴대전화의 Expo Go로 연다.

```powershell
$env:EXPO_PUBLIC_API_BASE_URL = "http://192.168.0.10:8000"
pnpm.cmd exec expo start --clear --port 8081
```

PC 브라우저로 테스트할 때는 위 두 줄 대신 같은 `FE/` 폴더에서 아래를 실행한다.

```powershell
$env:EXPO_PUBLIC_API_BASE_URL = "http://127.0.0.1:8000"
pnpm.cmd exec expo start --web --clear --port 8081
```

로그인 ID는 `teacher-demo`, 비밀번호는 계정 생성 때 입력한 값이다.
