# FE-05 측면 버튼으로 녹음 시작 · iPhone/Galaxy 실기기 테스트

브랜치: `verify/background-recording-ios-android` (FE-04의 백그라운드 녹음 위에 구현)

## 먼저 알아둘 것

iOS와 Android 모두 앱이 전원·측면 버튼 입력을 직접 읽을 수 없다. 그래서 **운영체제가 제공하는 측면 버튼 설정**에 PatPat을 연결한다.

| | 측면 버튼 동작 | PatPat이 하는 일 |
| --- | --- | --- |
| iPhone | 측면 버튼 길게 누르기 → Siri → "PatPat 녹음 시작" | App Intent가 앱을 열고 요청을 남기면 앱이 녹음을 시작 |
| Galaxy | 설정 → 유용한 기능 → 측면 버튼 → **두 번 누르기** → 앱 → PatPat | 앱 바로가기(`patpat://record/start`)로 열리면 앱이 녹음을 시작 |

**화면이 꺼진(잠긴) 상태에서 곧바로 녹음이 시작되지는 않는다.** 두 플랫폼 모두 일반 앱을 앞으로 가져오려면 잠금 해제가 필요하다.

- iPhone: Apple 기술지원 답변은 `openAppWhenRun`이면 앱이 전면으로 오기 때문에 기기 잠금 해제가 필요하다는 것이다. Siri가 Face ID/암호를 요구한다.
- Galaxy: 두 번 누르기에서 카메라는 잠금 상태에서도 열리지만 "앱 열기"는 잠금 해제가 필요하다는 안내가 있다(2차 자료, 이 테스트에서 확인).
- 일단 녹음이 시작된 뒤에는 FE-04의 백그라운드 녹음으로 화면을 꺼도 녹음이 이어진다.

따라서 기대 흐름은 "측면 버튼 → (잠금 해제) → PatPat이 열리며 녹음 시작 → 화면을 꺼도 계속"이다.

## 동작 방식

- `plugins/withSideButtonTrigger.js`(Expo 설정 플러그인)이 네이티브 프로젝트를 만든다. 이 PC에서 `expo prebuild`로 생성 결과를 확인했다.
  - iOS: `StartRecordingIntent.swift`를 앱 대상에 포함(Sources 빌드 단계 확인), 앱 이름 대체어(쓰담쓰담·팻팻·패트팻) 추가, URL 스킴 `patpat`.
  - Android: `patpat_shortcuts.xml` 정적 바로가기와 메인 액티비티 `android.app.shortcuts` 메타데이터, URL 스킴 `patpat`.
- iPhone intent는 앱의 Documents 폴더에 시각이 적힌 `patpat-start-request.txt`를 쓴다. 앱이 켜지거나 앞으로 올 때 읽고 지운 뒤 녹음을 시작한다. 링크 대신 파일을 쓰는 이유는 앱이 처음부터 켜질 때 요청을 잃지 않기 위해서다.
- Galaxy 바로가기는 `patpat://record/start` 링크로 앱을 연다. 앱이 켜져 있으면 새 링크 이벤트로, 꺼져 있으면 시작 링크로 읽는다.
- 요청은 45초 안에 처리되지 않으면 버린다. 로그인 전에 도착한 요청은 로그인이 끝나면 처리한다. 이미 녹음 중이거나 저장하지 못한 녹음이 있으면 새로 시작하지 않는다.
- 요청이 오면 어느 탭에 있든 녹음 화면으로 이동한다.

## 사전 준비 (한 번)

네이티브 코드가 바뀌었으므로 **개발 빌드를 새로 만들어 설치해야 한다.** FE-04의 이전 빌드로는 이 기능이 동작하지 않는다.

```sh
cd FE
pnpm build:dev
```

- iPhone 기기용 빌드는 유료 Apple Developer Program 계정과 기기 등록이 필요하다(FE-04 참고).
- 서버(`BE/`)를 켜고 `.env`의 `EXPO_PUBLIC_API_BASE_URL`을 같은 네트워크 주소로 지정한 뒤 `pnpm start:dev`를 실행한다.
- 두 기기에 모두 설치하고 **앱을 한 번 열어 로그인하고 마이크 권한을 허용**해 둔다. 첫 요청에서 권한 창이 뜨면 녹음 시작이 늦어진다.
- 기종·OS 버전을 아래 표에 적는다. Galaxy는 One UI 버전도 적는다.

## iPhone 설정과 테스트

설정 (iOS 버전에 따라 이름이 조금 다르다):

1. 설정 → Siri(또는 Apple 인텔리전스 및 Siri)에서 **"측면 버튼을 눌러 Siri 사용"** 을 켠다.
2. 같은 화면의 **"잠금 상태에서 Siri 허용"** 을 켠다.
3. 설정 → 앱 → PatPat → Siri에서 앱 사용 허용 항목이 있으면 켠다.
4. 단축어 앱을 열어 **PatPat → "녹음 시작"** 이 보이는지 확인한다.

## Galaxy 설정과 테스트

설정 (One UI 버전에 따라 이름이 조금 다르다):

1. 설정 → 유용한 기능(Advanced features) → **측면 버튼** → **두 번 누르기** 를 켠다.
2. 옵션에서 **앱** 을 고르고 톱니바퀴를 눌러 **PatPat** 을 선택한다. 앱 안의 기능을 고를 수 있는 버전이면 **"녹음 시작"** 을 고른다.
3. 먼저 홈 화면에서 PatPat 아이콘을 길게 눌러 **"녹음 시작"** 바로가기가 보이는지 확인한다. 이것이 보이면 바로가기 등록은 성공이다.

| # | 시나리오 | 기대 | 결과 |
| --- | --- | --- | --- |
| G-1 | 아이콘 길게 누르기 → "녹음 시작" | 앱이 열리고 녹음이 시작된다 (설정 확인용) | [ ] |
| G-2 | 앱을 켠 채 측면 버튼 두 번 | 녹음 화면으로 이동해 녹음이 시작된다 | [ ] |
| G-3 | 앱 종료 후 측면 버튼 두 번 | 앱이 처음부터 켜져도 녹음이 시작된다 | [ ] |
| G-4 | 화면 잠금 상태에서 측면 버튼 두 번 | 잠금 해제 후 앱이 열리고 녹음이 시작된다. **해제 전에 열리는지, 해제 후 시작하는지 기록** | [ ] |
| G-5 | G-4로 시작한 뒤 화면 끄기 1분 | 알림("녹음 중")과 함께 녹음이 이어지고 저장 길이가 맞는다 | [ ] |
| G-6 | 앱 선택 목록에 "녹음 시작" 기능이 있는가 | 있으면 그것으로, 없으면 앱만 열린다. **없으면 G-3·G-2가 "앱만 열림"으로 나올 수 있다** | [ ] |
| G-7 | 이미 녹음 중 측면 버튼 두 번 | 새 녹음을 만들지 않고 계속 녹음한다 | [ ] |

G-6에서 앱만 열리고 녹음이 시작되지 않는 기종은 구현 한계다. One UI가 앱 바로가기를 목록에 보여주지 않으면 이 방식으로는 측면 버튼에서 "녹음 시작"을 직접 고를 수 없다. 이 경우 결과를 기록해 두면 대안(앱을 열면 자동 시작 설정)을 정한다.

## 문제 해결

- **iPhone에서 Siri가 앱을 모른다고 답함:** 개발 빌드를 새로 설치했는지, 단축어 앱에 "녹음 시작"이 보이는지 확인한다. 보이지 않으면 설정 → 앱 → PatPat → Siri에서 허용하고 앱을 한 번 연 뒤 다시 시도한다.
- **iPhone에서 잠금 해제 후 앱만 열림:** 시나리오 I-4에 기록한다. 잠금 해제 흐름에서 요청이 끊기는 사례가 포럼에 보고되어 있다(비공식).
- **Galaxy에서 앱 목록에 PatPat이 안 보임:** 개발 빌드를 설치한 상태인지 확인한다. Expo Go는 바로가기를 등록할 수 없다.
- **둘 다 Expo Go에서는 동작하지 않는다.** 이 기능은 개발 빌드 전용이다.

## 이 기능이 확인되지 않은 것

- 이 PC에서는 전체 Xcode와 Android SDK가 없어 앱을 빌드하지 못했다. 확인한 것은 `expo prebuild` 생성 결과, Swift 파일의 macOS SDK 타입 검사, JS 자동 검사다. 실제 빌드 성공과 동작은 위 실기기 테스트로 확인한다.
- Siri가 한국어 문구를 실제로 알아듣는지, One UI가 앱 바로가기를 선택 목록에 보여주는지는 기종마다 다를 수 있다.
