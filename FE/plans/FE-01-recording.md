# FE-01 기능 구현 계획서

## 화면·탭 기본 구성과 녹음 시작·중지·날짜별 저장

- 상태: 구현 반영 — 실제 기기·시각 검증 대기
- 작성일: 2026-10-28
- 수정일: 2026-11-01
- 구현 예정 위치: `PatPat/FE`
- 문서 범위: 첫 번째 FE 기능의 구현 계획. 구현·테스트 결과가 아니다.

## 1. 목표

발표자료의 디자인을 참고해 프론트엔드 화면과 하단 탭의 기본 구성을 만들고, 녹음 탭에서 시작·중지·저장을 사용할 수 있게 한다. 교사가 그때그때 남긴 여러 녹음은 기기의 날짜별 폴더에 날짜·시간 파일명으로 각각 보관한다.

이번 기능의 완료 지점은 **디자인을 적용한 화면과 탭을 이동할 수 있고, 녹음한 여러 파일이 날짜별로 저장되며, 앱을 다시 실행해도 기존 파일을 유지하면서 새 녹음을 추가할 수 있는 상태**다.

담당 범위는 FE다. 별도 식별자 발급, 관리 DB·SQLite, 관찰 데이터 모델, 백엔드 API·전사·생성은 이번에 구현하지 않는다. 날짜 폴더 생성과 파일 저장은 요청한 녹음 동작에 필요한 기기 내 처리로 한정한다.

하루 녹음 개수에 임의의 제한을 두지 않는다. 기기 저장 공간 부족 등 실제 저장 실패는 사용자에게 안내한다.

## 2. 구현 범위

| 포함 | 다음 기능에서 구현 |
| --- | --- |
| React Native + Expo 프로젝트 기본 설정 | 저장된 녹음의 날짜별 목록·재생 |
| 발표자료를 참고한 색상·카드·버튼 디자인 | 마이크 권한 요청과 거부 안내 |
| 하단 탭과 준비 중 화면의 기본 구성 | 녹음 선택·삭제 |
| 녹음 시작·중지 및 반복 녹음 | 작성에 사용할 여러 녹음 선택 |
| 녹음 경과 시간 표시 | 음성 전사·아동별 분류 |
| 날짜 폴더와 날짜·시간 파일명으로 기기 내 저장 | 관찰일지 생성·수정·확정·공유 |
| 저장 성공·실패 안내 | 보관함의 이전 녹음·관찰일지 조회 |
| 오늘 저장한 녹음 개수와 최근 저장 정보 표시 | |

별도 식별자·관리 DB·API 계약은 추후 BE 담당자와 협의할 영역으로 남긴다. 이번 FE 작업에서 선행 설계하거나 구현하지 않는다.

### 권한 처리의 단계 구분

사용자 요청에 따라 마이크 권한 요청·재요청·거부 안내·설정 이동 흐름은 이번 구현 범위에서 제외한다. 실제 녹음 검증은 운영체제에서 마이크 사용이 이미 허용된 테스트 기기를 전제로 한다.

운영체제의 마이크 사용 허용은 실제 녹음에 필요한 조건이다. 이번에는 허용되지 않은 기기의 녹음까지 동작한다고 보장하지 않으며, 녹음 시작에 실패하면 녹음 중 또는 저장 성공으로 표시하지 않는다. 권한 기능은 별도 기능 계획에서 다룬다. 근거: [Expo Audio 권한 문서](https://docs.expo.dev/versions/latest/sdk/audio/).

## 3. 화면과 사용 흐름

### 하단 탭 기본안

| 탭 | 이번에 구성할 화면 | 후속 기능 |
| --- | --- | --- |
| 녹음 | 기본 진입 화면. 녹음 버튼·시간·저장 결과·오늘 개수 | 녹음 목록·선택으로 연결 |
| 관찰일지 작성 | 같은 디자인의 ‘준비 중’ 화면 | 선택한 근거로 초안 작성·직접 수정·수정 재요청·교사 확정 |
| 보관함 | 같은 디자인의 ‘준비 중’ 화면 | 이전 녹음과 관찰일지 확인 |

탭 이름과 구성은 검토 가능한 기본안이다. 이번에는 탭 이동과 공통 디자인을 만들고, 아직 없는 작성·조회 기능의 결과를 표시하지 않는다.

녹음 중 탭을 이동하면 녹음이 숨은 채 계속되지 않도록 이동을 제한하고 현재 녹음을 마치도록 안내한다. 저장 중에도 중복 동작을 막는다.

### 녹음 화면

- 화면 제목: ‘관찰 녹음’
- 안내 문구: ‘기억해 둘 관찰 내용을 녹음해 주세요.’
- 녹음 시간: `00:00`
- 주요 버튼: ‘녹음 시작’
- 오늘 저장한 녹음 개수
- 최근 저장한 녹음의 파일명·시각 및 저장 결과
- 방금 저장한 녹음의 길이. 앱 재실행 후 길이 복원을 위한 별도 DB는 만들지 않음

### 사용 순서

1. 교사가 ‘녹음 시작’을 누른다.
2. 녹음을 시작하고 화면에 ‘녹음 중’과 경과 시간을 표시한다.
3. 버튼이 ‘중지하고 저장’으로 바뀐다.
4. 버튼을 누르면 녹음을 중지한다.
5. 녹음 시작일의 날짜 폴더가 없으면 생성하고 날짜·시간 파일명으로 저장한다.
6. 실제 파일 저장이 끝나면 ‘녹음이 저장되었어요’를 표시하고 오늘 개수와 최근 저장 정보를 갱신한다.
7. 다음 녹음을 시작할 수 있다. 이전 녹음은 그대로 유지한다.

별도의 저장 버튼 없이 ‘중지하고 저장’ 한 번으로 녹음을 마치는 것을 기본안으로 한다.

### 하루 여러 번 녹음하는 예

| 시작 시각 | 저장 결과 |
| --- | --- |
| 09:10 | 첫 번째 녹음을 독립 파일로 저장 |
| 11:30 | 두 번째 녹음을 추가 저장하고 첫 번째 녹음 유지 |
| 15:20 | 세 번째 녹음을 추가 저장하고 앞선 두 녹음 유지 |

이 경우 오늘 저장한 녹음은 총 3개다. 다음 기능에서 날짜별로 확인하고, 개별 삭제하거나 여러 개를 골라 작성에 사용할 수 있도록 저장 구조를 준비한다.

## 4. 디자인 방향

참고 자료는 [쓰담쓰담 중간발표 자료](../../docs/presentation/쓰담쓰담%20중간발표ppt.pdf)다. 실제 확인한 2쪽의 서비스 소개와 11쪽의 SPEC 화면에서 배경·색상·카드 형태를 참고한다.

발표자료에는 모바일 앱의 탭·녹음 화면 시안이 없으므로, 아래 화면 구성은 발표자료의 시각적 분위기를 모바일에 적용하기 위한 FE 제안이다.

| 요소 | 적용 방향 |
| --- | --- |
| 배경 | 발표자료의 따뜻한 크림색 계열. 기준색 `#FFFDF7` |
| 제목 | 진한 갈색 `#49372C`, 굵고 친근한 인상 |
| 콘텐츠 | 흰색 바탕의 둥근 카드와 여유 있는 간격 |
| 강조 | 연한 노랑 `#FEF4D2`·`#FDE79B`, 주요 녹음 버튼과 선택된 탭에 활용 |
| 보조색 | 연분홍 `#FFE6E6`, 연초록 `#E8F8E8`, 연하늘 `#E6F2FF` |
| 버튼·탭 | 둥근 모서리, 아이콘과 글자 함께 표시, 활성 상태를 명확히 구분 |
| 장식 | 발표자료의 꽃·어린이집 분위기를 작은 포인트로 활용하되 녹음 조작과 읽기를 방해하지 않게 배치 |

색상은 PDF 렌더링에서 확인한 기준색이며 구현 시 모바일 화면에서 가독성을 확인한다. 발표자료의 정확한 폰트명·원본 로고 파일은 확정하지 않는다. 사용할 수 있는 자산을 확인한 뒤 적용하며, 지금 새 이미지나 로고를 만들지는 않는다.

## 5. 상태와 예외 처리

| 상황 | 처리 |
| --- | --- |
| 시작·중지 버튼 연속 누름 | 처리 중에는 중복 실행을 막아 녹음·저장이 겹치지 않도록 함 |
| 녹음 시작 실패 | 녹음 중으로 전환하지 않고 시작 실패 안내. 권한 전용 안내 흐름은 후속 구현 |
| 녹음 중 | 녹음 상태를 글자와 색상으로 함께 표시 |
| 녹음 중 탭 이동 시도 | 현재 화면 유지, 녹음을 마치도록 안내 |
| 저장 중 | ‘저장 중…’ 표시, 새 녹음 시작 제한 |
| 저장 성공 | 개수와 최근 저장 정보를 갱신하고 다음 녹음 시작 허용 |
| 저장 실패·저장 공간 부족 | 성공이나 정상 저장 개수 증가로 표시하지 않고 실패 이유와 재시도 안내 |
| 유효한 파일이 생성되지 않음 | 정상 녹음으로 등록하지 않고 다시 녹음하도록 안내 |
| 앱 전환·화면 잠금·전화 등으로 중단 | 계속 녹음하는 기능은 제외하고, 중단을 감지해 종료·저장을 시도한 뒤 결과 안내 |
| 같은 파일명 존재 | 기존 파일을 덮어쓰지 않고 저장 실패 안내 |
| 앱 재실행 | 날짜 폴더의 실제 파일로 오늘 개수·최근 파일명과 시각을 다시 표시 |

저장 실패 시 남아 있는 파일은 재시도에 활용한다. 재시도로 같은 녹음 파일이 중복 생성되지 않도록 한다. 새 녹음의 저장 실패나 재시도가 기존에 정상 저장된 녹음에 영향을 주어서는 안 된다.

앱 강제 종료나 운영체제의 갑작스러운 종료까지 녹음 보존을 보장하지는 않는다.

## 6. 기술과 파일 저장 방식

| 항목 | 제안 |
| --- | --- |
| 앱 | React Native + Expo |
| 언어 | TypeScript |
| 녹음 | `expo-audio` |
| 음성 파일 보관 | `expo-file-system` |

구현 시 선택한 Expo SDK와 호환되는 버전으로 설치한다. 기기 내 파일·폴더 처리는 Expo 공식 문서를 기준으로 한다. 참고: [Audio](https://docs.expo.dev/versions/latest/sdk/audio/), [FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/).

SQLite·별도 관리 테이블·별도 로컬 식별자는 도입하지 않는다. 화면 상태에 필요한 녹음 여부·경과 시간·현재 파일 위치만 사용한다.

### 폴더와 파일명

앱 전용 보관 경로 아래에 `recordings/YYYY-MM-DD/` 폴더를 만든다. 파일명은 녹음 시작 시각 기준 `YYYY-MM-DD_HH-mm.m4a`로 한다. 시작 시간은 24시간제의 시·분까지만 사용하고 초·밀리초와 별도 식별자는 파일명에 추가하지 않는다.

```text
recordings/
  2026-11-01/
    2026-11-01_09-10.m4a
    2026-11-01_11-30.m4a
    2026-11-01_15-20.m4a
  2026-11-02/
    2026-11-02_09-05.m4a
```

`.m4a`는 Android·iOS의 녹음 출력 형식을 이에 맞추는 기본안이다. 실제 인코딩과 확장자가 일치하도록 구현 시 확인하며, 다른 형식의 파일을 확장자만 바꿔 저장하지 않는다.

### 저장 정책

- 임시 캐시에만 두지 않고 앱 전용 보관 경로에 최종 파일을 저장한다. 이 경로는 개발 PC의 `FE` 폴더나 외부 서버가 아니다.
- 날짜 폴더는 필요한 날 최초 저장 시 만들고, 이미 있으면 같은 폴더에 파일을 추가한다.
- 한 번의 녹음은 하나의 파일로 저장한다. 이전 녹음을 덮어쓰거나 여러 녹음을 자동으로 합치지 않는다.
- 날짜와 녹음 시작 시간의 시·분만 파일명에 포함한다. 같은 분에 시작한 녹음 등으로 같은 경로가 이미 존재하면 덮어쓰지 않고 실패로 알린다.
- 실제 파일 저장이 끝난 뒤에만 저장 성공과 개수 증가를 표시한다. 불완전한 임시 파일은 정상 개수에 포함하지 않는다.
- 오늘 개수와 최근 파일명·시각은 날짜 폴더의 실제 파일을 기준으로 표시한다. 별도 DB·색인 파일을 만들지 않는다.
- 앱 재실행 후 같은 날짜 폴더에 새 녹음을 추가한다. 새 저장의 실패가 기존 파일에 영향을 주지 않게 한다.
- 파일명에는 실명·아동 이름을 넣지 않으며, 음성 파일을 Git이나 외부 AI에 보내지 않는다.

### 날짜 구분 기준

폴더와 파일명은 **기기 현지 시간 기준의 녹음 시작 시각**으로 함께 정한다. 녹음 시작 때 정한 날짜·시각을 중지·저장할 때까지 유지한다. 화면의 ‘오늘’은 날짜가 바뀌거나 앱이 다시 활성화되면 갱신한다.

예를 들어 23:59에 시작해 다음 날 00:02에 저장한 녹음은 시작한 날짜에 속하며, 저장에 성공한 뒤 해당 날짜의 개수에 반영한다. 실제 관찰이 발생한 날짜는 녹음 시작일과 별개다.

### 도메인·API와의 구분

날짜 폴더·파일명은 FE의 기기 내 파일 정리 규칙이다. 새로운 관찰 사실·도메인 클래스·BE 식별자를 정의하지 않는다.

- 파일명이나 파일 경로를 `observation_id`로 사용하지 않는다.
- 녹음 시작 시각을 관찰 발생일이나 관찰일지 대상 기간으로 자동 확정하지 않는다.
- 파일 위치나 녹음 관리 정보를 기존 API 요청 필드에 임의로 추가하지 않는다.

## 7. 코드 구성과 작업 순서

실제 구현 요청을 받으면 `PatPat/FE`에 다음 역할을 나누어 구성한다.

| 구성 | 역할 |
| --- | --- |
| 공통 디자인 | 색상·카드·버튼·제목 스타일 |
| 하단 탭 | 녹음·관찰일지 작성·보관함 이동, 준비 중 화면 |
| 녹음 화면 | 버튼·시간·상태·오늘 개수·최근 저장 결과 안내 |
| 녹음 제어 | 시작·중지·중복 조작 방지·중단 처리 |
| 기기 파일 처리 | 날짜 폴더 생성, 날짜·시간 파일명 저장, 개수 확인 |
| 검증 | 탭 이동·화면 상태·반복 저장·저장 실패 확인 |
| 실행 안내 | 설치·실행 방법, 실제 점검 결과와 미검증 항목 |

커밋은 다음 단위로 나누는 것을 제안한다.

1. **기본 화면과 탭:** Expo·TypeScript 설정, 발표자료 기반 디자인, 세 탭의 기본 구성
2. **녹음 조작:** 시작·중지·경과 시간·중복 조작 방지
3. **날짜별 파일 저장:** 날짜 폴더·날짜시간 파일명, 반복 저장, 오늘 개수와 최근 저장 결과 안내
4. **검증과 마무리:** 화면·탭 이동·중단·저장 실패 확인 및 점검 기록

각 단계는 확인 가능한 상태로 묶고, 사용자가 단계별로 커밋하기 좋게 변경 내용을 정리한다. 커밋 실행은 별도 요청에 따른다.

구현에 사용한 환경과 실행 방법은 [FE README](../README.md), 실제 실행한 검사와 결과는 [검증 기록](../TEST_RESULTS.md)에 기록한다. 실제 기기 실행과 제품 전체 테스트 완료로 해석하지 않는다.

## 8. 검증과 완료 조건

### 화면·탭 확인

- 크림색 배경·갈색 제목·둥근 카드·파스텔 강조가 발표자료의 분위기와 이어지는지 실제 화면을 확인한다.
- 세 탭을 이동할 수 있고 선택된 탭과 준비 중 기능을 구분할 수 있다.
- 녹음 대기·녹음 중·저장 중·성공·실패 상태가 실제 동작과 일치한다.
- 녹음 중 탭 이동으로 녹음 상태가 숨겨지거나 파일이 유실되지 않는다.

### 자동 검증

- 버튼을 연속으로 눌러도 녹음과 저장이 중복 실행되지 않는다.
- 파일 저장이 실패하면 성공으로 표시하거나 정상 개수를 늘리지 않는다.
- 저장 재시도로 동일한 녹음 파일이 중복 생성되지 않는다.
- 날짜 폴더와 파일명이 정한 형식으로 생성된다. 파일명 충돌 시 기존 파일을 덮어쓰지 않는다.
- 같은 날 여러 녹음을 저장해도 이전 파일을 덮어쓰지 않는다.
- 새 녹음의 저장 실패·재시도가 기존 정상 녹음에 영향을 주지 않는다.
- 날짜별 개수는 정상 저장된 녹음만 포함하고, 자정을 넘긴 녹음도 정한 시작일 기준으로 구분한다.

### 실제 기기 확인

- 마이크 사용이 이미 허용된 테스트 기기에서 확인한다. 권한 요청·거부 흐름은 이번 검증 범위에서 제외한다.
- 시험 소리를 녹음하고, 파일이 실제로 재생 가능한지 확인한다. 앱 내 목록·재생 화면 구현과는 구분한다.
- 같은 날 10회 연속 녹음하고, 같은 날짜 폴더에 날짜·시간 이름의 파일 10개가 유지되는지 확인한다. 10회는 시험 횟수이며 하루 녹음 개수 제한이 아니다.
- 앱을 종료한 뒤 다시 실행해도 기존 파일이 남아 있고 오늘 개수·최근 파일명과 시각이 다시 표시되는지 확인한다.
- 재실행 후 새 녹음을 추가해도 앞선 녹음이 유지되는지 확인한다.
- 자정을 넘긴 녹음과 날짜 변경 후 화면의 개수 갱신을 확인한다.
- 앱 전환·화면 잠금·녹음 중단 시 화면 상태와 저장 결과가 일치하는지 확인한다.

우선 검증 기기는 Android로 제안한다. iOS는 사용할 기기가 준비되면 별도로 확인하며, 실행하지 못한 환경은 미검증으로 명시한다.

검증에는 합성 음성이나 시험 신호를 사용하고, 실제 아동의 이름·음성은 사용하지 않는다. 녹음 파일은 Git에 포함하지 않는다.

## 9. 프로젝트 규칙과의 관계

- 원본 음성은 기기에 보관하며, 이번 기능에는 서버 업로드나 외부 AI 호출을 넣지 않는다. 현재 SPEC 4절·AC6의 개인정보 원칙을 따른다.
- ‘녹음 저장 완료’는 관찰일지의 ‘완료’ 상태와 구분한다. 기록의 교사 검토·확정 규칙은 유지한다.
- 현재 골든 케이스는 관찰 분류·초안 생성 중심이다. 이번 녹음 기능의 검증 결과를 제품 전체 AC 통과로 보고하지 않는다.
- AGENTS와 SPEC 사이에 AC 번호 차이가 있으므로, 이후 작업에서도 번호와 함께 해당 규칙의 내용을 확인한다. 예를 들어 원본 음성 외부 전송 금지는 현재 SPEC의 AC6, AGENTS의 AC9 참조에 해당한다. 기존 판정 기준은 변경하지 않는다.

## 10. 검토 이력과 구현 시작 조건

- 최초 계획: 녹음 시작·중지·기기 내 저장을 첫 FE 기능으로 제안했다.
- 사용자 보완: 교사가 하루에도 여러 번 녹음하므로 여러 파일을 각각 관리해야 한다.
- 2026-11-01 범위 수정: 사용자의 FE 담당 범위를 반영해 권한 요청·거부 안내와 SQLite·별도 로컬 식별자·관리 DB 설계를 제외했다. 날짜 폴더와 날짜·시간 파일명으로 반복 녹음을 보관하도록 변경했다.
- 2026-11-01 화면 수정: 발표자료의 시각적 분위기를 참고해 공통 디자인과 세 탭의 기본 구성을 포함했다. 관찰일지 작성·보관함의 실제 기능은 후속 구현으로 유지한다.
- 2026-11-01 파일명 수정: 사용자 요청에 따라 초·밀리초를 제외하고 `날짜_시-분.m4a` 형식으로 변경했다. 같은 파일명은 덮어쓰지 않는 규칙을 유지한다.
- 2026-11-01 구현 요청: 사용자가 이 계획서를 기반으로 FE 녹음 기능 구현을 요청해 구현을 시작했다. 코드와 실행 방법은 [FE README](../README.md), 실행한 검사와 미검증 범위는 [검증 기록](../TEST_RESULTS.md)에 정리한다.
- 반복 녹음·기존 파일 보존·오늘 저장 개수·재실행 후 추가 녹음·다건 및 날짜 경계 검증은 유지한다. 권한 기능의 연기는 기존 SPEC·골든 케이스의 판정 기준 변경을 뜻하지 않는다.
- 이 문서 저장은 구현 승인을 의미하지 않는다. 사용자와 계획을 검토·수정한 뒤, 사용자가 검토 완료와 이 계획대로의 구현을 요청하면 실제 구현을 시작한다.

화면·탭·녹음 제어·기기 파일 저장 코드를 구현했다. 자동 검사 결과와 실제 기기·시각 검증 대기는 검증 기록에서 구분하며, 이 계획서를 제품 전체 검증 통과 기록으로 사용하지 않는다.
