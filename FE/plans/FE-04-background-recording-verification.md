# FE-04 백그라운드 녹음 · iOS/Android 동시 검증

브랜치: `verify/background-recording-ios-android` (기준: `MVP_record`)

화면이 꺼지거나 다른 앱을 쓰는 동안에도 이미 시작한 녹음이 이어지는지 iOS와 Android 실기기에서 같은 시나리오로 검증한다. 이 문서는 **녹음 중 이어가기**만 다룬다. 측면 버튼으로 **새로 시작**하는 기능은 [FE-05](FE-05-side-button-trigger.md)를 따른다.

## 브랜치에서 바뀐 것

| 항목 | 내용 |
| --- | --- |
| `expo-dev-client`, `expo-constants` | 개발 빌드(Expo Go 대체)와 실행 환경 판별 |
| `app.json` | `expo-audio`의 `enableBackgroundRecording: true`. iOS `UIBackgroundModes: audio`, Android 마이크 포그라운드 서비스·알림 추가(`expo prebuild`로 생성 결과 확인) |
| `eas.json` | `development`(iOS 기기·Android APK), `development-simulator`(iOS 시뮬레이터) |
| `src/recording/backgroundMode.ts` | Expo Go에서는 기능을 끄고 기존 동작(화면을 벗어나면 중지·저장)을 유지, 개발/배포 빌드에서는 켠다 |
| `src/recording/useRecording.ts` | 개발 빌드에서는 백그라운드·화면 꺼짐에도 녹음 유지, 오디오 모드에 `allowsBackgroundRecording` 적용 |

## 준비물과 제약

- 이 PC에는 전체 Xcode와 Android SDK가 없다(`xcodebuild`, `adb` 없음). 로컬 빌드(`expo run:*`)는 쓰지 않고 **EAS 클라우드 빌드**를 쓴다. EAS 로그인은 되어 있다.
- **iPhone 실기기 빌드는 유료 Apple Developer Program 계정과 기기 등록이 필요하다.** 계정이 없으면 iOS는 이 방식으로 검증할 수 없다. iOS 시뮬레이터 빌드는 계정 없이 가능하지만 시뮬레이터를 실행할 Xcode가 있는 Mac이 필요하며, 마이크·화면 잠금 동작은 실기기와 다르다.
- Android는 APK를 내려받아 설치하면 되며 별도 유료 계정이 필요 없다.
- 서버 PC와 휴대전화는 같은 네트워크여야 한다.

## 실행 순서

한 번만 한다.

```sh
cd FE
pnpm exec eas init
```

`eas init`은 Expo 계정에 프로젝트를 만들고 `app.json`에 `projectId`를 추가한다. 만들어지는 값을 확인한 뒤 커밋한다.

두 플랫폼을 동시에 빌드한다. EAS가 두 빌드를 병렬로 처리한다.

```sh
pnpm build:dev
```

빌드가 끝나면 iOS는 기기에, Android는 APK로 설치한다. 개발 서버는 두 기기가 함께 쓴다.

```sh
echo "EXPO_PUBLIC_API_BASE_URL=http://<개발 PC의 같은 네트워크 주소>:8000" > .env
pnpm start:dev
```

서버(`BE/`)도 실행해 둔다. 설치한 앱에서 개발 서버를 선택하면 두 기기가 같은 코드로 시험된다.

## 이 브랜치가 확인하지 않는 것

- 측면 버튼으로 녹음을 새로 시작하는 동작은 [FE-05](FE-05-side-button-trigger.md)에서 다룬다.
- 제조사별 배터리 최적화에 의한 종료.
- 장시간(수십 분) 녹음의 배터리·저장 공간.
