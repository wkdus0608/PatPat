# FE-05 계획 — 교사 글쓰기 예시·원 기록 양식

- 상태: 계획 작성 · 구현 전
- 작성일: 2026-11-05
- 범위·이유: 사용자 요청에 따라 설정에 교사가 작성한 글과 원의 기록 형식을 남기는 두 입력 화면을 추가한다. FE 화면·상태·저장/조회 연결 경계만 다룬다.

## 1. 화면과 흐름

설정의 교사 정보 카드에 **교사 이름 → ‘내 글쓰기 예시’ → ‘우리 원 기록 양식’ → ‘로그아웃’** 순서로 세로 배치한다. 기존 교사 표시 이름·카드 스타일·아동 명단 영역은 유지한다.

| 버튼·화면 제목 | 안내 | 입력 내용·보조 문구 |
| --- | --- | --- |
| **내 글쓰기 예시** | 선생님이 작성한 글을 남겨주세요. | 이전에 작성한 관찰일지나 알림장 내용을 붙여 넣어주세요. |
| **우리 원 기록 양식** | 우리 원에서는 어떻게 기록하나요? | 관찰일지나 알림장의 항목, 순서, 제목, 작성 규칙을 자유롭게 적어주세요. |

- 각 버튼은 설정 안의 별도 화면을 연다. [FE-04](FE-04-settings-child.md)의 아동 특성 화면과 같이 상단 ‘뒤로’·제목, 흰색 둥근 카드, 여러 줄 입력창, 아래 노란색 ‘저장하기’·상태 안내로 구성한다.
- 두 화면 모두 직접 입력·붙여넣기로 내용을 누적·수정한다. 입력창의 접근성 이름은 화면 제목, placeholder는 각각 ‘작성했던 글을 붙여 넣어주세요.’·‘우리 원의 기록 형식을 적어주세요.’로 한다.
- 상단·Android 뒤로가기는 교사 정보 카드가 있는 설정 화면으로 먼저 복귀한다. 긴 본문·버튼은 함께 스크롤하고 키보드·안전 영역에 가리지 않게 한다.

## 2. 처리 규칙·연결 범위

- **저장 흐름:** FE-04의 명시적 저장·조회·실패/미연결 안내·수동 재시도·미저장 이탈 확인을 공통 적용한다. 성공 안내만 ‘글쓰기 예시를 저장했어요.’·‘기록 양식을 저장했어요.’로 구분한다. 공백·줄바꿈·빈 문자열로 지우기를 허용하며 자동 저장하지 않는다.
- **입력 분리·보존:** 현재 로그인 교사와 두 입력 종류별로 저장본·편집본·실패 상태를 분리한다. 같은 로그인 중에는 화면 이동·설정 재진입 후 미저장 입력을 우선 복원하고, 하나를 저장해도 다른 입력의 미저장 상태를 없애지 않는다. 설정 닫기·로그아웃 확인은 아동 특성과 두 교사 입력을 함께 확인하도록 확장한다. 로그아웃 성공·401·앱 종료 시 임시 입력을 정리하며 종료 후 복구는 보장하지 않는다.
- **자료 용도:** 글쓰기 예시는 표현 방식, 기록 양식은 구성에 대한 참고 자료다. 예시 속 과거 아동·사건을 현재 관찰 근거로 사용하지 않는다. 이번 FE에서는 자료의 AI 전달·학습·일지 생성 반영을 연결하지 않으며, 알림장 양식 설명 입력이 알림장 생성 기능의 추가를 뜻하지 않는다. (AC1·AC2)
- **FE 연결 경계:** 현재 교사 API는 `teacher_id`·`display_name`을 제공하며 두 자료의 저장·조회 계약은 없다. 교사별 조회·저장 연결부와 미연결 안내까지만 준비하고 실제 성공 응답 전에는 저장 완료로 표시하지 않는다. ‘우리 원 기록 양식’도 현재 교사의 입력으로 관리한다. 원 전체 공유·새 API 필드/경로·DB·정본 문서 변경과 영구 저장 검증은 별도 계약·연동 범위다.

## 3. 검증

구현 후 가상 교사·가상 예시와 대체 저장/조회 연결부로 검사하고 [검증 기록](../TEST_RESULTS.md)에 결과를 남긴다.

| 구분 | 중점 확인 |
| --- | --- |
| 화면·이동 | 교사 이름 아래 버튼 순서, 각 화면의 문구·입력·저장 버튼, 상단/Android 뒤로가기 목적지 |
| 저장·복원 | FE-04 공통 상태·오류 처리, 두 자료별 저장/재시도, 설정 재진입·미저장 이탈 취소, 입력 중 조회·늦은 응답·중복 저장 |
| 분리·회귀 | 교사 계정·입력 종류 간 혼입 방지, 다른 입력 저장 후 미저장 상태 유지, 기존 아동 명단·특성·로그아웃 동작 |
| 연결·기기 | 미연결의 가짜 성공·추가 AI 호출 없음, 작은 화면·큰 글자·긴 본문·키보드·스크롤·접근성 |

위 항목은 실행 계획이다. 기존 테스트·AC·골든 케이스 판정은 유지하고, 자동 검사·실제 화면·영구 저장 검증을 구분한다.
