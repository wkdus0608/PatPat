# FE-03 계획 — 관찰일지 작성

- 상태: FE 구현 완료 · 실제 기기 확인과 백엔드 연결 대기
- 작성일: 2026-11-01
- 범위: FE 화면·선택·편집·상태·공유 연결. 구현일 2026-11-02, 검증 결과는 [TEST_RESULTS](../TEST_RESULTS.md) 참고

## 1. 목표와 화면

**흐름:** 녹음 여러 개 가져오기 → 아동별 초안 확인·직접 수정 → 필요하면 수정 요청 → 교사 확정·저장 → 공유.

현재 로고·색상·하단 탭을 유지하고 작성 탭에 아래 영역을 배치한다.

| 영역 | 구성 |
| --- | --- |
| 사용할 녹음 | ‘녹음 보관함에서 가져오기’ 버튼, 선택 파일 목록·선택 해제 |
| 관찰일지 초안 | ‘초안 작성’ 버튼, 아동별 초안 선택, 본문 편집·근거·확인 필요 표시 |
| 수정 요청 | 여러 줄 프롬프트 입력, ‘수정 요청’ 버튼, 수정 제안 확인·적용 |
| 마무리 | ‘확정하기’와 ‘공유하기’ 버튼, 처리 상태·실패 안내 |

## 2. 녹음 선택과 초안 확인

### 녹음 가져오기

- 작성 탭 안에서 보관함의 날짜별 녹음 목록을 재사용한 **선택 전용 화면**으로 이동한다. 보관함의 단건 조회·삭제 동작과 구분한다.
- 체크박스로 여러 파일을 선택하고 ‘선택한 녹음 가져오기’로 돌아온다. 0개일 때 가져오기를 막고 취소하면 이전 선택을 유지한다.
- 선택 파일의 날짜·시각·파일명을 표시한다. ‘선택 해제’는 원음 파일을 삭제하지 않는다.
- 기존 초안이 있는 상태에서 파일 구성을 바꾸면 확인 후 초안·수정 제안·확정 상태를 초기화한다. 취소하면 선택과 편집 내용을 보존한다.
- 초안 요청 전 파일 존재를 다시 확인한다. 삭제·손상된 파일은 안내하고 임의로 빼거나 다른 파일로 대체하지 않는다.

### 초안 확인·직접 수정

- 선택한 녹음과 연결된 관찰만 사용한다. 응답의 아동 순서를 유지하고 아동별 카드나 전환 버튼으로 기록을 나눠 본다.
- 공통 활동과 아동별 문장·근거를 구분한다. 제공된 관찰·배움 읽기·놀이 지원·지원 계획만 표시하고 없는 항목을 채우지 않는다.
- 개별 근거가 없는 아동은 `missing_evidence`에 따라 ‘확인 필요’로 표시한다. 연결되지 않은 근거 원문을 만들어 보여주지 않는다.
- 교사는 본문을 직접 수정할 수 있다. 다른 아동으로 이동해도 각 편집 내용을 따로 유지한다.

## 3. 수정 요청

- 예시 안내: ‘관찰 사실은 유지하고 문장을 더 간결하게 바꿔줘.’ 빈 프롬프트로는 요청하지 않는다.
- 요청 대상은 **현재 선택한 아동의 기록**이다. 다른 아동의 초안·직접 수정 내용을 함께 바꾸지 않는다.
- 현재 편집본과 요청 당시의 근거·버전을 기준으로 새 수정 후보를 받는다. 기존 글 옆에 제안으로 보여 주고 교사가 ‘적용’하거나 ‘취소’한다.
- 실패·취소 시 기존 본문과 프롬프트를 유지한다. 늦게 도착한 응답이 이후 편집이나 다른 아동의 기록을 덮지 않게 한다.
- 프롬프트·수정 본문도 가명 처리 확인 후에만 외부 AI 처리 경로로 넘긴다. 입력에 없는 사실을 추가하는 수정은 허용하지 않는다.

## 4. 확정·공유와 보관함 연결

- 교사가 현재 아동의 최종 본문을 확인하고 **‘확정하기’**를 누른다. 빈 본문·처리 중에는 확정·공유를 막는다.
- 확정은 해당 `record_id`의 `edited_text`를 공백·줄바꿈까지 그대로 저장한다. 모델을 다시 호출해 다듬지 않는다.
- 실제 저장 성공 응답 이후에만 완료로 표시하고 공유를 활성화한다. 확정 후 본문을 바꾸면 공유를 잠그고 다시 확정해야 한다.
- ‘공유하기’는 **현재 아동의 저장된 확정 본문만** React Native의 기본 텍스트 공유창으로 연다. 다른 아동 기록·원음·프롬프트·내부 ID는 넣지 않는다.
- 공유창에서 교사가 대상 앱을 선택한다. 취소·실패해도 확정 기록은 유지하며, 공유창을 연 결과를 실제 수신·발송 완료로 표시하지 않는다.
- 저장·조회 공급원이 연결되면 FE-02의 ‘작성한 관찰일지’에 같은 최종 본문을 표시한다. 화면 이동만으로 저장됐다고 처리하지 않는다.

## 5. 현재 연결 범위와 상태 처리

| 기능 | 이번 FE에서의 범위 |
| --- | --- |
| 녹음 가져오기 | 기존 기기 파일 목록과 실제 다중 선택 연결 |
| 초안 생성·수정 요청 | 화면·입력·요청/응답 연결 경계 준비. 공급원 미연결 시 ‘연결 준비 중’ 안내와 실행 제한 |
| 확정·관찰일지 저장 | 저장 연결 경계 준비. 미연결 상태에서 완료나 보관함 등록으로 표시하지 않음 |
| 공유 | 모바일 공유 연결 준비. 실제 확정·저장이 확인된 본문이 있을 때만 사용 |

- 로컬 전사·가명 처리·아동/관찰 연결·DB·AI·새 API는 구현하지 않는다. 실제 생성·재요청은 해당 처리와 계약 연동 후 동작한다.
- 현재 SPEC은 `observation_ids` 기반이며 BE 계획에는 녹음 기반 요청 방향이 있다. 계약 정리 전 파일명·경로를 관찰 ID로 바꾸거나 요청 필드를 임의 추가하지 않는다.
- 로딩·미연결·빈 선택·요청 실패를 구분하고 중복 요청을 막는다. 실제 기록처럼 보이는 예시를 실앱에 넣지 않는다.
- 일반 탭 이동에는 앱 실행 중 선택·편집 상태를 유지한다. 생성·수정 중 이탈과 편집 폐기에는 확인하며 확정·공유 처리 중에는 이동을 막는다. 강제 종료 후 복구는 이번 범위에서 보장하지 않는다.
- 녹음·재생 중 탭 이동 제한과 자원 정리를 유지한다. 웹은 화면·입력 미리보기로 구분하며 기기 파일·모바일 공유를 가짜로 실행하지 않는다.

## 6. 작업·검증과 시작 조건

커밋 단위: ① 작성 화면·다중 선택 ② 초안·직접 편집 ③ 수정 요청·제안 적용 ④ 확정·공유·보관함 연결 경계 ⑤ 검증·안내. 커밋 실행은 별도 요청에 따른다.

| 검증 | 기준 |
| --- | --- |
| 선택 | 다중 선택·취소·해제·파일 소실, 기존 초안 변경 확인, 원음 보존 |
| 초안·수정 | 아동·근거 분리, 직접 편집 보존, 빈 요청·중복·실패·늦은 응답·제안 적용/취소 |
| 확정·공유 | 확정 전·저장 실패·편집 후 공유 차단, 본문 그대로 저장, 모델 재호출 없음, 현재 아동의 확정문만 공유 |
| 연결·회귀 | 미연결 상태 구분, 저장 성공 후 보관함 조회, 기존 녹음·보관함 검사 유지 |
| 기기 | Expo Go의 화면·키보드·뒤로가기·스크롤과 실제 OS 공유창을 플랫폼별 확인 |

가명 코드·가상 관찰로 FE 상태와 표현을 검사한다. 실제 AI 문장 의미 검토·영속 저장·공유·시각 확인은 실행 여부를 따로 기록하고, 미연결·미실행 항목을 통과로 보고하지 않는다. 기존 골든 케이스·AC는 변경하지 않는다.
