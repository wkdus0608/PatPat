# FE-03 계획 — 관찰일지 작성

- 상태: 단계별 FE 화면 전환 구현 완료 · 실제 기기 확인·서버 업무 연동 대기
- 작성일: 2026-11-01 / 수정일: 2026-11-04
- 변경 이유·범위: 사용자 요청에 따라 한 화면에 나열된 작성 단계를 개별 화면으로 나눴다. 화면·제어 코드를 수정했으며, 실행 결과와 미검증 범위는 [검증 기록](../TEST_RESULTS.md)의 2026-11-04 단계별 화면 변경 항목을 따른다.

## 1. 화면 흐름

로고·색상·하단 탭은 유지하고, 작성 탭 안에서 **한 번에 현재 화면 하나만** 표시한다. 스크롤은 단계 이동이 아니라 현재 목록·본문을 끝까지 보는 데 사용한다.

| 화면 | 구성·동작 | 다음 화면 |
| --- | --- | --- |
| **1. 녹음 선택** | ‘관찰일지를 작성할 녹음을 선택해 주세요.’ 안내와 날짜·시각·파일명이 있는 녹음 리스트. 여러 개 선택·해제하고 하단 **‘다음하기’** 누르기 | 초안 생성 중 안내 → 생성 완료 시 2번. 별도의 ‘초안 작성’ 버튼 없음 |
| **2. 초안 확인** | 아동별로 전환하며 초안 전문·근거·확인 필요 표시를 스크롤해 보기. 본문은 읽기 전용 | 하단 **‘직접 수정’ → 2-A**, **‘AI에게 재수정’ → 2-B**, **‘완료’ → 확정·저장 후 3번** |
| **2-A. 직접 수정** | 현재 초안을 즉시 편집할 수 있는 별도 화면. 하단 **‘완료’** | 편집한 본문 확정·저장 후 3번 |
| **2-B. AI에게 재수정** | ‘어떻게 수정해 드릴까요?’ 안내, 여러 줄 프롬프트 입력, 하단 **‘수정하기’** | 수정 결과를 받으면 2번으로 복귀. 같은 화면에서 제안을 검토해 ‘적용’ 또는 ‘취소’한 뒤 세 가지 동작을 다시 선택 |
| **3. 완성본·공유** | 확정된 현재 아동의 관찰일지 전문을 읽기 전용으로 표시하고, 하단 **‘공유하기’** 제공 | 기기 기본 텍스트 공유창에서 대상 앱 선택 |

2-A·2-B는 선택하는 분기이며 모두 거칠 필요는 없다. AI 재수정은 반복할 수 있다. 하단 버튼은 본문 스크롤과 분리하고 키보드·안전 영역에 가리지 않게 한다.

## 2. 공통 동작 규칙

- **이동·보존:** 뒤로가기는 2-A·2-B→2번, 2번→1번, 3번→2번이다. 1번에서는 기존 탭 이동을 따른다. 탭을 옮겨도 실행 중인 화면·선택 아동·녹음·편집본·프롬프트·후보를 유지한다. 강제 종료 후 복구는 보장하지 않는다.
- **선택 변경:** 선택 해제로 원음을 삭제하지 않는다. 기존 초안이 있을 때 녹음 구성을 바꾸려면 확인 후 현재 작업만 초기화한다. 취소하면 작업을 보존하고, 이미 확정·저장한 기록은 지우지 않는다.
- **생성·수정:** 선택한 녹음의 관찰만 사용하고 서버가 고정한 전체 활성 명단 순서와 관찰 원문 순서를 유지한다. 공통 활동·개별 문장·근거를 구분하며, 개별 근거가 없는 아동은 `missing_evidence`에 따라 ‘확인 필요’로 표시한다. 없는 항목·사실을 채우거나 다른 아동의 사실을 섞지 않는다. (AC1·AC2·AC3, GC-07·GC-19)
- **AI 제안:** 요청 대상은 현재 아동이다. 직접 편집본이 있으면 그대로 저장한 뒤 최신 버전으로 요청한다. 제안은 기존 본문을 덮지 않고, 적용·취소 전에는 직접 수정·재요청·완료를 막는다. 적용은 후보 채택이며 최종 확정이 아니다. 오래된 버전·후보는 재조회·재검토한다.
- **완료·공유:** 두 ‘완료’는 현재 아동의 `edited_text`와 `expected_version`을 제출해 공백·줄바꿈까지 그대로 저장하며 AI를 재호출하지 않는다. 저장 성공 후에만 3번으로 이동한다. 공유 직전 상세를 재조회해 `can_share`를 확인하고 `share_text`만 전달한다. 확정 후 본문 수정·후보 채택 시 다시 확정해야 한다. 공유 취소·실패는 기록을 지우지 않으며 공유창 열기를 실제 발송 완료로 표시하지 않는다. 저장·조회 연결 후 보관함에도 같은 확정문을 표시한다. (AC5)
- **제한·오류:** 0개 선택·빈 프롬프트·빈 본문은 해당 실행을 막는다. 삭제·손상·전사 미완료 녹음을 임의로 제외·대체하지 않는다. 로딩·빈 목록·실패·미연결을 구분하고 실패 시 해당 화면과 입력을 보존한다. 중복 요청과 취소 후 늦은 응답 적용을 막으며, 생성·수정 중 이탈과 편집 폐기에는 확인하고 확정·공유 중에는 이동을 막는다.

## 3. 연결 범위

- 현재 녹음·전사·일지 업무 서비스는 미연결/기본 501이다. 연결 전에는 실행을 제한하고 ‘연결 준비 중’을 안내하며, 가짜 초안·완료·보관함 등록을 만들지 않는다. 웹은 입력·화면 미리보기로 구분한다. 기존 녹음·재생 중 이동 제한과 자원 정리를 유지한다.
- 현재 MVP 계약은 `recording_ids`로 생성 요청 → 서버의 전사 완료 녹음·전체 활성 명단 고정이다. 원음은 외부 STT로 처리하고 가명 처리는 생략하며, 일지 생성 AI에는 선택 전사문·서버 명단만 전달한다. 원음을 일지 AI 입력에 섞지 않고 API 키는 서버에서 관리한다. 초기 로컬 처리 가정이 남은 FE 연결 경계는 후속 연동 시 맞춘다.
- 화면 변경에 원음 저장·전사·관찰 추출·DB·AI·새 API 구현은 포함하지 않는다. 파일명·경로를 서버 ID로 바꾸거나 요청 필드를 추가하지 않으며, 녹음 저장 날짜만으로 관찰 기간을 추정하지 않는다.

## 4. 구현 후 확인할 항목

| 구분 | 확인 내용 |
| --- | --- |
| 화면·이동 | 첫 진입 녹음 목록, 단계별 단독 화면, 세 가지 분기·AI 결과 복귀, 뒤로가기·탭 복귀 시 상태 보존 |
| 입력·오류 | 다중/0개 선택, 파일 소실·전사 미완료, 빈 입력, 중복 요청·취소·늦은 응답·버전 충돌, 실패/501 시 입력 보존 |
| 기록·공유 | 아동·공통/개별 근거 분리, 제안 적용/취소, 두 완료의 정확한 문구 저장·AI 재호출 없음, 확정 전/재편집 후 공유 차단, 현재 아동 확정문만 공유·보관함 조회 |
| 실제 기기 | Expo Go의 긴 본문 스크롤·키보드·하단 버튼·안전 영역·Android 뒤로가기·OS 공유창 |

가명 코드·가상 관찰로 검증한다. 위 표는 실행 계획이며, 실제 AI 의미 품질·영속 저장·공유·시각 확인 결과는 실행 후 따로 기록한다. 기존 골든 케이스·AC는 변경하지 않는다.
