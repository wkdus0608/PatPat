# FE-03 계획 — 관찰일지·알림장 작성

- 상태: 기존 단계별 화면 구현 완료 / 기록 유형·키워드 입력·‘다음’ 버튼 변경은 계획 수정·구현 전
- 작성일: 2026-11-01 / 수정일: 2026-11-05
- 변경 이유·범위: 사용자 요청에 따라 첫 화면에 기록 유형과 키워드 입력을 추가하고 녹음 선택을 선택 사항으로 바꾼다. 이번에는 FE 계획서만 수정한다. 이전 구현 결과는 [검증 기록](../TEST_RESULTS.md)의 2026-11-04 단계별 화면 변경 항목을 따른다.

## 1. 화면 흐름

로고·색상·하단 탭은 유지하고, 작성 탭 안에서 **한 번에 현재 화면 하나만** 표시한다. 스크롤은 단계 이동이 아니라 현재 목록·본문을 끝까지 보는 데 사용한다.

| 화면 | 구성·동작 | 다음 화면 |
| --- | --- | --- |
| **1. 작성 준비** | 아래 세 항목과 하단 **‘다음’** 버튼. 왼쪽 화살표는 없애고 접근성 이름·관련 안내도 ‘다음’으로 통일 | 연결 가능한 입력은 초안 생성 → 완료 시 2번. 별도의 ‘초안 작성’ 버튼 없음 |
| **2. 초안 확인** | 아동별로 전환하며 초안 전문·근거·확인 필요 표시를 스크롤해 보기. 본문은 읽기 전용 | 하단 **‘직접 수정’ → 2-A**, **‘AI에게 재수정’ → 2-B**, **‘완료’ → 확정·저장 후 3번** |
| **2-A. 직접 수정** | 현재 초안을 즉시 편집할 수 있는 별도 화면. 하단 **‘완료’** | 편집한 본문 확정·저장 후 3번 |
| **2-B. AI에게 재수정** | ‘어떻게 수정해 드릴까요?’ 안내, 여러 줄 프롬프트 입력, 하단 **‘수정하기’** | 수정 결과를 받으면 2번으로 복귀. 같은 화면에서 제안을 검토해 ‘적용’ 또는 ‘취소’한 뒤 세 가지 동작을 다시 선택 |
| **3. 완성본·공유** | 확정된 현재 아동의 기록 전문을 읽기 전용으로 표시하고, 하단 **‘공유하기’** 제공 | 기기 기본 텍스트 공유창에서 대상 앱 선택 |

2-A·2-B는 선택하는 분기이며 모두 거칠 필요는 없다. AI 재수정은 반복할 수 있다. 하단 버튼은 본문 스크롤과 분리하고 키보드·안전 영역에 가리지 않게 한다.

### 첫 화면 입력

| 순서 | 항목 | 구성 |
| --- | --- | --- |
| 1 | **기록 유형(필수)** | ‘어떤 기록을 작성할까요?’ 아래 ‘관찰일지’·‘알림장’ 중 하나 선택. 초기에는 미선택이며 선택 전 ‘다음’ 비활성화 |
| 2 | **녹음 선택(선택)** | 날짜·시각·파일명이 있는 기존 목록에서 다중 선택·해제. 녹음이 없어도 키워드를 입력할 수 있음 |
| 3 | **오늘의 키워드(선택)** | 녹음 목록 아래 여러 줄 입력창. ‘녹음이 없어도 오늘의 관찰을 키워드로 남길 수 있어요.’ 안내와 ‘놀이, 아동의 말과 행동 등을 적어주세요.’ placeholder. 녹음과 함께 입력도 가능 |

## 2. 공통 동작 규칙

- **이동·보존:** 뒤로가기는 2-A·2-B→2번, 2번→1번, 3번→2번이다. 1번에서는 기존 탭 이동을 따른다. 탭·화면 이동 후에도 기록 유형·녹음·키워드·선택 아동·편집본·프롬프트·후보를 유지하고 이후 화면의 기록 표기는 선택 유형에 맞춘다. 강제 종료 후 복구는 보장하지 않는다.
- **입력 변경:** 선택 해제로 원음을 삭제하지 않는다. 기존 초안이 있을 때 유형·녹음·키워드를 바꾸면 확인 후 현재 작업만 초기화한다. 취소하면 기존 입력·작업을 보존하고, 이미 확정·저장한 기록은 지우지 않는다.
- **생성·수정:** 선택 녹음에서 확인된 관찰과 직접 입력한 키워드만 근거로 삼는다. 키워드의 공백·줄바꿈을 보존하고 불명확한 아동·행동·감정을 추측해 채우지 않는다. 서버가 고정한 전체 활성 명단 순서와 관찰 원문 순서, 공통/개별 문장·근거 구분, 개별 근거가 없는 아동의 ‘확인 필요’ 표시를 유지한다. 관찰일지 항목 분류는 해당 유형에만 적용한다. (AC1·AC2·AC3, GC-07·GC-19)
- **AI 제안:** 요청 대상은 현재 아동이다. 직접 편집본이 있으면 그대로 저장한 뒤 최신 버전으로 요청한다. 제안은 기존 본문을 덮지 않고, 적용·취소 전에는 직접 수정·재요청·완료를 막는다. 적용은 후보 채택이며 최종 확정이 아니다. 오래된 버전·후보는 재조회·재검토한다.
- **완료·공유:** 두 ‘완료’는 현재 아동의 `edited_text`와 `expected_version`을 제출해 공백·줄바꿈까지 그대로 저장하며 AI를 재호출하지 않는다. 저장 성공 후에만 3번으로 이동한다. 공유 직전 상세를 재조회해 `can_share`를 확인하고 `share_text`만 전달한다. 확정 후 본문 수정·후보 채택 시 다시 확정해야 한다. 공유 취소·실패는 기록을 지우지 않으며 공유창 열기를 실제 발송 완료로 표시하지 않는다. 저장·조회 연결 후 보관함에도 같은 확정문을 표시한다. (AC5)
- **제한·오류:** 녹음 0개나 빈/공백뿐인 키워드 각각을 필수 입력 오류로 처리하지 않는다. 둘 다 없으면 ‘작성할 관찰 내용이 없어요.’를 안내하고 초안을 생성하지 않는다. 빈 프롬프트·빈 본문은 해당 실행을 막으며, 선택한 녹음의 삭제·손상·전사 미완료를 키워드로 우회하지 않는다. 로딩·빈 목록·실패·미연결을 구분하고 실패 시 화면·입력을 보존한다. 중복 요청·취소 후 늦은 응답을 막으며, 생성·수정 중 이탈과 편집 폐기에는 확인하고 확정·공유 중에는 이동을 막는다.

## 3. 연결 범위

- 현재 녹음·전사·일지 업무 서비스는 미연결/기본 501이다. 연결 전에는 실행을 제한하고 ‘연결 준비 중’을 안내하며, 가짜 초안·완료·보관함 등록을 만들지 않는다. 웹은 입력·화면 미리보기로 구분한다. 기존 녹음·재생 중 이동 제한과 자원 정리를 유지한다.
- 현재 MVP 계약은 `recording_ids`로 생성 요청 → 서버의 전사 완료 녹음·전체 활성 명단 고정이다. 원음은 외부 STT로 처리하고 가명 처리는 생략하며, 일지 생성 AI에는 선택 전사문·서버 명단만 전달한다. 원음을 일지 AI 입력에 섞지 않고 API 키는 서버에서 관리한다. 초기 로컬 처리 가정이 남은 FE 연결 경계는 후속 연동 시 맞춘다.
- 현재 BE는 관찰일지·녹음 1개 이상만 지원하며 알림장·키워드 입력 계약은 없다. FE에서 유형·키워드를 구분해 보존하되 미지원 조합의 ‘다음’은 연결 준비 안내를 표시한다. 키워드를 조용히 버리거나 알림장을 관찰일지로 바꿔 요청하지 않는다. 해당 생성·저장은 BE 계약 확정 후 연결한다.
- 화면 변경에 원음 저장·전사·관찰 추출·DB·AI·새 API 구현은 포함하지 않는다. 키워드를 가짜 녹음/관찰 ID로 만들거나 요청 필드를 임의로 추가하지 않으며, 파일명·경로를 서버 ID로 바꾸지 않는다. 녹음 저장일·키워드 입력일로 관찰일·기간을 확정하지 않는다.

| 실제 기기 | Expo Go의 긴 본문 스크롤·키보드·하단 버튼·안전 영역·Android 뒤로가기·OS 공유창 |

가명 코드·가상 관찰로 검증한다. 이번 추가는 미구현·미검증이며 이전 실행 결과와 구분한다. 기존 ‘0개 선택 차단’·‘다음하기/화살표’ 검사는 사용자 변경 범위에 맞춰 갱신하되 골든 케이스·AC는 유지한다. 실제 AI 의미 품질·영속 저장·공유·시각 확인은 별도로 기록한다.
