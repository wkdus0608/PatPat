# FE-04 계획 — 계정 설정·아동 명단 관리

- 상태: 계획 수정 완료 · 변경 구현 전 / 작성일: 2026-11-04
- 범위: 사용자 요청에 따른 설정·명단 변경 계획. 이번에는 이 문서만 수정한다.

## 1. 화면과 흐름

기존 설정 진입 위치·배치·색상·카드를 유지하고, 상단에 계정 정보와 하단에 아동 추가·명단을 둔다.

| 영역 | 동작 |
| --- | --- |
| 계정·닫기 | 교사 표시 이름·로그아웃 유지. 로그아웃 시 로그인 화면, ‘닫기’ 또는 뒤로가기로 이전 화면 복귀 |
| 추가 | 이름 입력 → ‘아동 추가’ → 서버 저장 성공 후 입력 비우기·목록 반영 |
| 명단 | 카카오톡 친구 목록처럼 **한 아동을 한 줄에, 이름은 한 번만** 표시. 이름순으로 정렬하고 긴 목록은 스크롤. 행별 이름 입력·저장·비활성화 버튼과 비활성 보기 스위치 제거 |
| 삭제 | ‘선택’ → 한 명 이상 체크 → ‘선택한 아동 삭제’ → 대상 이름·인원 확인 → ‘삭제’. 성공한 행만 목록에서 제거 |
| 취소 | 선택 중 ‘취소’·뒤로가기는 체크 해제 후 일반 목록으로 복귀. 삭제 확인창의 취소는 선택 유지 |

## 2. 처리 규칙

- **명단 기준:** 활성·비활성 개념 없이 등록한 아동은 삭제 전까지 모두 표시하고 일지 생성에 사용한다. 동명이인은 `child_id`로 구분하며 합치지 않는다. 화면 정렬은 서버의 명단·생성 순서를 바꾸지 않는다. (AC2)
- **기록 보존:** 삭제는 등록 명단에서 제거하는 동작이다. 확인창에서 기존 관찰일지는 유지됨을 알린다. 과거 기록·초안의 대상과 근거를 보존하고 삭제한 ID는 재사용하지 않는다.
- **입력·오류:** 공백뿐인 이름·0명 삭제는 막고, 선택 중에는 추가를 제한한다. 처리 중 중복 실행·화면 이탈을 막는다. 빈 목록·로딩·연결 실패를 구분하고 추가 실패 시 입력, 일부 삭제 실패 시 실패 대상의 선택을 유지한다. 성공·실패 인원을 안내해 재시도하며 401이면 남은 요청을 중단하고 재로그인한다.
- **서버 변경:** 기존 `is_active`·비활성화 API 재사용으로 처리하지 않는다. 구현 전에 SPEC·온톨로지·작업 규칙·명단/API/작성 계약과 모델·저장소를 등록·조회·삭제 방식으로 맞추고, 삭제 API와 과거 기록 참조 보존 방식을 확정한다.

## 3. 검증

구현 후 가상 계정·아동으로 위 흐름과 오류 처리를 검사한다. 재로그인·서버 재시작 후 추가·삭제 유지, 교사별 명단 분리, 작은 화면·키보드·Android 뒤로가기는 별도로 확인한다. 결과는 실행 후 기록하며 기존 AC·골든 케이스 판정 기준은 유지한다.
