# FE-04 계획 — 계정 설정·아동 명단 관리

- 상태: 명단·특성 입력·명시적 저장 흐름 FE 구현. 특성 저장·조회 API 미연결, 실기기 확인·서버 삭제 연동 대기.
- 작성일: 2026-11-04 / 수정일: 2026-11-05
- 범위: 설정·명단·아동 특성의 FE 화면, 상태 관리, API 연결 경계.
- 변경 이유: 사용자 요청에 따라 기존 임시 입력에 ‘저장하기’·결과 안내·실패 후 재시도를 추가하고, 후속 구현 요청에 따라 FE에 반영한다.

## 1. 화면과 흐름

### 설정·명단

기존 설정 진입 위치·계정 정보·배치·색상·카드를 유지한다.

| 영역 | 동작 |
| --- | --- |
| 계정·닫기 | 교사 표시 이름·로그아웃 유지. 로그아웃 시 로그인 화면, ‘닫기’·뒤로가기로 이전 화면 복귀 |
| 추가 | 이름 입력 → ‘아동 추가’ → 저장 성공 후 입력 비우기·목록 반영 |
| 명단 | 아동당 한 줄·이름 한 번 표시, 이름순 정렬·스크롤. 행별 이름 편집·저장·비활성화와 비활성 보기 스위치 제거 |
| 특성 진입 | 일반 행 오른쪽 ‘특성 작성’·화살표 → 해당 아동 화면. 신규 등록 후에도 제공하되 자동 이동하지 않음. 삭제 선택 중에는 체크박스만 표시 |
| 삭제 | ‘선택’ → 한 명 이상 체크 → ‘선택한 아동 삭제’ → 이름·인원·‘기존 관찰일지는 유지돼요’ 확인 → ‘삭제’. 성공한 행만 제거 |
| 취소 | 선택 중 ‘취소’·뒤로가기는 선택 해제, 삭제 확인 취소는 선택 유지 |

### 아동 특성

- 설정 안의 별도 화면: 상단 ‘뒤로’·‘아동 특성’, 본문 아동 이름·흰색 둥근 입력 카드. 뒤로가기는 명단으로 복귀하며 기존 크림색 배경·갈색 글자·노란 기본 버튼을 사용한다.
- 안내: **‘아동에 대해 알려주세요.’** / ‘좋아하는 놀이, 평소 표현 방식, 도움이 필요한 상황을 자유롭게 적어주세요.’
- 여러 줄 입력창: 접근성 이름 ‘아동 특성’, placeholder ‘아동의 특성을 자유롭게 적어주세요.’. 아래에 **‘저장하기’**와 ‘작성한 뒤 저장하기를 눌러주세요.’를 둔다. 긴 본문·버튼·상태 안내는 함께 스크롤한다.

| 상태·동작 | 표시·처리 |
| --- | --- |
| 편집 | 변경이 있을 때 저장 활성화·‘아직 저장하지 않은 내용이 있어요.’ 표시. 미입력 허용, 기존 내용을 빈 문자열로 지우는 저장도 허용 |
| 저장 중 | ‘저장 중…’·진행 표시. 중복 저장·편집·뒤로가기·설정 닫기·로그아웃 제한 |
| 성공 | 실제 성공 응답 후 ‘아동 특성을 저장했어요.’ 안내창. ‘확인’ 후 현재 화면에 ‘저장됨’ 표시, 재편집하면 미저장 상태 |
| 실패 | ‘저장하지 못했어요. 입력한 내용은 유지돼요. 다시 시도해 주세요.’ 안내창. ‘다시 시도’는 재요청, ‘확인’은 창만 닫음. 실패 상태를 남겨 재진입 후에도 재시도 가능 |
| 미연결 | 저장 클릭 시 ‘아직 저장 기능이 연결되지 않았어요. 입력한 내용은 유지돼요.’ 안내 |
| 미저장 이탈 | 뒤로가기·설정 닫기 시 ‘아직 저장하지 않은 내용이 있어요. 입력한 내용은 이번 로그인 동안 유지돼요.’ 안내. ‘계속 작성’은 입력 화면 유지/복귀, ‘나가기’는 명단/이전 화면으로 이동 |
| 미저장 로그아웃 | ‘로그아웃하면 저장하지 않은 아동 특성이 사라져요.’ 확인 후 실행 |

## 2. 처리 규칙

- **명단·선택:** 서버가 반환한 모든 행을 활성 구분 없이 표시하고 동명이인은 `child_id`로 구분한다. 정렬은 화면 복사본에만 적용한다. 선택 모드·선택 ID·삭제 상태를 관리하며 재조회에서 없어진 ID는 선택에서 뺀다. (AC2)
- **명단 오류:** 공백뿐인 이름·0명 삭제, 처리 중 중복 실행·화면 이탈을 막고 선택 중 추가를 제한한다. 빈 목록·로딩·실패를 구분하며 추가 실패 시 입력, 일부 삭제 실패 시 실패 대상 선택을 보존한다. 성공·실패 인원과 재시도를 안내하고 401이면 남은 요청을 중단·재로그인한다. 명단 로딩·저장·로그아웃 중에는 특성 진입을 막는다.
- **명단 연결:** 삭제는 `deleteChild(token, child_id)` 한 곳에서 호출하며 설정의 `renameChild`·`deactivateChild` 호출은 제거한다. 실제 삭제 API 제공 전에는 가짜 API로 흐름을 검증한다.
- **특성 상태:** 교사·`child_id`별로 마지막 저장본과 편집 입력을 분리한다. 공백·줄바꿈을 그대로 전달하고 성공 응답 전에는 저장본을 갱신하지 않는다. 실패하면 둘 다 보존하며, 늦은 입력·응답을 다른 아동·계정에 적용하지 않는다. (AC2)
- **보존·정리:** 임시 입력의 수명을 설정 화면에서 로그인 세션으로 옮긴다. 화면 이동·설정 닫기·명단 재조회 후에도 미저장 입력·실패 상태를 유지하고 재진입 시 조회본보다 우선 복원한다. 복귀·재진입만으로 저장/재시도하지 않는다. 로그아웃 성공·401·앱 종료 또는 삭제 성공·성공한 명단 조회에서 대상 제외 시 정리한다. 조회·삭제 실패만으로 지우지 않으며 앱 종료·인증 만료 후 복구는 보장하지 않는다.
- **특성 조회:** 연결 후 진입 시 저장본을 조회한다. 로딩·저장본 없음·조회 실패·미연결을 구분하고, 실패 시 기존 입력을 보존하며 저장본 확인 전 덮어쓰기 저장을 막는다.
- **FE 연결 범위:** 현재 SPEC 5-1절·명단 API에는 특성 저장·조회 계약이 없다. FE에 교체 가능한 조회·저장 연결부만 두고 서버 모델·API·DB·정본 문서는 변경하지 않는다. 기존 명단 요청에 특성을 추가하거나 경로·필드·저장 위치를 임의로 정하지 않는다. 임시 보관·가짜 서비스 성공을 실제 저장으로 표시하지 않으며, 영구 저장은 별도 BE 계약·연동 후 검증한다. 특성의 관찰 근거 변환·AI 전달·일지 상태 변경은 포함하지 않는다. (AC1·AC2)

## 3. 검증

가짜 API·저장/조회 연결부와 가상 아동으로 1~2절을 검사하고 결과는 [검증 기록](../TEST_RESULTS.md)에 남긴다.

| 구분 | 중점 확인 |
| --- | --- |
| 화면·상태 | `tests/settingsView.test.ts`: 버튼·입력·안내창·상태별 제약. 긴 이름·빈 입력 포함 |
| 명단 회귀 | `tests/rosterSelection.test.ts`: 추가·선택·삭제·취소, 부분 실패·401, 화면 정렬과 서버 순서 분리 |
| 특성 제어 | `tests/childCharacteristics.test.ts`: 성공 전 저장본 유지, 실패 후 설정 재진입·수동 재시도, 미저장 이탈 취소, 아동/계정 분리·지연 응답, 조회 실패·중복 실행·정리 경계 |
| 연결 | 미연결의 성공 표시 금지, 명단 요청·AI·일지 상태에 영향 없음. 실제 서버 삭제·특성 영구 저장은 API 제공 후 별도 확인 |
| 기기 | 작은 화면·큰 글자·긴 본문·스크롤·키보드·안전 영역·Android 뒤로가기, 재로그인 후 명단 조회 |

기존 187개 통과 기록은 이전 임시 입력 구현의 결과다. ‘저장 버튼 없음·설정 닫기 시 초기화’와 이에 따른 이탈 검사는 사용자 변경 범위에 맞춰 갱신하며, 나머지 기존 검사·AC·골든 케이스 판정은 유지한다. 이번 실행 결과는 검증 기록에 별도로 남기고 정적 화면/실기기, 가짜 서비스/실제 저장 결과를 구분한다.
