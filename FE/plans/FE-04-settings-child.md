# FE-04 계획 — 계정 설정·아동 명단 관리

- 상태: FE 범위로 계획 수정 완료 · 구현 전 / 작성일: 2026-11-04
- 범위: 설정 화면의 계정 정보·아동 명단 UI와 명단 제어·API 호출 코드(FE). 서버 모델·API·계약 문서 변경은 이 계획에서 다루지 않는다.

## 1. 화면과 흐름

기존 설정 진입 위치·배치·색상·카드를 유지하고, 상단에 계정 정보와 하단에 아동 추가·명단을 둔다.

| 영역 | 동작 |
| --- | --- |
| 계정·닫기 | 교사 표시 이름·로그아웃 유지. 로그아웃 시 로그인 화면, ‘닫기’ 또는 뒤로가기로 이전 화면 복귀 |
| 추가 | 이름 입력 → ‘아동 추가’ → 저장 성공 응답 후 입력 비우기·목록 반영 |
| 명단 | 카카오톡 친구 목록처럼 **한 아동을 한 줄에, 이름은 한 번만** 표시. 이름순으로 정렬하고 긴 목록은 스크롤. 행별 이름 입력·저장·비활성화 버튼과 비활성 보기 스위치 제거 |
| 삭제 | ‘선택’ → 한 명 이상 체크 → ‘선택한 아동 삭제’ → 대상 이름·인원 확인 → ‘삭제’. 성공한 행만 목록에서 제거 |
| 취소 | 선택 중 ‘취소’·뒤로가기는 체크 해제 후 일반 목록으로 복귀. 삭제 확인창의 취소는 선택 유지 |

## 2. 처리 규칙

- **명단 표시:** 서버가 돌려준 명단을 모두 표시하고, 화면에서 활성·비활성 구분(‘비활성’ 표시, 비활성 포함 조회)을 하지 않는다. 동명이인은 `child_id`로 구분해 각각 한 줄로 둔다. 이름순 정렬은 화면 표시용 복사본에만 적용하고, 작성 화면에 넘기는 명단 순서는 바꾸지 않는다. (AC2)
- **API 연결:** 삭제는 API 클라이언트의 `deleteChild(token, child_id)` 한 곳에서만 호출한다. 설정 화면에서 `renameChild`·`deactivateChild` 호출을 제거한다. 서버 엔드포인트는 BE 계약을 따르며, 연동 전에는 가짜 API로 FE 흐름을 구현·검증한다.
- **선택 상태:** 명단 제어 코드에 선택 모드·선택한 `child_id` 목록·삭제 진행 상태를 둔다. 명단을 다시 불러오면 목록에 없는 ID는 선택에서 뺀다.
- **확인창:** 삭제 대상 이름·인원과 ‘기존 관찰일지는 유지돼요’ 안내를 표시한다.
- **입력·오류:** 공백뿐인 이름·0명 삭제는 막고, 선택 중에는 추가를 제한한다. 처리 중 중복 실행·화면 이탈을 막는다. 빈 목록·로딩·연결 실패를 구분하고 추가 실패 시 입력, 일부 삭제 실패 시 실패 대상의 선택을 유지한다. 성공·실패 인원을 안내해 재시도하며 401이면 남은 요청을 중단하고 재로그인한다.

## 3. 검증

가짜 API와 가상 아동으로 명단 제어 테스트(`tests/rosterSelection.test.ts`)와 화면 표시 테스트(`tests/settingsView.test.ts`)를 실행해 위 흐름과 오류 처리를 검사한다. 작은 화면·키보드·Android 뒤로가기, 재로그인 후 명단 재조회는 기기에서 별도로 확인하고, 실제 서버 삭제 연동은 서버 삭제 API 제공 후 확인한다. 결과는 실행 후 [검증 기록](../TEST_RESULTS.md)에 남기며 기존 AC·골든 케이스 판정 기준은 유지한다.
