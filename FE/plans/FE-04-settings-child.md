# FE-04 계획 — 계정 설정·아동 명단 관리

- 상태: 기존 명단 UI FE 구현 완료 · 실기기 확인·서버 삭제 연동 대기 / 아동 특성 입력 화면은 계획 추가·구현 전
- 작성일: 2026-11-04 / 수정일: 2026-11-05
- 범위: 설정 화면의 계정 정보·아동 명단 UI와 명단 제어·API 호출 코드(FE), 아동별 특성 입력 화면·임시 입력 상태. 서버 모델·API·계약 문서 변경은 이 계획에서 다루지 않는다.
- 변경 이유: 2026-11-05 사용자 요청에 따라 등록한 아동의 특성을 적는 화면과 진입 버튼을 추가한다. 기존 계정·추가·선택·삭제 흐름은 유지하며, 이번 작업은 계획서 수정까지만 수행한다.

## 1. 화면과 흐름

기존 설정 진입 위치·배치·색상·카드를 유지하고, 상단에 계정 정보와 하단에 아동 추가·명단을 둔다.

| 영역 | 동작 |
| --- | --- |
| 계정·닫기 | 교사 표시 이름·로그아웃 유지. 로그아웃 시 로그인 화면, ‘닫기’ 또는 뒤로가기로 이전 화면 복귀 |
| 추가 | 이름 입력 → ‘아동 추가’ → 저장 성공 응답 후 입력 비우기·목록 반영 |
| 명단 | 카카오톡 친구 목록처럼 **한 아동을 한 줄에, 이름은 한 번만** 표시. 이름순으로 정렬하고 긴 목록은 스크롤. 행별 이름 입력·저장·비활성화 버튼과 비활성 보기 스위치 제거 |
| 특성 화면 진입 | 일반 명단의 각 아동 행 오른쪽에 ‘특성 작성’ 버튼과 오른쪽 화살표 표시 → 해당 아동의 특성 입력 화면. 새로 추가한 아동도 등록 성공 후 같은 버튼 제공. 추가 직후 자동 이동하지 않음 |
| 특성 화면 복귀 | 상단 ‘뒤로’ 또는 Android 뒤로가기로 명단 복귀. 특성 화면에서 설정 전체를 바로 닫지 않음 |
| 삭제 | ‘선택’ → 한 명 이상 체크 → ‘선택한 아동 삭제’ → 대상 이름·인원 확인 → ‘삭제’. 성공한 행만 목록에서 제거 |
| 취소 | 선택 중 ‘취소’·뒤로가기는 체크 해제 후 일반 목록으로 복귀. 삭제 확인창의 취소는 선택 유지 |

### 아동 특성 입력 화면

- 설정 화면 안의 별도 화면으로 표시한다. 상단은 ‘뒤로’와 제목 ‘아동 특성’, 본문은 대상 아동 이름과 하나의 입력 카드로 구성한다.
- 카드 안내는 **‘아동에 대해 알려주세요.’**, 보조 문구는 ‘좋아하는 놀이, 평소 표현 방식, 도움이 필요한 상황을 자유롭게 적어주세요.’로 한다.
- 입력창은 ‘아동 특성’ 접근성 이름을 가진 여러 줄 텍스트 입력창으로 두고, placeholder는 ‘아동의 특성을 자유롭게 적어주세요.’로 한다. 특성 입력은 선택 사항이며, 미입력 상태도 허용한다.
- 기존 크림색 배경·갈색 글자·흰색 둥근 카드·노란 강조색·여백을 재사용한다. 작은 화면에서도 긴 아동 이름과 입력창이 버튼을 가리지 않게 하고, 긴 본문 스크롤·키보드·안전 영역을 고려한다.
- 현재 특성 저장 API가 없으므로 별도 저장 성공 표시나 저장 버튼은 두지 않는다. 입력창 아래에 ‘입력한 내용은 명단으로 돌아와도 유지되지만, 설정을 닫으면 사라져요.’를 표시한다. 영구 저장은 후속 계약·연동 범위다.

## 2. 처리 규칙

- **명단 표시:** 서버가 돌려준 명단을 모두 표시하고, 화면에서 활성·비활성 구분(‘비활성’ 표시, 비활성 포함 조회)을 하지 않는다. 동명이인은 `child_id`로 구분해 각각 한 줄로 둔다. 이름순 정렬은 화면 표시용 복사본에만 적용하고, 작성 화면에 넘기는 명단 순서는 바꾸지 않는다. (AC2)
- **API 연결:** 삭제는 API 클라이언트의 `deleteChild(token, child_id)` 한 곳에서만 호출한다. 설정 화면에서 `renameChild`·`deactivateChild` 호출을 제거한다. 서버 엔드포인트는 BE 계약을 따르며, 연동 전에는 가짜 API로 FE 흐름을 구현·검증한다.
- **선택 상태:** 명단 제어 코드에 선택 모드·선택한 `child_id` 목록·삭제 진행 상태를 둔다. 명단을 다시 불러오면 목록에 없는 ID는 선택에서 뺀다.
- **특성 화면 이동:** 삭제 선택 모드에서는 ‘특성 작성’ 버튼을 숨기고 기존 체크박스만 표시한다. 명단 로딩·저장·로그아웃 처리 중에는 특성 화면 진입을 막는다. 특성 화면의 뒤로가기는 명단 복귀를 우선 처리하고, 기존 명단의 선택·삭제·닫기 동작은 유지한다.
- **특성 입력 상태:** 입력은 서버 `Child` 필드를 늘리지 않는 FE 화면 상태로만 관리하고 `child_id`별로 분리한다. 같은 설정 화면 안에서는 아동 간 이동·명단 재조회 후에도 공백·줄바꿈을 포함해 입력을 유지한다. 설정 닫기·로그아웃·인증 만료 시 초기화하며, 삭제 성공 또는 재조회로 명단에서 없어진 아동의 입력도 제거한다. 다른 아동·계정의 입력으로 재사용하지 않는다. (아동 분리 원칙: AC2)
- **연결 경계:** SPEC 5-1절과 현재 명단 API에는 특성 필드·저장 경로가 없다. 이번 추가는 FE 입력 화면에 한정하며 기존 등록·이름 수정 요청에 특성을 섞거나 새 API를 임의로 호출하지 않는다. 특성을 관찰 근거로 변환하거나 일지 생성·AI 입력에 연결하지 않는다. 새 도메인 속성·영구 저장 계약이 필요하면 정본 문서부터 별도로 정의한다. (AC1·AC2)
- **확인창:** 삭제 대상 이름·인원과 ‘기존 관찰일지는 유지돼요’ 안내를 표시한다.
- **입력·오류:** 공백뿐인 이름·0명 삭제는 막고, 선택 중에는 추가를 제한한다. 처리 중 중복 실행·화면 이탈을 막는다. 빈 목록·로딩·연결 실패를 구분하고 추가 실패 시 입력, 일부 삭제 실패 시 실패 대상의 선택을 유지한다. 성공·실패 인원을 안내해 재시도하며 401이면 남은 요청을 중단하고 재로그인한다.

## 3. 검증

가짜 API와 가상 아동으로 명단 제어 테스트(`tests/rosterSelection.test.ts`)와 화면 표시 테스트(`tests/settingsView.test.ts`)를 실행해 위 흐름과 오류 처리를 검사한다. 작은 화면·키보드·Android 뒤로가기, 재로그인 후 명단 재조회는 기기에서 별도로 확인하고, 실제 서버 삭제 연동은 서버 삭제 API 제공 후 확인한다. 결과는 실행 후 [검증 기록](../TEST_RESULTS.md)에 남기며 기존 AC·골든 케이스 판정 기준은 유지한다.

아동 특성 화면 구현 후에는 다음 항목을 추가로 확인한다. 아래는 실행 계획이며 이번 계획서 수정에서 구현·검증 완료로 보고하지 않는다.

- 새로 추가한 아동과 기존 아동의 ‘특성 작성’ 버튼, 대상 아동 이름·안내·여러 줄 입력창 표시, 명단 복귀와 재진입 시 입력 유지.
- 동명이인·다른 아동의 입력 분리, 명단 재조회 시 입력 유지, 삭제 실패 시 입력 유지·삭제 성공 또는 목록 제외 시 정리, 설정 닫기·로그아웃·인증 만료 시 초기화.
- 삭제 선택 모드에서 진입 버튼 미표시, 처리 중 진입 차단, 기존 추가·선택·삭제·이름순 표시·서버 명단 순서 유지의 회귀 확인.
- 특성 입력·화면 복귀 시 API 호출·AI 호출·일지 상태 변경이 없고 기존 명단 요청에 특성 필드가 포함되지 않는지 확인.
- 작은 화면·긴 이름·긴 입력·키보드 노출·안전 영역·Android 뒤로가기의 실제 화면 확인. 자동 검사의 입력·이동 결과와 기기 화면 확인 결과를 구분해 기록.
