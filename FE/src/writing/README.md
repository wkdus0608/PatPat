# 관찰일지 작성 화면 연결

FE-03의 단계별 화면과 기존 서비스 연결 경계다. 새 API·DB·도메인 속성은 추가하지 않는다.

## 화면과 상태

- `picker`(녹음 선택) → `review`(초안 확인) → `complete`(완성본·공유). 초안에서 `edit`(직접 수정) 또는 `revision`(AI 수정 요청)으로 이동한다.
- ‘다음하기’는 선택 검증과 생성을 이어서 실행한다. AI 결과는 초안 화면에서 제안으로 검토하고, ‘완료’는 저장 성공 후 완성본으로 이동한다.
- `WritingScreen`은 탭 이동 중에도 유지된다. 선택 화면으로 탭 복귀할 때 목록을 새로 읽으며 선택·편집 내용은 보존한다. 앱 종료 후 복구나 영속 저장을 대신하지 않는다.
- 기본 앱에는 기기 녹음 목록과 모바일 공유창만 연결한다. 생성·수정·확정은 미연결이므로 실행을 제한하고 가짜 결과를 만들지 않는다.

## 기존 연결 경계와 후속 서버 연동

`PatPatAppView`의 `writingServices: WritingServices`로 주입한다. 아래는 초기 로컬 처리 설계의 FE 포트이며 현재 MVP의 HTTP 계약이 아니다. 이번 변경은 화면 전환과 상태 제어에 한정해 기존 계약 검사와 포트를 유지했다.

| 포트 | 현재 역할 |
| --- | --- |
| `workflow.prepare` | 선택한 기기 파일에 대응하는 관찰·아동 순서와 초기 `privacyVerified` 검증값 반환 |
| `workflow.generate` | 초기 관찰 기반 `DraftRequest`로 초안 반환 |
| `workflow.revise` | 현재 아동·본문·프롬프트·근거로 수정 후보 `{text}` 반환 |
| `confirmation.confirm` | `{edited_text}` 그대로 저장한 뒤 `{status: '완료'}` 반환 |
| `journals` | 동일 저장소의 확정 목록·최종 본문을 보관함에 제공 |
| `sharing` | 현재 아동의 확정문으로 Android·iOS 기본 텍스트 공유창 열기 |

현재 MVP 정본은 [SPEC](../../../docs/SPEC.md) 3·5-1절과 [API 계약](../../../BE/docs/API_CONTRACT.md)·[작성 계약](../../../BE/docs/WRITING.md)이다. 외부 STT·가명 처리 생략, `recording_ids` 기반 생성, 서버 명단·버전, 서버의 수정 후보 채택과 공유 직전 상세 재조회는 후속 서버 어댑터에서 연결해야 한다. 초기 포트를 현재 서버 API에 직접 연결하거나 파일 경로를 서버 ID로 변환하지 않는다. 기존 FE의 `version`은 앱 실행 중 편집·후보 무효화용이며 서버 버전이 아니다.

## 보존할 조건

- 아동별 편집과 근거를 분리하고, 빈 근거를 사실로 채우지 않는다. 구조 검사와 실제 AI 문장 의미 검증은 구분한다.
- 생성·수정 중 이탈에는 확인하고 늦은 응답을 무시한다. 확정·공유 중에는 이동·편집을 막는다.
- 확정은 교사 본문을 공백·줄바꿈까지 보존하고 AI를 다시 호출하지 않는다. 저장 실패로 완성본 화면이나 보관함 행을 만들지 않는다.
- `opened`는 공유창 처리 결과이며 실제 수신·발송 완료가 아니다. 공유 취소·실패 후에도 확정 기록은 유지한다.

상세 화면 흐름은 [FE-03 계획](../../plans/FE-03-journal-writing.md), 실행한 검사와 미검증 범위는 [TEST_RESULTS](../../TEST_RESULTS.md)를 따른다.
