# 관찰일지 작성 화면 연결

FE-03의 화면 상태와 연결 경계다. 새 API·DB·도메인 속성을 정의하지 않는다. `EditableJournal`의 버전·후보·확정문은 아동 간 혼입과 늦은 응답을 막기 위한 앱 실행 중 편집 상태다.

## 현재 상태

- `WritingScreen`은 탭을 옮겨도 유지되어 선택·편집을 보존한다. 앱 종료 후 복구나 영속 저장을 대신하지 않는다.
- 기본 실행에는 녹음 목록과 모바일 `Share`만 연결한다. 생성·수정·확정은 미연결이며 가짜 결과를 만들지 않는다.
- 기기 파일은 보관함의 `RecordingLibrary`로 조회·검증한다. 작성 화면은 파일을 삭제·이동·복사하지 않는다.

## 연결 지점

`PatPatAppView`의 선택 속성 `writingServices: WritingServices`로 주입한다. `types.ts`의 각 포트는 로컬 서비스와 FE 사이의 연결이며 HTTP 계약이 아니다. API 합의 전 임의 URL을 만들지 않는다.

| 포트 | 책임 |
| --- | --- |
| `workflow.prepare` | 선택한 녹음만 로컬 전사·가명 처리하고 연결된 관찰, 요청 아동 순서, 선택 파일 대응을 반환 |
| `workflow.generate` | 정본 `DraftRequest`를 처리하고 SPEC 초안 응답을 반환 |
| `workflow.revise` | 현재 아동·본문·프롬프트·근거를 받아 로컬 검증·가명 처리 후 수정 후보 `{text}` 반환. 아직 정본에 없는 수정 API를 의미하지 않음 |
| `confirmation.confirm` | 해당 `record_id`에 `{edited_text}`를 그대로 로컬 저장한 뒤 정본 `{status: '완료'}` 반환 |
| `journals` | 같은 저장소의 완료 목록과 최종 본문 조회. 기존 보관함에도 같은 인스턴스를 전달 |
| `sharing` | 확정한 현재 아동의 본문만 공유. 미지정 시 Android·iOS 기본 텍스트 공유창 사용 |

`PreparedObservations`의 `recordingUris`, `childIds`, `privacyVerified`는 로컬 준비 결과 확인용 FE 정보이며 서버 요청 필드가 아니다. `generate`에는 `record_type`, `child_ids`, `observation_ids`만 전달한다. 원본 경로·파일·실명 매핑을 외부 AI 요청에 넣지 않는다. 관찰일지 기간을 파일 생성 날짜로 추정하지 않는다.

## 연결 시 지켜야 할 조건

1. `workflow`는 **신뢰하는 로컬 처리 경계**에만 연결한다. `privacyVerified: true`는 로컬 검증 성공 후에만 설정한다. FE의 불리언 검사는 실제 전사·가명 처리 성공을 증명하지 않는다.
2. 직접 편집문과 프롬프트에도 실명이 들어갈 수 있다. `revise`를 외부 AI 클라이언트에 바로 연결하지 않는다. 로컬에서 가명 처리·매핑 확인 실패 시 외부 요청을 중단한다.
3. 요청 관찰 순서·아동 순서를 보존한다. 불명확·다른 아동의 근거, 누락·중복 응답, 교사 확정 전 완료 응답은 거부한다. 응답 문장의 의미·사실 보존은 별도 검증 대상이다.
4. `AbortSignal`로 생성·수정 요청 취소를 처리한다. 취소를 무시한 늦은 응답도 FE가 적용하지 않는다. 확정·공유 처리 중에는 이동과 편집을 막는다.
5. 확정 경로에서 모델을 호출하지 않는다. 저장 실패를 완료로 반환하지 않으며, 저장·조회는 같은 정확한 최종 본문을 사용한다. FE는 서버 상태를 가정해 보관함에 임의 행을 추가하지 않는다.
6. `opened`는 OS 공유창 처리 결과다. 수신·발송 완료가 아니며, 취소·실패해도 확정 기록을 지우지 않는다.

정본은 [SPEC](../../../docs/SPEC.md), 동작 범위는 [FE-03 계획](../../plans/FE-03-journal-writing.md)을 따른다. 현재 SPEC의 관찰 기반 요청과 BE 설계 계획의 녹음 기반 요청은 구현 전 합의가 필요하다.
