# FE-01 검증 기록

- 기록일: 2026-11-01
- 범위: FE 녹음 제어·기기 파일 저장·탭 화면 코드
- 환경: Windows, Node.js 24.22.1, pnpm 11.25.0, Expo 58.0.22

## 실행 결과

| 실행 | 결과 | 확인 범위 |
| --- | --- | --- |
| `pnpm install --store-dir .pnpm-store` | 성공 | 의존성·잠금 파일 준비. esbuild 빌드 스크립트만 명시적으로 허용 |
| `pnpm typecheck` | 통과 | FE와 테스트 코드의 TypeScript 검사 |
| `pnpm test` | 31/31 통과, skip 없음 | 녹음 제어 11개, native adapter 9개, 파일 저장 11개 |
| `pnpm exec expo install --check` (오프라인) | 호환 버전 일치 출력 | 설치 SDK의 버전 정보 기준. CLI가 오프라인 신뢰도 제한을 안내하므로 온라인 검증 완료로 보지 않음 |
| `pnpm export` | Android·iOS·웹 코드 묶음 생성 성공 | Metro/Hermes 변환. native 앱 설치·기기 실행은 아님 |
| `git diff --check` 및 새 파일 공백 확인 | 통과 | 새 FE 텍스트 파일 24개, JSON 구문·문서 상대 링크·코드 펜스 확인 |

초기 타입 검사에서 React Native 0.88의 제거된 `StatusBar.backgroundColor` 속성 사용이 발견되어 수정했다. 수정 후 타입 검사가 통과했다.

native adapter를 분리한 최종 코드에서도 `pnpm export --max-workers 2`를 실행해 세 플랫폼의 코드 묶음 생성이 성공했다. 파일명 변경이나 판정 기준 완화 없이 검증했다.

## 자동 검사의 의미

- 빠른 시작·중지 조작이 녹음·파일 저장을 중복 실행하지 않는다.
- 같은 분의 파일명 충돌이 기존 녹음을 덮어쓰지 않는다. 충돌을 녹음 시작 전에 확인한다.
- 가상 녹음 10건의 날짜별 저장과 저장 객체 재생성 후 집계를 확인했다. 실제 녹음 10회 측정 결과는 아니다.
- 복사·최종화 실패 시 원본이 유지되고, 저장 재시도가 파일을 중복 생성하지 않는다.
- 빈 파일·잘못된 형식·임시 파일을 정상 파일로 집계하지 않는다.
- 앱 전환 준비 중의 녹음 시작 취소, 녹음 중단, 종료 실패 후 재시도를 가상 녹음기로 확인했다.
- native 종료 오류 이벤트가 발생하면 불완전 파일을 저장 성공으로 처리하지 않는다. 성공 이벤트가 뒤에 와도 해당 녹음의 오류를 지우지 않는다.
- 자정을 넘긴 녹음의 시작일 유지, 저장 완료 후 목록 읽기 실패와 저장 실패의 구분을 확인했다.

테스트의 파일 내용은 합성 문자열·가상 데이터다. 식별 가능한 음성·실제 아동 이름·실명 매핑은 포함하지 않는다.

## 실제로 확인하지 못한 범위

- Android·iOS 기기에서 마이크 녹음과 M4A 재생.
- 실제 기기에서 10회 반복 녹음, 재실행 후 파일 보존, 저장 공간 부족·전화·화면 잠금·백그라운드 처리.
- native 이벤트의 실제 전달 시점, 제조사별 녹음 중지 동작.
- 모바일 화면의 실제 렌더링, 큰 글자·작은 화면의 가독성과 탭 이동 조작.
- 브라우저 화면 확인은 실행 권한이 거절되어 수행하지 못했다. 코드 묶음 성공을 시각 검증으로 대신하지 않는다.
- 권한 요청·거부 UX, 백엔드 DB·API, 전사·가명 처리·초안 생성·수정·확정·공유는 이번 구현에 포함하지 않았다.

현재 골든 케이스는 관찰 분류·초안 생성 중심이다. 이 FE 검사는 제품 전체 골든 케이스·AC 통과나 문장 생성 의미 검토 결과가 아니다. 기존 판정 데이터와 AC는 변경하지 않았다.

## 기기 확인 체크리스트

마이크 사용이 허용된 Android 테스트 기기에 설치해 확인한다. 시험 신호나 가상 문장의 합성 음성을 사용한다.

- [ ] 녹음 시작·시간·중지·저장이 실제 동작과 일치한다.
- [ ] 날짜 폴더와 `날짜_시-분.m4a` 파일명을 확인하고 파일을 재생할 수 있다.
- [ ] 서로 다른 분에 10회 녹음한 파일이 모두 유지된다.
- [ ] 같은 분에 다시 시작하면 기존 파일을 보존하며 충돌을 알린다.
- [ ] 앱 재실행 뒤 오늘 개수·최근 파일을 확인하고 추가 녹음할 수 있다.
- [ ] 자정 경계와 앱 재활성화 뒤 날짜·개수가 갱신된다.
- [ ] 녹음·저장 중 탭 이동과 연속 조작이 파일을 유실시키지 않는다.
- [ ] 앱 전환·잠금·전화 등 중단 시 결과가 실제 파일과 일치한다.
- [ ] 저장 공간 부족 시 성공으로 표시하지 않고 재시도할 수 있다.
- [ ] 화면·탭·글자 크기를 확인한다.

위 항목은 미실행 체크리스트이며 측정 결과가 아니다.

## 2026-11-01 사용자 요청에 따른 UI 보완

위 실행 결과와 미검증 항목·기기 체크리스트는 최초 구현 당시 기록으로 보존한다. 아래 내용은 이후 UI 변경에 대한 추가 기록이며, 기존 자동 검사·골든 케이스·AC의 기대값을 변경하지 않는다.

### 변경 이유와 범위

- 사용자가 제공한 ‘파팻과 함께하는 행복한 친구들.png’를 `assets/patpat-logo.png`로 그대로 복사해 상단 ‘PatPat’ 왼쪽에 배치했다. 파일의 픽셀은 수정하지 않고 화면 표시 영역으로 여백을 조정했다.
- 사용자 요청에 따라 녹음 화면의 소개 문구·오늘 개수·최근 파일 카드·하단 장식을 제거했다. 중앙 녹음 카드의 시간·시작/중지·상태와 저장 결과 안내를 유지했다.
- 화면에 전달하던 집계 정보와 새로고침 동작, 앱 진입·재활성화 때의 집계 조회를 제거했다. 저장·제어 코드의 내부 파일 집계와 기존 31개 자동 검사는 유지했다.
- 날짜별 저장·파일명·충돌·반복 녹음·기존 파일 보존·실패 재시도 규칙은 이번 UI 수정으로 바꾸지 않았다.

### 변경 후 검사 상태

| 실행 | 결과 | 확인 범위 |
| --- | --- | --- |
| `pnpm.cmd typecheck` | 통과 | UI 변경 후 TypeScript 검사 |
| `pnpm.cmd test` | 기존 31/31 통과 | 테스트 코드·기대값 변경 없이 재실행 |
| 원본 PNG와 로고 자산의 SHA-256 비교 | 일치 | 원본을 그대로 복사했는지 확인 |
| `pnpm.cmd export --max-workers 2` | Android·iOS·웹 코드 묶음 생성 성공 | 종료 코드 0, 제공 로고 PNG가 번들 자산에 포함됨. 실제 화면 렌더링 확인은 아님 |

위 최초 구현 당시 결과와 이번 UI 변경 후 재검사 결과를 구분한다. 이전 브라우저 실행 승인 거절을 존중해 이번에도 브라우저의 시각 확인은 수행하지 않았으며, 코드 묶음 생성이나 원본 일치 검사를 실제 화면 확인으로 대신하지 않는다.

### 최신 UI·기기 확인 항목

기존 체크리스트의 ‘오늘 개수·최근 파일 표시’ 확인은 사용자 요청으로 화면에서 제거된 항목이다. 기존 미실행 기록은 유지하고, 현재 화면은 아래 항목으로 확인한다.

- [ ] 제공 로고가 ‘PatPat’ 왼쪽에 표시되고 로고·이름·날짜가 겹치지 않는다.
- [ ] 녹음 화면에 소개 문구·오늘 개수·최근 파일 카드·하단 장식이 표시되지 않는다.
- [ ] 중앙 녹음 카드에서 시간·시작/중지·저장 재시도·상태·저장 결과를 확인할 수 있다.
- [ ] 작은 화면과 큰 글자 설정에서도 녹음 버튼과 저장 결과가 잘리지 않는다.
- [ ] 세 탭을 이동할 수 있고 녹음·저장·재시도 중 이동 제한이 유지된다.
- [ ] 앱 재실행 후 날짜 폴더의 기존 파일을 확인하고, 기존 파일을 보존하며 새 녹음을 추가할 수 있다.
- [ ] 자정 경계에서 시작일 폴더와 파일명을 유지하고, 상단 날짜가 갱신된다.

위 최신 항목도 미실행 체크리스트다. 실제 마이크 녹음·파일 재생·native 이벤트 시점 등 앞서 기록한 미검증 범위는 그대로 남아 있다.
