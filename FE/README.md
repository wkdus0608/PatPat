# PatPat FE

React Native + Expo 프론트엔드다. 로그인·아동 명단은 실제 서버에 연결하며 녹음·보관함·관찰일지 작성 화면을 포함한다.

아래 작성·출력 흐름은 `main`의 v2 구현 기준이다.

## 로그인·명단 연결

[로컬 실행 안내](../README.md)에 따라 서버와 테스트 계정을 준비한다. `.env.example`을 `.env`로 복사하고 `EXPO_PUBLIC_API_BASE_URL`을 서버 주소로 설정한 뒤 앱을 시작한다. 휴대전화에서는 같은 네트워크의 개발 PC 주소를 사용한다.

로그인 후 상단 설정에서 교사 정보·로그아웃과 아동 추가·명단을 제공한다. 명단은 서버 응답을 이름순으로 표시하며 한 행에 이름을 한 번만 보여 준다. ‘선택’으로 여러 아동을 체크해 삭제 대상을 확인하고 취소할 수 있다. 현재 BE에는 아동 삭제 API가 없어 실제 삭제 요청은 ‘서버 연결 준비 중’으로 실패 처리하며 명단을 지우지 않는다. 비활성화 API를 삭제로 대신 호출하지 않는다.

Android·iOS는 SecureStore로 로그인을 유지하고 만료 시 다시 로그인한다. 웹은 토큰을 메모리에만 보관해 새로고침하면 재로그인한다. 서버 연결 실패는 로그인 만료와 구분한다.

`pnpm test:integration`은 FE 클라이언트를 실제 FastAPI·임시 SQLite에 연결해 로그인·명단 변경·교사 분리·서버 재시작·로그아웃을 확인한다. BE 가상 환경이 필요하다. 실기기 SecureStore 동작은 별도 확인 대상이다.

## 실행

검증한 환경은 Node.js 24.22.1, pnpm 11.25.0, Expo SDK 58이다. 의존성 버전은 `pnpm-lock.yaml`에 고정된다.

저장소 루트의 터미널에서 실행한다. PowerShell에서는 `.cmd`를 사용하면 실행 정책 오류를 피할 수 있다.

```powershell
cd FE
pnpm.cmd install
pnpm.cmd start --clear
```

Expo SDK 58에 맞는 Expo Go에서 **이번 실행의 QR 코드**를 스캔한다. 기존 화면이 유지되면 Expo Go를 완전히 종료한 뒤 다시 연결한다. `pnpm.cmd web`은 화면 미리보기이며 휴대전화 파일을 읽거나 재생·삭제하지 않는다.

## 구현 범위

- 녹음·관찰일지 작성·보관함의 하단 탭.
- 발표자료 기반 크림색 배경, 갈색 제목, 둥근 카드, 파스텔 강조색.
- 상단 ‘PatPat’ 왼쪽에 사용자가 제공한 [로고](assets/patpat-logo.png) 표시. PNG를 그대로 복사했으며 화면에서 여백이 적게 보이도록 표시 영역만 조정한다.
- 녹음 시작, 경과 시간, 중지 후 저장, 반복 녹음.
- 녹음 화면은 중앙 녹음 카드와 상태·저장 결과 안내로 구성한다. 사용자 요청에 따라 소개 문구·오늘 개수·최근 파일 카드·하단 장식을 제거했다.
- 중복 조작 차단, 녹음 중 탭 이동 제한, 앱 전환·native 중단 감지.
- 파일 저장 실패 시 원본 유지와 저장 재시도. 실패를 정상 저장으로 표시하지 않는다.

화면에는 개수·최근 파일 정보를 전달하지 않으며 앱 진입·재활성화 때 화면 표시용 집계를 조회하지 않는다. 저장·제어 코드의 내부 집계 기능과 기존 자동 검사는 유지한다.

### 보관함

- 종류 선택 → 녹음 파일 / 작성한 관찰일지 → 목록 → 개별 상세.
- 녹음은 날짜·시각 최신순으로 조회하고, 상세에서 재생·일시정지·처음부터 듣기·확인 후 단건 삭제가 가능하다.
- 뒤로가기·탭 이동·앱 전환 시 재생을 정리한다. 삭제 실패는 성공으로 표시하지 않는다.
- 연결 관찰일지는 보관함에서 날짜별로 확인한다.

### 관찰일지 작성

- 녹음을 선택하면 서버가 외부 STT API로 전사한다. 교사는 알림장 초안을 검토·수정·확정하고 연결 관찰일지를 편집한다.
- 교사 설정에서 Word 양식을 등록한다. 관찰일지에서 아동·기간을 고르고 ‘Word로 출력하기’를 누르면 등록 양식의 서식에 내용을 채운 `.docx`를 받을 수 있다.

### 마이크 사용 전제

녹음 시작을 누르면 마이크 권한을 확인하고, 요청 가능한 상태이면 OS 허용 창을 연다. 거부된 경우 설정에서 마이크를 허용하도록 안내한다. iPhone의 권한 창으로 인한 일시적 inactive는 녹음 준비 취소로 처리하지 않는다.

Expo Go에서 이미 권한을 거부했다면 휴대전화 설정의 Expo Go 마이크 권한을 허용한다. Android 개발 기기는 다음 명령으로 미리 허용할 수도 있다.

```powershell
adb shell pm grant com.patpat.frontend android.permission.RECORD_AUDIO
```

위 패키지명은 독립 앱 빌드의 `app.json` 값이다. Expo Go는 앱 패키지가 다르므로 이미 허용된 Expo Go 환경을 사용한다. iOS의 최초 설치 권한 흐름과 실제 기기 동작은 아직 검증하지 않았다.

## 파일 저장

녹음 시작 시 기기의 현지 날짜·시각을 정하고, 앱 전용 document 경로 아래에 먼저 저장한다. 저장 후 서버 업로드를 시도한다.

```text
recordings/
  2026-11-01/
    2026-11-01_09-10.m4a
    2026-11-01_11-30.m4a
  2026-11-02/
    2026-11-02_09-05.m4a
```

- 초·밀리초·별도 ID를 파일명에 넣지 않는다.
- 같은 분에 저장된 파일이 이미 있으면 새 녹음 시작을 차단한다. 파일을 덮어쓰거나 이름 뒤에 임의 번호를 붙이지 않는다. 다음 분에 다시 시작할 수 있다.
- 23:59에 시작해 다음 날 저장한 녹음은 시작한 날 폴더에 둔다.
- AAC/M4A 설정으로 녹음하며, 다른 파일의 확장자만 바꾸지 않는다.
- 임시 파일은 `.pending`으로 구분하고 정상 저장 파일 집계에 포함하지 않는다. 저장에 성공한 뒤 녹음 캐시를 정리한다.
- 녹음 길이는 현재 녹음 세션에서만 유지한다. 별도 DB·식별자·색인 파일은 없다.
- 저장 실패 파일은 앱이 실행 중인 동안 재시도할 수 있다. 강제 종료·운영체제 종료·앱 삭제 후의 복구는 보장하지 않는다.

## 녹음 서버 연결

새 녹음은 기기에 저장한 직후 연결되어 있으면 바로 서버에 전송한다. 인터넷이 끊겨도 현재 로그인된 앱의 녹음·기기 재생은 가능하며, 앱이 자동으로 재시도하고(앱 복귀 시 즉시) 보관함의 새로고침으로도 재시도한다. 같은 분에 여러 번 녹음하면 `날짜_시-분.m4a`, `날짜_시-분_2.m4a`처럼 순번을 붙여 모두 보관한다. 기기/서버 저장 상태를 구분하고 중복 전송을 방지한다. 기존 기기 녹음은 업로드하지 않는다.

서버 녹음은 인증 후 임시 다운로드로 재생한다. 삭제는 기기·서버·모두를 구분한다. Android·iOS 실기기 재생은 별도 확인이 필요하다. 웹은 기존 미리보기 범위다. 앱을 완전히 종료한 뒤 오프라인으로 다시 열면 기존 로그인 검증에는 서버 연결이 필요하다.
