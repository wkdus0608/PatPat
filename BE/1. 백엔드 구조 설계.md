# 쓰담쓰담 MVP 백엔드 구조·API 설계

## 1. 이번 작업의 결과물

확인한 로컬 기획·인터뷰·온톨로지·스펙·골든 케이스·발표 자료와 [10.28 MVP 메모](https://app.notion.com/p/4075271cc46480ae9e5dff3853a533a4)를 기준으로 설계한다.

- 실제 `PatPat` 저장소의 현재 `main`에서 **`codex/mvp-backend`** 브랜치를 만든다.
- 저장소 안에 **`BE` 폴더**를 만들고 Python FastAPI 기반 구조를 구성한다.
- 이번 범위는 **폴더 구조, 요청·응답 모델, API 문서, 데이터 설계**까지다.
- 서버 상태 확인과 API 문서는 실행 가능하게 만들고, 나머지 기능은 명시적인 `501 NOT_IMPLEMENTED`를 반환한다. DB 저장·녹음 처리·AI 호출·배포는 구현하지 않는다.

## 2. 폴더와 데이터 구조

FastAPI의 [모듈별 라우터 구성](https://fastapi.tiangolo.com/tutorial/bigger-applications/)을 사용하고, 다음 역할을 분리한다.

| 구성 | 역할 |
|---|---|
| API | 테스트 계정 인증, 아동 명단, 녹음, 초안 생성, 일지 수정·확정 |
| 요청·응답 모델 | 프론트와 공유하는 필드·상태·오류·예시 |
| 서비스 인터페이스 | 아동 분류, 생성, 재요청, 확정의 처리 경계 |
| 저장소 인터페이스 | DB 조회·저장과 원음 파일 보관 경계 |
| AI 클라이언트 인터페이스 | 가명 텍스트만 받는 외부 AI 연결 경계 |
| 문서·테스트 | 아키텍처, 데이터 관계, API 계약, 구조 검증 |

데이터 관계는 **교사 → 아동 명단·녹음 → 관찰 → 생성 묶음 → 아동별 일지·수정 이력**으로 정한다. 일지 문장에는 사용한 관찰 ID를 연결한다.

후속 MVP 구현의 기본 저장 방식은 **SQLite에 명단·메타데이터·텍스트를 저장하고, 원음은 서버의 비공개 파일 영역에 보관**하는 구조로 정한다. 이번에는 관계와 저장소 인터페이스만 작성한다.

## 3. 앱과 서버의 처리 계약

- **아동 설정:** 별도 설정 탭에서 전체 명단을 관리한다. 서버 DB에 실명과 고정 아동 ID를 연결하며, 작성할 때마다 아동을 선택하지 않는다. 아동을 비활성화해도 과거 기록의 ID는 유지한다.
- **녹음:** 앱이 녹음·기기 내 전사를 담당한다. 원음은 자체 서버에 보관하지만 외부 AI에는 보내지 않는다. 앱은 서버 명단을 받아 이름을 가명 ID로 바꾼 전사문을 제출한다.
- **자동 작성:** 사용자는 녹음만 선택한다. 서버는 선택한 녹음과 해당 교사의 전체 명단을 대조해 아동별 초안을 만든다. 생성 시작 시 명단과 근거를 고정한다.
- **불명확한 대상:** 동명이인·전사 오류·대상 불명확 관찰을 임의로 배정하지 않는다. 해당 관찰은 제외하고 확인 필요로 표시한다. 가명 처리가 확인되지 않은 입력은 외부 AI 호출을 막는다.
- **근거 없는 아동:** 명단에는 있지만 개별 관찰이 없는 아동은 문장을 만들지 않고 `missing_evidence: true`로 반환한다.
- **관찰일지 형식:** 관찰·배움 읽기·놀이 지원·지원 계획 중 입력에 근거가 있는 항목만 작성한다. 부상·다툼도 사실을 보존하며 관찰 문장에 포함한다.
- **수정:** 직접 저장과 확정은 AI를 호출하지 않는다. AI 재요청은 기존 내용을 덮어쓰지 않고 새 수정 후보를 만든다. 재요청 지시문과 수정 본문도 외부 전송 전에 가명 여부를 검사한다.
- **공유:** 교사가 확정한 글을 앱에서 실명으로 표시하고 복사·OS 공유한다. 별도의 공개 링크나 보호자 발송 API는 만들지 않는다.
- **삭제:** 녹음 삭제 시 원음과 재생 접근을 제거한다. 이미 만든 일지는 유지하고, 사용한 가명 관찰은 근거 스냅샷으로 보존한다. 삭제된 녹음은 신규 작성에 선택할 수 없다.

## 4. API 규격

업무 API는 `/api/v1` 아래에 구성한다. 필드명은 기존 규칙대로 `snake_case`를 사용한다.

| 영역 | 정의할 API |
|---|---|
| 상태·인증 | `GET /health`, 테스트 계정 로그인, 내 계정 조회 |
| 아동 명단 | 목록·등록·수정·비활성화 |
| 녹음 | 파일 업로드, 목록·상세·처리 상태, 인증된 재생, 삭제 |
| 전사문 | 녹음별 가명 전사문 등록·교체와 연결된 관찰 조회 |
| 초안 생성 | `POST /drafts`에 `recording_ids`만 제출, 생성 상태·결과 조회 |
| 관찰일지 | 목록·상세, 직접 수정 저장, AI 수정 재요청, 교사 확정 |

추가 계약은 다음과 같다.

- 로그인 이후의 소유자는 인증 정보로 결정하며, 요청의 `teacher_id`를 신뢰하지 않는다. 일반 회원가입은 제외한다.
- 생성·AI 재요청은 작업 ID를 반환하고 상태 조회로 결과를 확인하는 비동기 계약으로 정의한다.
- 생성 묶음 ID와 아동별 `record_id`를 구분해 특정 아동의 일지만 수정할 수 있게 한다.
- 이전 녹음·일지는 날짜 기준 목록 조회를 지원한다. 일지는 아동·작성 상태로도 필터링한다.
- 녹음의 처리 상태와 일지의 `작성중·검토중·완료` 상태를 분리한다.
- OpenAPI에는 향후 정상 응답 예시와 현재의 미구현 응답을 구분해 표시한다.

## 5. 문서 정합성과 검증

- 아키텍처 문서에 자체 서버의 원음·실명 매핑 보관을 **이번에 변경한 결정**으로 기록한다. 기기 내 전사와 외부 AI의 가명 텍스트 전용 경계는 유지한다.
- 기존 스펙을 이번 관찰일지 MVP와 맞추고, AGENTS의 AC 번호 및 부상 처리 규칙의 불일치를 정리한다. 기존 골든 케이스의 판정 조건은 완화하지 않는다.
- RAG·알림장·사진·PDF 내보내기·외부 플랫폼 연동은 이번 구현에서 제외한다.
- 서버 시작, 상태 응답, OpenAPI 생성, 요청 검증, 미구현 응답을 확인한다.
- DB 연결·파일 저장·외부 AI 호출이 발생하지 않는지 확인한다. 이 검증을 실제 MVP 기능이나 AI 생성 품질의 검증으로 보고하지 않는다.
