# PatPat Evals 설계서

PatPat의 [스펙](../docs/SPEC.md)에 따라 알림장 v2의 관찰 입력, 생성 초안, 교사 확인과 확정 상태를 평가한다. 기존 사례 20개 중 현재 MVP의 AC1~AC5에 적용되는 17개를 실행한다.

## 1. 지표와 합격선

팀이 승인한 단위는 케이스다. 각 지표의 분모는 그 지표가 연결된 케이스 수다. 적용한 기준 전체를 통과한 케이스를 분자로 센다. 같은 지표에서 한 케이스가 여러 기준을 어겨도 위반 건수는 한 건이다.

| 지표 | 기대 조건 | 채점기 | 합격선 | 근거 |
|---|---|---|---|---|
| AC1 관찰 근거 | 필수 관찰 보존, 없는 사실 차단, 개별 관찰 없음 표시, 메모 속 지시 발견 시 교사 확인. `EV-01`의 즐거움 표현만 허용 | 상태·표시는 코드, 사실의 의미는 AI | 위반 0건 | 교사가 관찰한 내용을 전달한다 |
| AC2 아동 귀속 | 다른 아동의 사실 혼입 차단. 대상이 불명확하면 교사가 확인한 아동에게만 반영 | 확인 흐름은 코드, 개인·공동 행동의 귀속은 AI | 위반 0건 | 다른 아이에 대한 행동이 잘못 전달되는 것을 막는다 |
| AC3 공통과 개별 구분 | 공통 관찰은 공통 단락에, 아동별 사실은 해당 개별 단락에 배치. 공통 관찰이 비면 개별 관찰만으로 작성. 반 활동에 불참한 아동은 불참을 명시 | 단락은 코드, 배치된 사실의 의미는 AI | 적용 케이스 100% | 반 전체와 아이별 관찰을 교사가 구분할 수 있다 |
| AC4 부상 사실 보존 | 기록된 부위·좌우·처치를 보존하고 알림장의 특이사항을 분리. 빠진 정보와 충돌은 확인 필요로 표시 | 표시와 영역은 코드, 부상 사실의 의미는 AI | 위반 0건 | 부위와 처치가 보호자에게 정확히 전달되어야 한다 |
| AC5 교사 확정 | 임시 저장 후 미완료, 교사 확정 후 완료와 본문 보존 | 코드 | 위반 0건 | 교사가 완료 시점과 문구를 결정한다 |

**MVP 합격선은 적용 케이스 17건 모두 통과다.** `EV-09`는 공통 관찰 없이 개별 초안이 만들어졌는지 검사한다. 가명 처리인 `EV-17·18`(AC6)은 후속 개발 범위다. 직접 발송과 미지원 안내를 검사했던 `EV-19`는 제품 범위 밖이다. 실행 오류, 알 수 없는 응답, 깨진 AI 판정은 집계에 남긴다.

## 2. 평가 데이터셋

[`evalset.jsonl`](evalset.jsonl)의 필수 키는 `id`, `category`, `query`, `expect`, `graders`, `note`다. 선택 키 `scope`의 기본값은 `mvp`이고, `future`와 `out_of_scope`는 각각 후속 개발과 제품 범위 밖 사례다. `query`에는 아동 역할, 관찰 입력, 앱에서 실행할 동작을 넣었다. `expect.code`는 제품 응답·상태의 경로와 기대값을, `expect.judge`는 의미에 대한 조건을 명시한다. 조작에 쓰는 아동 이름, 원음, 전사문은 모두 가상 데이터다.

| 채점 방식 | 케이스 | 수 |
|---|---|---:|
| 코드 | EV-02, 06, 09, 15, 16, 20 | 6 |
| AI | EV-01, 03~05, 07, 11 | 6 |
| 코드와 AI | EV-08, 10, 12~14 | 5 |

일상·정상 상태를 확인하는 MVP 케이스는 `EV-01`, `03`, `08`, `09`, `11`, `12`, `15`, `16`이다. 나머지 9건은 관찰 부족, 모호한 담당 아동, 기록 충돌, 부재 또는 입력 속 지시를 다룬다. 관찰 없음과 부상 두 유형은 기존 GC-04·GC-08을 활용했고, EV-01은 GC-02와 같은 관찰 유형에 팀이 승인한 별도 평가 예외를 적용했다. 새 실패를 발견하면 어떤 AC를 검증하는지와 기대 조건을 사람이 확인한 뒤 케이스를 추가한다.

## 3. AI 채점과 검증

[`judge_prompt.md`](judge_prompt.md)는 원래 관찰, 공통문, 아동별 초안·특이사항과 기준을 케이스별로 받는다. 기준마다 근거 한 문장을 먼저 쓰고 통과·실패를 JSON으로 반환한다. 표현이 달라도 뜻이 같으면 허용한다. 케이스별 독립 호출을 사용한다.

러너가 저장한 초안과 기준을 사람이 읽고 판단 항목마다 `true` 또는 `false`를 기록한다. AI는 같은 초안을 사람 판정 없이 채점한다. 두 판정의 **일치율 80% 이상**부터 AI 판정을 합격 근거로 사용한다. 현재 MVP의 의미 채점은 11개 케이스에 12개 기준이 적용되므로 모두 비교한다면 10개 이상 일치해야 한다. 기준·프롬프트·모델 변경 시 일치율을 다시 확인한다.

## 4. 실행

저장소 루트에서 실행한다. 백엔드 개발 환경의 Python과 `.[test,ai]` 의존성을 사용한다. 녹음 케이스의 가상 WAV 업로드에는 서버와 동일한 `ffprobe`와 `ffmpeg`를 사용한다.

```sh
python evals/run_evals.py run --mode fake --change '첫 로컬 점검' --golden 'BE 자동 테스트 상태'
python -m unittest discover -s evals -p test_evals.py -v
```

`fake`는 정상 HTTP 경로, 임시 SQLite와 로컬 테스트 모델을 사용한다. `live`는 같은 앱 경로에서 설정된 실제 생성 모델을 호출한다. 두 모드 모두 녹음 케이스에서는 가상 전사문을 제공하며 STT 품질을 측정 범위에서 제외한다. 실제 생성은 `ANTHROPIC_API_KEY`와 `PATPAT_AI_MODEL`을 백엔드 실행 환경에 넣고 `--mode live`로 시작한다.

```sh
python evals/run_evals.py review 'evals/results/<실행_ID>.json'
python evals/run_evals.py review 'evals/results/<실행_ID>.json' --template > 'evals/results/<실행_ID>-human-labels.jsonl'
python evals/run_evals.py judge 'evals/results/<실행_ID>.json' --judge-model '<모델>' --labels 'evals/results/<실행_ID>-human-labels.jsonl'
```

`review`는 원본 초안과 채점할 항목을 보여준다. 생성한 라벨 틀의 `labeler`와 `labels`를 사람이 작성한다. AI 채점에는 `PATPAT_EVAL_JUDGE_API_KEY` 또는 `ANTHROPIC_API_KEY`를 사용한다. 재실행에서 데이터셋·AI 채점 모델·프롬프트·실행 모드가 동일하고 기존 일치율이 현재 기준을 충족하면 `--calibration`으로 검증을 재사용할 수 있다. 종료 코드는 합격 0, 불합격 1, 판정 보류 또는 실행 옵션 오류 2다.

러너는 실제 세션·알림장 API를 호출하고 출력에서 아동별 텍스트와 상태를 추출한다. v2의 공통 단락은 저장된 공통문과 실제 합쳐진 문장의 앞부분을 대조한다. `needs_check`와 알림장 응답은 화면 표시를 위한 백엔드 신호로 확인한다. 기기 렌더링 검증은 별도다. 특이사항은 실제 별도 필드나 제목으로 구분된 문단을 찾는다. 결과 JSON의 `run.excluded_cases`에는 MVP 실행 범위 밖인 사례와 그 범위를 기록한다.

## 5. 첫 기준점과 결과 비교

실행마다 `evals/results/`에 수정하지 않는 JSON 한 건과 `history.csv` 한 줄을 남긴다. 커밋, 변경 설명, 생성 모델과 규칙 해시, 데이터셋 해시, AI 채점 버전·모델, 골든 확인 상태, 지표별 건수와 케이스별 실제 출력을 기록한다. AI 판정은 저장한 원본과 연결한 별도 결과로 남는다.

첫 로컬 실행은 러너와 백엔드 동작의 점검 기준점이다. 범위를 확정하기 전의 20건 결과는 당시 조건으로 보존한다. MVP 범위 변경 후 첫 17건 실행이 새 기준점이다. 외부 모델 호출과 사람 라벨 검증이 가능한 환경에서 실제 모델의 품질 기준점을 측정한다. 실제 비교는 같은 실행 모드·데이터셋·AI 채점 버전과 모델끼리 한다. 모델·프롬프트·검색 조건 변경이나 릴리스 전에 골든 상태를 확인한 커밋에서 실행한다. 동일 커밋을 3회 실행해 지표별 자연 변동 폭을 기록한 뒤 그 폭을 넘는 차이에 대해 개선 또는 회귀를 판단한다.

관찰된 실패를 발생 원인과 빈도로 묶어 개선 순서를 정한다. 첫 실행에 실패 10건이 있으면 10건을 우선 분석하고, 10건보다 적으면 확인된 실패를 모두 기록한다. 첫 실행과 오답 검증 결과는 [러너 위임과 확인 기록](../docs/prompts/delegation_evals.md)에 남긴다.

## 6. 제출 요약

**로컬 MVP Evals 최종 합격.** 데이터셋 20건 중 현재 MVP에 적용되는 17건을 같은 입력으로 재실행했다. 로컬 테스트 모델의 초안을 GPT가 직접 채점했고, 채점 요약을 공유한 뒤 사용자가 12개 판정의 일치를 확인했다. 사용자 확인 기준 일치율은 **12/12(100%)**로 80% 합격선을 충족했다. [사용자 판정 기록](results/2026-11-18T160022Z-7838b4-human-labels.jsonl)

| 수정 후 | 17 | 0 | 0 | [최종 합격 결과](results/2026-11-18T161439Z-7839e7.json) |
