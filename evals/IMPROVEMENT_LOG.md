# 개선 기록 (IMPROVEMENT_LOG)

개선 루프(기준선 → 오류 분석 → 가설 → 변경 → 같은 평가로 재측정 → 홀드아웃 확인)의 기록이다. 기준선은 [BASELINE_LIVE_V2.md](BASELINE_LIVE_V2.md)(2차-b)이고, 개선 전후를 같은 데이터셋·같은 판정 프롬프트·같은 판정 모델(`claude-opus-5-5`)로 3회씩 쟀다. 생성 모델은 `claude-haiku-5-5`, effort `high`다. 코드는 브랜치 `improve/thin-input-questions`에 있다. 이후 사용자 지시로 질문 정책을 정리하고 웹·Word 오류를 고친 변경은 문서 끝의 ‘개선 2’에 있다(브랜치 `fix/question-policy-and-ux`, 실제 모델로는 아직 재측정하지 못했다).

**요약.** 얇은 입력에는 사실을 더 묻고 길고 상세하게 쓰게 했더니, 새로 만든 질문 경로 사례에서 질문의 질과 사실 충실도는 대부분 통과하고 알림장 분량은 입력 분량에 묶이지 않게 늘었다. 그러나 **500자 하한은 새 질문 경로 사례(EV-35~39)에서 한 번도 못 넘었고 EV-31은 3회 중 1회만 넘었다**(평균 달성률 65~99%). **홀드아웃은 API 크레딧이 소진되어 개선 후에 실행하지 못했다**(7절).

## 개선 1. 얇은 입력의 아이에게만 질문 1~2개로 사실을 더 모은 뒤 길게 쓴다

### 1. 배경과 오류 분석

- 사용자 기준(2026-11-21): 알림장은 입력 분량에 비례하지 않게 멘토 예시(약 610자)처럼 길게 쓰되, 없는 사실을 만들면 안 된다.
- 기준선(2차-b)에서 실패 45건 중 가장 많은 범주가 분량 부족(18건, 40%)이었다. 알림장 개별 단락의 중앙값은 48자로 예시의 8%였다.
- 원인은 두 가지였다. 첫째, 규칙 md가 입력 분량에 비례해 짧게 쓰게 했다(`notice/guide.md` 길이 절 등). 둘째, 입력이 짧으면 사실이 부족해서 지어내지 않고는 길게 쓸 수 없다. 멘토 예시 610자는 어떤 사건에나 쓰는 안내 문장 약 110자와 그 사건의 사실 문장 약 490자로 이루어져 있고, 제품은 입력을 1.1~1.8배로 풀어 쓴다.
- 그래서 입력이 얇은 아이에게는 교사에게 사실을 더 묻는 것이 지어내지 않고 길게 쓰는 유일한 방법이다. 다만 2026-11-06에 사용자가 ‘아이당 질문이 많으면 직접 쓰는 것보다 느리다’며 질문을 예외 상황으로 한정하기로 했으므로, 입력이 얇은 아이에게만 한두 개로 제한한다(2026-11-21 사용자 승인).

### 2. 가설

1. 입력이 150자 이하인 아이에게 아이당 1~2개(학급 전체 6개 이내)를 직접 입력으로 묻고 교사가 답하면, 답에서 얻은 사실로 지어내지 않고 500자 이상의 알림장을 쓸 수 있다.
2. 규칙의 길이 지침을 ‘입력 분량에 비례’에서 ‘사실을 빠짐없이 풀어 쓰기 + 끝에 부모 안내’로 바꾸고 긴 예시를 주면, 입력이 충분한 아이는 질문 없이도 500자 근처까지 쓴다.
3. 입력이 충분한 아이에게는 묻지 않고, 교사가 답하지 않으면 사실을 지어내지 않는다(회귀 방지).

### 4. 측정 방법

- **개발 세트**: `evalset.jsonl` 39건 중 MVP 36건 = 기존 31건 + 질문 경로 사례 5건(EV-35~39). 새 사례는 규칙의 예시와 겹치지 않는 장면으로 만들었다.
  - EV-35 한 줄 입력(퍼즐), EV-36 공통 블록이 있는 한 줄 입력(물 주기), EV-37 세 아이(답하는 얇은 아이·답하지 않는 얇은 아이·입력이 충분한 아이), EV-38 부상 한 줄 입력(그네), EV-39 입력이 충분한 대조군(비눗방울).
  - **가상 교사**: 제품이 던진 직접 입력 질문에 사례가 정한 사실(`teacher_facts`)만으로 답한다(제품과 같은 모델). 모르는 질문은 ‘기억나지 않아요.’로 건너뛴다. 판정은 입력과 실제로 전달된 답에 없는 사실을 지어낸 것으로 본다.
  - 모든 알림장 분량 기준은 입력과 무관한 500자(멘토 예시의 약 80%, 임시값)다.
- **홀드아웃**: `evalset_holdout.jsonl` 5건(HO-01~05)은 새 장면으로 같은 구조를 만들었고, 개발 중에는 열지 않았다. 개선 전 결과만 있다([results](results/)의 아래 실행).
- 측정은 모두 3회다. 판정 프롬프트는 가상 교사 항목을 추가한 새 버전이고 개선 전후가 같다. 세트와 판정 프롬프트가 바뀌었으므로 이전 기준선(2차-b)과 숫자를 직접 비교하지 않고, 개선 전도 새 세트로 다시 쟀다.

### 7. 한계와 미검증

- **홀드아웃을 개선 후에 실행하지 못했다.** 3차 시도의 AI 판정 도중 API 크레딧이 소진되어(`Your credit balance is too low`, HTTP 400) 홀드아웃과 이후 측정을 할 수 없다. 개선이 새 장면에서도 통하는지는 확인하지 못했다. 크레딧을 충전한 뒤 아래 명령을 한 번 실행한다(개선 전 결과는 위 표의 실행 ID). 개발 세트에서 이미 여러 번 고쳤으므로 홀드아웃은 한 번만 쓴다.
- 3차 시도의 AI 판정은 EV-33~39에서 오류라 그 시도의 사실 충실도는 EV-01~32까지만 비교했다. 그래서 2차 시도를 최종으로 남겼다.
- 가상 교사는 제품과 같은 모델이라 실제 교사보다 질문을 잘 알아듣고 협조적일 수 있다. 실제 교사의 답은 더 짧거나 일부만 답할 것이다.
- 교사가 질문을 건너뛰면 한 줄 입력에서 지어낸 세부가 가끔 나온다. EV-34(‘블록을 일곱 개 쌓았다.’)는 1·2차 시도 각각 3회 중 1회에서 ‘하나씩 차곡차곡’ 같은 쌓는 방식을 덧붙였고, 개선 전에는 글이 너무 짧아 이런 일이 없었다. 분량을 늘리는 쪽의 위험이다.
- AI 판정은 사람 라벨과 일치율을 확인하기 전의 잠정값이다([사람 채점표](BASELINE_HUMAN_REVIEW.md)는 개선 전 기준선용이다).
- 500자·150자·6개는 모두 임시값이다. 관찰일지는 이번 개선에 포함하지 않았다(`observation/guide.md`의 ‘입력 분량에 맞춘다’ 지침이 그대로다).

```sh
# 저장소 루트, BE 가상 환경. 크레딧을 충전한 뒤 홀드아웃을 한 번만 쟀다(3회 + AI 판정).
set -a && . ./.env && set +a
for i in 1 2 3; do PYTHONDONTWRITEBYTECODE=1 BE/.venv/bin/python evals/run_evals.py run --mode live --evalset evals/evalset_holdout.jsonl --change "개선 후 홀드아웃 $i/3" --golden "BE 376건·골든 하니스 11건·평가기 45건 통과" & done; wait
# 출력된 결과 파일마다
PYTHONDONTWRITEBYTECODE=1 BE/.venv/bin/python evals/run_evals.py judge evals/results/<측정 결과>.json --evalset evals/evalset_holdout.jsonl --judge-model claude-opus-5-5
```

2. **분량 하한**: 지금 사실에 충실한 글은 500자의 65~99%에서 멈춘다. 하한을 450자로 낮추면 EV-31·EV-39는 3회 모두, EV-36은 2회 통과하지만 EV-35·EV-38(입력과 답의 사실이 더 적은 사례)은 여전히 실패한다. 500자를 유지할지, 낮출지, 질문을 더 물어 사실을 늘릴지 정해 주세요.

4. **관찰일지에도 같은 개선**을 적용할지.
5. 브랜치 `improve/thin-input-questions`를 어떻게 합칠지(푸시·병합은 하지 않았다).

### 3. 웹·Word·관찰일지 오류 수정

- **Word**: 관찰 기간·작성 교사·교사의 해석 및 지원 계획 칸을 채운다. 템플릿이 없어도 기본 양식(12행)으로 출력된다(`default_form`). 관찰일지의 ‘해석 및 지원 계획’ 문장이 내용 칸에 섞이던 오류를 분리했다(`split_interpretation`).
- **관찰일지**: 개별 관찰이 없는 아이는 공통 문단에 ‘개별 관찰 없음(반 공통 활동만 기록함).’을 덧붙여 보여 준다. 내용·학습·사건사고 사이의 중복 문장을 제거한다.
- **웹 화면**: 보관함 세로 스크롤(3번째 아이가 잘려 안 보임), 온보딩 ‘이전’, 날짜 직접 입력, 새로고침해도 로그인 유지, 알림장 ‘전체 확정’, 작성 중 경과 시간 안내, 관찰일지 이번 주·이번 달·전체 버튼, 출력 버튼·안내 문구, 확정 후 관찰일지 업데이트 확인 실패를 오류가 아닌 안내로 표시.

### 5. 검증 상태

- **통과**: BE 416건, 골든 하니스 11건, 평가기 47건, FE 302건. `npx tsc --noEmit`은 기존 테스트 파일 3곳(`childCharacteristics`·`rosterSelection`·`teacherSettings`)의 기존 오류만 남고 새 오류는 없다.
- **실제 브라우저(가짜 AI)에서 확인**: 하지 않은 일 질문 → 답 → 초안 → 전체 확정, 보관함 3번째 아이 스크롤, 이번 주 기간 채우기, 새로고침 로그인 유지, Word 기본 양식 출력(200, docx 12행).
- **미검증(실제 모델)**: API 크레딧이 소진되어 모든 프롬프트·규칙 변경을 실제 모델로 확인하지 못했다. 가짜 AI 테스트는 구조(질문이 뜨는지, 모드가 맞는지, 답이 전달되는지)만 본다. 확인이 필요한 것은 ① 모델이 던지는 하지 않은 일 질문의 질 ② 부드러운 모드 알림장의 분량과 사실 충실 ③ ‘그대로’ 모드의 길이 ④ 관찰일지 중복 제거·주어 일관 ⑤ AI의 Word 칸 배치다.

### 6. 고치지 않은 것과 위험

- **고치지 않음**: 콘솔 401 오류(재현되지 않았고 이번 흐름의 네트워크 기록에도 앱이 낸 오류 응답이 없다), 녹음에서 이름을 잘못 알아들었을 때의 안내 문구, README·사용 안내 문서(기존 문서는 사용자가 나중에 일괄 수정), AI가 덧붙인 내용 색 표시·‘기타’ 관찰영역·특성 태그 추천·호칭 설정(기능 추가라 사용자 결정이 필요).
