# PatPat 라이브 기준선 (수정 전 제품)

> **1차 기준선이다.** 같은 날 사용자가 평가 기준(길고 상세하게, 존댓말, 불참 이유, 색칠 사실)을 정해 주어 데이터셋이 바뀌었다. 현재 기준은 [2차 기준선](BASELINE_LIVE_V2.md)이다. 이 문서의 숫자는 기준이 바뀌기 전 값이므로 2차 숫자와 직접 비교하지 않는다.

2026-11-21에 실제 생성 모델로 제품 경로(HTTP → 파이프라인 → Claude)를 25건×3회 측정했다. 이후 개선의 **before 값**이다. AI 판정은 사람 확인 전의 잠정값이다.

## 1. 요약

- 전체 통과는 **17·18·17건/25건(평균 69%)**이다. 기존 17건은 15~16건 통과다. 같은 사례를 테스트 모델(fake)로 돌린 17/17과 다르다. 동료 피드백에서 도출한 신규 8건은 매번 2건만 통과했다.
- 지표별로 부상 사실(AC4)과 교사 확정(AC5)은 100%, 입력에 없는 서술(AC1)은 67%, 표시·안내 3건(말투·시간 범위·Word)은 모두 실패했다.
- 7건(EV-01·22·23·24·26·27·28)은 3회 모두 실패했고, EV-07만 3회 중 1회 통과했다. 판정 결과는 대체로 안정적이고, 흔들린 것은 초안 전 확인 질문이다(6건에서 질문이 나왔다 안 나왔다 함).
- 비용과 지연은 작다. 실행 1회(78회 호출)에 약 0.06달러, 호출 1건은 종류별 중앙값 2~6초다. 동료 ⑦이 본 "몇 분"은 이 설정에서 재현되지 않았다(5절). 동료 ①~⑦은 `10팀 MVP 사용 피드백_1~7.pdf`의 번호다.
- 한계: AI 판정(`claude-opus-5-5`)은 사람 라벨과의 일치율을 아직 확인하지 않았다. 모델 설정은 로컬 `.env`의 값이며 배포 서버와 같은지 확인하지 못했다(6절).

개선 순서는 빈도순이다. ① 입력에 없는 서술(6건, AC1), ② 시간대 충돌·시간 범위·말투·Word·중복(각 3건), ③ 공동 사건(2건). AC1은 피드백에서도 ④가 ‘가장 먼저’로 꼽았으므로 맨 앞에 둔다.

### 재현율의 입력 의존성

관찰 없는 아동의 관찰일지에 개인 경험 문장이 생기는 문제는 입력에 따라 재현율이 달랐다. ⑦ 입력(EV-28)은 3/3 재현됐고, ④ 입력(EV-21)은 0/3이었다. 측정 전 탐색에서 ④ 입력은 2회 중 1회 재현됐다. 이 결함을 고쳤는지 판단하려면 두 입력을 모두, 여러 번 돌려야 한다.

### 재현되지 않은 것

- 11/19 배포 평가에서 3건이던 ‘이름·행동 귀속’ 실패와 규칙 md 예시 이름(‘다온이’)의 유출은 75회 실행에서 **0건**이었다. 자리표시자 이름(‘평가아동가’ 등)을 쓴 사례에서도 없었다. 배포 서버와 로컬의 모델·규칙·코드가 다르거나, 그 평가의 자리표시자 이름(‘가상아동다’)이 원인일 수 있다.
- 배포 평가의 ‘부상 표시’ 실패 2건도 로컬 live 3회에서는 재현되지 않았다(EV-11~14 통과 12/12).

## 5. 일관성·비용·지연

### 초안 전 확인 질문

- 75회 중 49회(65%)에서 질문이 1개 이상 나왔다. 평균 0.97개이고 분포는 0개 26회, 1개 32회, 2개 12회, 3개 3회, 4개 2회다. 사례 입력이 한 줄이라 ‘핵심 관찰 누락’ 질문이 자주 나온 영향이 크다. 현장 입력으로 일반화하지 않는다.
- 질문 유무가 3회 모두 같은 사례는 19/25다. 같은 입력인데 달라진 사례는 EV-01(0·1·1), EV-03(1·0·0), EV-04(0·1·1), EV-21(1·1·0), EV-22(0·1·0), EV-26(2·0·1)이다. 동료 ④⑦이 ‘질문이 안 나왔다’고 한 것과 같은 현상이다.

### 판정의 흔들림

- 사례 판정이 회차마다 달라진 것은 EV-07뿐이다(✕○✕). 코드 검사 세부로는 EV-23의 이모지(2/3)와 어말(2/3)이 흔들렸다.
- 지표 변동 폭 25%p(AC2)는 사례 하나(EV-07)의 차이다. 개선 여부는 사례 단위 1건 변동보다 크게 달라졌을 때만 판단한다.

**동료 ⑦의 ‘몇 분’과의 차이.** 이 설정에서는 교차 검토 호출이 중앙값 5초, 최대 18초다. ⑦은 ‘작성에 필요한 맥락을 확인하고 있어요’가 1분 넘게 이어졌다고 했다. 가설 두 가지를 세웠고 둘 다 검증하지 않았다.

1. 배포 서버의 모델·effort·리전이 로컬 `.env`와 다르다.
2. 작업자 스레드 풀이 모든 교사의 작업을 공유해 대기열이 생겼다. 풀은 4개이고([runner.py](../BE/app/jobs/runner.py)), 알림장 생성 작업 하나가 끝날 때까지 스레드 하나를 쓴다. 앱은 `prepare_journals`로 요청하므로 관찰일지 초안도 아이마다 작업 하나가 따로 들어간다. 대략 15명 반의 교사 한 명은 생성 30초와 관찰일지 90초(아이당 약 6초×15)의 작업자 시간을 쓴다. 이 값은 이번 측정 호출 지연으로 계산한 추정이다. 같은 시간대에 교사 7명이 쓰면 합계 840초를 스레드 4개가 나눠 약 3.5분 걸린다.

확인 방법: 배포 DB의 `jobs` 표에서 `started_at − created_at`(대기)과 `finished_at − started_at`(실행)을 11/16~18 사용분으로 집계한다.

## 6. 해석할 때 주의

1. **AI 판정은 잠정이다.** 사람 라벨이 없어 `judge_status`가 `unvalidated`다. 특히 판정이 엄격하거나 해석이 갈릴 수 있는 기준은 EV-01(‘모래를 모으고…’를 윤색으로 볼지), EV-07, EV-22, EV-27, EV-28이다. 11/19 배포 평가에서도 05·12번이 사람과 GPT 판정이 갈렸다.
2. **자리표시자 이름의 부작용.** EV-25를 뺀 사례는 ‘평가아동가·나·다’를 쓴다. 모델이 이름을 ‘평가’, ‘나’, ‘다’로 줄인 문장이 1회차에서 3개(EV-07, EV-10, EV-22) 있었다. 판정 기준은 아동 코드를 기준으로 하지만, ‘나는’처럼 대명사로 읽히는 문장은 판정에 노이즈가 될 수 있다.
3. **배포 서버와의 차이.** 모델·effort·커밋이 배포 서버와 같은지 확인하지 못했다. 11/19 배포 평가는 `model_revision`이 `null`이다.
4. **신규 사례의 기대 조건은 팀 승인 전 초안이다.** EV-22의 통과 조건, EV-23의 인사·이모지 반영, EV-26의 작성 교사·관찰 기간 채움은 동료 피드백을 기대 조건으로 옮긴 것이다. 제품이 그렇게 동작해야 하는지는 사람이 정한다.
5. **표본이 작다.** 사례 25건, 반복 3회다. 지표 분모는 AC2·AC3·AC4가 4, AC5가 2, 표시·안내가 3이다.
6. **측정하지 않은 것.** STT 이름 인식, 실기기·모바일 화면, 사용자 만족도, 작성 시간 단축, 이름이 자연스러운 실제 반 규모(15~20명)의 지연이다.

## 7. 사람이 확인할 일

1. **AI 판정 검증.** [사람 채점표](BASELINE_HUMAN_REVIEW.md)의 16개 기준에 A(충족)·B(미충족)·?(보류)를 붙인다. 아래 명령으로 일치율을 계산하고, 80% 이상이면 AI 판정을 합격 근거로 쓴다. 미만이면 판정 프롬프트를 고치고 기준선을 다시 잰다.
2. **신규 사례 EV-21~28의 기대 조건 승인.** 특히 EV-22·23·26.
3. **배포 서버의 모델·effort·커밋 확인.** 다르면 같은 조건으로 한 번 더 잰다.

```sh
# 저장소 루트, BE 가상 환경. 키는 셸 환경으로만 불러오고 출력하지 않는다.
set -a && . ./.env && set +a
PYTHONDONTWRITEBYTECODE=1 BE/.venv/bin/python evals/run_evals.py review evals/results/2026-11-21T043941Z-10dc00.json --template > evals/results/2026-11-21T043941Z-10dc00-human-labels.jsonl
# 파일의 labeler와 labels(true/false)를 채운 뒤
PYTHONDONTWRITEBYTECODE=1 BE/.venv/bin/python evals/run_evals.py judge evals/results/2026-11-21T043941Z-10dc00.json --judge-model claude-opus-5-5 --labels evals/results/2026-11-21T043941Z-10dc00-human-labels.jsonl
# 통과하면 2·3회차는 --calibration으로 같은 검증을 재사용한다.
```

기준선을 다시 측정할 때는 같은 데이터셋·판정 프롬프트·판정 모델을 쓰고, 측정 명령은 다음과 같다.

```sh
PYTHONDONTWRITEBYTECODE=1 BE/.venv/bin/python evals/run_evals.py run --mode live --change '<변경 내용>' --golden '<골든 확인 상태>'

```

## 8. 러너 변경 기록

기존 사례 17건의 정의는 바꾸지 않고 뒤에 8건을 더했다. 기존 17건의 fake 상태는 변경 전후가 같다(스모크로 대조). 제품 코드(BE·FE·규칙 md)는 바꾸지 않았다.

| 파일 | 변경 |
|---|---|
| [`patpat_adapter.py`](patpat_adapter.py) | 관찰일지(`prepare_journals`)·Word 출력 실행, 블록 장소·시간·영역(`meta`)·말투 예시(`writing_examples`)·가상 이름(`names`) 입력, 명단 밖 예시 이름·시계 시간 범위 검출, AI 호출 토큰·지연 기록(`usage`) |
