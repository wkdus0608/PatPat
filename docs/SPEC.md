# 제품 스펙 (SPEC)

## 1. 문제
어린이집 담임 교사는 여러 아동의 관찰을 아동별로 되찾아 정리할 시간이 없어, 기록을 미루거나 아이별 내용을 공통문으로 대신한다. (상세: PROBLEM.md)

## 2. 대상
4명 이상 아동을 맡아 알림장 또는 관찰일지를 직접 쓰는 어린이집 담임 교사. 원장·행정 담당자·보호자는 대상이 아니다.

## 3. 핵심 흐름
1. 교사가 관찰을 음성 또는 텍스트로 입력한다.
2. 로컬 AI가 음성을 전사하고 이름을 가명 코드(`C01` 등)로 바꾼다.
3. 외부 AI가 가명 텍스트를 아동별 관찰로 나누고, 관찰은 로컬에 쌓인다.
4. 교사가 고른 관찰로 외부 AI가 초안을 만든다.
5. 로컬에서 실명을 되돌린 뒤 교사가 검토·수정·확정한다.

| 구분 | 알림장 | 관찰일지 |
|---|---|---|
| 주기 | 사용하는 기관에서 매일 | 월 1~2회 이상 |
| 쓰는 관찰 | 당일 관찰 | 대상 기간에 쌓인 관찰 |
| 내용 | 그날의 활동·특이사항 | 아동의 말·행동·반응과 상황 |

주기는 팀의 업무 정의이며 제품이 강제하지 않는다. 제품은 기록을 발송하지 않는다.

## 4. 범위
- **포함**: 음성·텍스트 관찰 입력과 저장, 로컬 전사·가명 처리·실명 복원, 아동별 관찰 분류, 알림장·관찰일지 초안(공통/아이별 문장 분리, 문장별 근거, 근거 없는 아동 표시, 민감 관찰 분리), 교사 검토·확정, 임시저장
- **비포함**: 발송·외부 앱 연동, 사진·이미지 처리, 발달 진단, 다른 문서 유형, 실명 데이터의 외부 전송

### 개인정보 처리 (팀 결정)
- **로컬 AI**: 음성 전사, 이름→가명 코드 치환. 매핑은 로컬 DB에만 둔다. 구체 모델은 미정이며 외부 전사 API로 대체하지 않는다.
- **외부 AI**: 가명 텍스트만 받아 분류·초안을 만든다. 원본 음성·실명·매핑표는 보내지 않는다. 가명 처리에 실패하면 외부 호출을 멈추고 교사에게 확인을 요청한다.
- **로컬 복원**: 결과의 코드를 매핑대로 실명으로 바꾼다. 이름을 추측하거나 내용을 다시 생성하지 않는다.

## 5. 인터페이스
PatPat 내부 API이며 외부 AI로 그대로 전달하지 않는다.

- `POST /observations` — body: `{child_ids[], text | audio}` → `{observations: [{observation_id, child_ids[], activity, text}]}`
- `POST /drafts` — body: `{record_type, child_ids[], observation_ids[]}` → `{common_text, records: [{record_id, child_id, individual_sentences: [{text, observation_ids[]}], special_notes: [{text, sensitive}], missing_evidence, status}]}`
- `POST /records/{record_id}/confirm` — body: `{edited_text}` → `{status: "완료"}`
- `GET /health` — `{status: "ok"}` (예정)

규칙:
- `record_type`은 `알림장` 또는 `관찰일지`다.
- 초안은 `observation_ids`로 고른 관찰만 근거로 쓴다. 여러 날의 일을 한 날로 합치거나 날짜를 추측하지 않는다.
- 아동 식별자는 가명 코드이며, 실명 복원은 로컬 검토 화면에서만 한다.
- `confirm`은 `edited_text`를 외부 AI 재호출 없이 그대로 저장한다.
- 보호자에게 보내는 엔드포인트는 없다.

## 6. 수용 기준
두 기록 유형에 똑같이 적용한다. 판정 데이터는 `docs/golden_cases.yaml`이며, 실행 하니스와 제품 테스트는 아직 없다.

- **AC1 [상시]**: 아이별 문장마다 근거 관찰을 1개 이상 연결한다 — `observation_ids`가 비어 있는 아이별 문장은 없다.
- **AC2 [상시]**: 입력에 없는 아동의 행동·발화·감정·부상을 생성하지 않는다 — 골든 케이스의 `forbidden_facts`가 기록에 나오지 않는다.
- **AC3 [상시]**: 한 아동의 기록에 다른 아동의 관찰을 넣지 않는다 — C01 기록에 C02에게만 연결된 관찰이 나오지 않는다.
- **AC4 [예외]**: 어떤 아동의 관찰이 0건이면, 그 아동의 개별 문장을 만들지 않고 `missing_evidence: true`로 표시한다.
- **AC5 [이벤트]**: 여러 아동의 초안을 요청하면, 공통 활동 문장(`common_text`)과 아이별 문장을 분리한다 — 관찰이 다른 두 아동의 개별 문장이 같으면 실패.
- **AC6 [이벤트]**: 초안을 요청하면, 입력 관찰의 필수 사실(`required_facts`)을 해당 아동 기록에 모두 담는다.
- **AC7 [예외]**: 부상·다툼 관찰이 입력되면, `special_notes`에 `sensitive: true`로 분리하고 원래 사실(부위·상황·조치)을 바꾸지 않는다.
- **AC8 [상시]**: 교사가 확정(`confirm`)하기 전의 기록을 완료로 바꾸거나 보호자·외부 플랫폼에 발송하지 않는다.
- **AC9 [이벤트]**: `GET /health` 요청이 오면 200과 `{"status":"ok"}`를 반환한다.
- **AC10 [상시]**: 로컬 전사·가명 처리를 거친 텍스트만 외부 AI에 보낸다(텍스트 입력은 전사 생략). 원본 음성·실명·매핑표는 외부 요청에 없고, 가명 처리 실패 시 외부 호출은 0건이다. 실명 복원은 로컬 매핑과 일치하며 이름 외의 내용은 바꾸지 않는다. 음성 경로는 가상 음성 준비물로 따로 검증해야 한다.
