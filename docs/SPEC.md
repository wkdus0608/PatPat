# 제품 스펙 (SPEC)

## 1. 문제
하루에 여러 아동(4명 이상)의 알림장·일지를 쓰는 어린이집 담임 교사가, 흩어진 관찰 근거에서 아이별 행동을 되찾아 공통 활동과 구분해 쓰는 일을 보육 시간 안에 끝내지 못해, 기록을 퇴근 후로 미루거나 아이별 내용을 공통문·일괄작성·생략으로 대신한다. (상세: PROBLEM.md)

## 2. 타깃 사용자
- **대상**: 하루 단위로 4명 이상 아동의 알림장 또는 관찰일지를 직접 작성하는 어린이집 담임 보육교사
- **비대상**: 원장·행정 담당자, 보호자

## 3. 핵심 기능 (한 문장)
교사의 음성·텍스트 메모 → 로컬 AI로 전사·가명 처리 → 외부 AI API로 아동별 분류·근거 있는 알림장·일지 초안 생성 → 로컬에서 실명 복원 → 교사가 검토·확정 후 복사·저장.

## 4. 범위
- **포함**: 음성·텍스트 관찰 입력, 로컬 AI 전사·가명 처리, 로컬 DB의 실명↔가명 매핑·실명 복원, 관찰 구조화, 공통/아이별 문장 분리 초안, 문장별 근거 연결, 근거 없는 아동 "확인 필요" 표시, 민감 관찰 분리, 교사 검토·확정, 임시저장·이어쓰기
- **비포함**: 자동 발송, 외부 알림장 앱 연동, 사진 자동 분석, 발달 진단, 상담·발달 기록, 실명이 포함된 데이터의 외부 전송·외부 저장, 결제, 다국어

### 개인정보 처리 원칙 (팀 회의 결정)
- **로컬 AI:** 음성을 텍스트로 바꾸고, 음성·텍스트 속 이름을 가명 코드(`C01` 등)로 치환한다. 같은 아동의 코드는 로컬 DB 매핑으로 유지한다.
- **외부 AI API:** 가명 처리된 텍스트와 코드만 받아 아동별 분류 및 알림장·관찰일지 초안을 생성한다. 원본 음성·실명 메모·실명 매핑표는 전달하지 않는다. 가명 처리가 실패하거나 이름의 매핑을 확인할 수 없으면 외부 호출을 중단하고 교사 확인을 요청한다.
- **로컬 복원:** 생성 결과의 코드를 로컬 매핑에 따라 실명으로 되돌려 교사가 검토한다. 이름을 추측하거나 관찰 내용을 다시 생성하지 않는다. 실명 복원본과 교사 수정본도 외부 AI에 보내지 않는다.

로컬 AI 사용은 필수다. 구체적인 모델은 미정이며, 외부 전사 API로 대체하지 않는다.

## 5. 인터페이스
아래 경로는 PatPat 내부 인터페이스이며 외부 AI API로 요청을 그대로 전달하지 않는다. `POST /observations`의 음성·실명 입력은 먼저 로컬에서 처리한다. 구조화 관찰·초안의 아동 식별자는 가명 코드로 유지하고, 실명 복원은 로컬 검토 화면에서 적용한다. 교사의 `edited_text`는 외부 AI 재호출 없이 로컬에 그대로 저장한다.

- `POST /observations` — body: `{child_ids[], text | audio}` → `{observations: [{observation_id, child_ids[], activity, text}]}`
- `POST /drafts` — body: `{record_type, child_ids[], observation_ids[]}` → `{common_text, records: [{record_id, child_id, individual_sentences: [{text, observation_ids[]}], special_notes: [{text, sensitive}], missing_evidence, status}]}`
- `POST /records/{record_id}/confirm` — body: `{edited_text}` → `{status: "완료"}`
- `GET /health` — `{status: "ok"}` (예정)

> 외부 AI 처리와 구조화 데이터는 실명 대신 가명 코드(`child_id`, 예: `C01`)를 사용한다. 실명과 매핑은 로컬에만 둔다. 보호자에게 보내는 엔드포인트는 만들지 않는다.

## 6. 수용 기준 (테스트로 검증 — Definition of Done)
각 AC는 EARS 문형 "[조건]일 때, PatPat은 [동작]한다"로 쓰고, 조건 자리의 유형을 [ ]에 표시한다.

- **AC1 [상시 적용]**: PatPat은 항상 아이별 문장마다 근거 관찰을 1개 이상 연결한다 — `observation_ids`가 비어 있는 아이별 문장은 없다.
- **AC2 [상시 적용]**: PatPat은 항상 입력에 없는 아동의 행동·발화·감정·부상을 생성하지 않는다 — 골든 케이스의 금지 사실(`forbidden_facts`)이 기록에 나오지 않는다.
- **AC3 [상시 적용]**: PatPat은 항상 한 아동의 기록에 다른 아동의 관찰을 넣지 않는다 — C01 기록에 C02에게만 연결된 관찰이 나오지 않는다.
- **AC4 [예외 대응]**: 어떤 아동의 관찰이 0건이면, PatPat은 그 아동의 개별 문장을 만들지 않고 `missing_evidence: true`로 표시한다.
- **AC5 [이벤트 기반]**: 여러 아동의 초안을 요청하면, PatPat은 공통 활동 문장(`common_text`)과 아이별 문장을 분리해 응답한다 — 관찰이 다른 두 아동의 개별 문장이 같으면 실패.
- **AC6 [이벤트 기반]**: 초안을 요청하면, PatPat은 입력한 관찰의 필수 사실(`required_facts`)을 해당 아동 기록에 모두 담는다.
- **AC7 [예외 대응]**: 부상·다툼 관찰이 입력되면, PatPat은 이를 `special_notes`에 `sensitive: true`로 분리하고 원래 사실(부위·상황·조치)을 바꾸지 않는다.
- **AC8 [상시 적용]**: PatPat은 항상 교사가 확정(`confirm`)하기 전의 기록을 완료로 바꾸거나 보호자·외부 플랫폼에 발송하지 않는다. 가명 데이터의 외부 AI 처리는 AC10을 따른다.
- **AC9 [이벤트 기반]**: `GET /health` 요청이 오면, PatPat은 200과 `{"status":"ok"}`를 반환한다.

- **AC10 [상시 적용]**: PatPat은 항상 로컬 AI 전사·가명 처리를 거친 텍스트만 외부 AI에 전달한다(텍스트 입력은 전사 생략). 원본 음성·실명·매핑표는 외부 요청에 없고, 가명 처리 실패 시 외부 호출은 0건이다. 실명 복원은 로컬 매핑과 일치하며 이름 외의 내용은 바꾸지 않는다.

> AC1~AC10의 판정 데이터: `docs/golden_cases.yaml`. 실행 하니스와 제품 테스트는 아직 없다. AC10의 음성 전사 경로는 가상 음성 준비물과 실행 검증이 추가로 필요하다.
