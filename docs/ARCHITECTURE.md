# PatPat 아키텍처

현재 MVP는 알림장 작성과 연결된 관찰일지의 준비·조회·편집을 지원한다. 제품 범위는 [SPEC](SPEC.md), 도메인 관계는 [온톨로지](ontology.yaml), API 상세는 [백엔드 계약](../BE/docs/API_CONTRACT.md), 기존 판정 기준은 [골든 케이스](golden_cases.yaml)를 따른다.

## 1. 데이터 흐름

- 텍스트는 교사가 날짜와 반을 선택해 연 작성 세션에 반 공통·아동별 입력으로 저장한다.
- 녹음은 기기에 먼저 저장하고 서버에 자동 업로드한다. 교사가 작성 날짜에 해당하는 녹음을 선택하면 서버가 선택 원음만 전사하도록 요청하고, 성공한 전사문은 재사용한다.
- 서버는 입력을 검토해 필요한 추가 질문을 반환한다. 교사는 관찰영역과 추가 사실을 확인하고, 아이별 알림장 초안을 검토·수정한 뒤 확정한다.
- 연결 관찰일지 초안은 알림장 확정 전에 준비할 수 있다. 확정된 알림장에 연결된 관찰일지는 아동·관찰일별로 조회·편집하고 보관함에서 열 수 있다. 수정한 알림장을 다시 확정할 때 교사는 연결 관찰일지의 갱신 여부를 선택할 수 있다.

## 2. 구성 요소

| 구성 요소 | 책임 |
| --- | --- |
| `FE/src/recording/`, `FE/src/library/sync.ts` | Expo 앱의 녹음·기기 저장과 서버 동기화 |
| `FE/src/writing/`, `FE/src/library/`, `FE/src/api/v2.ts` | 알림장과 관찰일지 화면, 보관함, v2 API 연결 |
| `BE/app/api/v1/`, `BE/app/recordings/storage.py` | v1 인증·명단과 비공개 원음 업로드·재생·삭제 |
| `BE/app/container.py`, `BE/app/sessions/`, `BE/app/pipeline/` | v2 서비스 구성, 작성 세션·입력 저장, 전사 이후 검토·초안 처리 |
| `BE/app/notices/`, `BE/app/journal/` | 알림장 본문·버전·확정 관리, 연결 관찰일지 저장·조회·편집 |
| `BE/app/jobs/runner.py`, `BE/app/core/migrations.py` | SQLite 작업 실행과 데이터베이스 스키마 관리 |
| `BE/app/transcriptions/cache.py`, `BE/app/ai/` | 전사 결과 재사용, 외부 텍스트 AI 호출과 사용량 기록 |

FE는 React Native와 Expo를 사용한다. BE는 Python과 FastAPI를 사용하며 v1과 v2가 인증 토큰과 SQLite 데이터베이스를 공유한다. 원음은 서버의 비공개 파일 영역에 보관한다.

## 3. 도구와 실행 계약

| 외부 연결 | 실행 시점과 설정 |
| --- | --- |
| STT | 선택 원음의 성공한 전사 결과가 없을 때 서버가 `SpeechToTextClient`를 호출한다. 실제 공급자는 별도로 연결해야 한다. 가상 전사문은 데모에 사용할 수 있다. |
| 텍스트 AI | 서버가 전사문에서의 사실 추출, 추가 질문, 초안, 수정 제안, 관찰일지 작성에 필요한 호출을 구성한다. Anthropic 연동은 서버 키 설정이 필요하다. 테스트와 데모에는 대체 AI를 사용할 수 있다. |

서버가 처리 순서와 호출할 작업을 정한다. 텍스트 AI 응답은 서버에서 해석하고 저장한다. 알림장 본문 저장과 확정은 서로 다른 요청이며, 확정은 저장된 버전을 대상으로 한다. 확정 이후에는 조건에 따라 별도 관찰일지 작업이 시작된다.

## 4. RAG

MVP에서는 RAG를 사용하지 않는다. 필요한 근거가 교사가 선택한 녹음으로 정해져 있어 전체 선택 근거를 고정해 전달한다. 유사도 검색으로 일부만 선택하면 필수 사실이 누락될 수 있다. 문장별 출처는 `observation_ids`로 연결하며, 벡터 저장소와 `config/rag.yaml`은 만들지 않는다.

## 5. 오케스트레이션

- 날짜와 반을 기준으로 작성 세션을 열고 공통·아동별 입력을 저장한다. 녹음 경로는 선택 원음의 소유권과 작성일을 확인하고 전사한 뒤, 전사문에서 가져온 인용과 아동 연결을 검토한다.
- 서버는 작업별 진행 상태를 SQLite에 기록한다. 작업 실행은 `JobRunner`가 담당하며, 앱은 작업 상태와 저장된 결과를 조회한다.
- 교사가 추가 질문에 답하면 서버가 검토를 이어간다. 현재 앱은 교사가 관찰영역을 직접 확인하도록 요청하며 알림장 생성 시 연결 관찰일지 초안 준비를 함께 요청한다.
- 저장된 알림장을 녹음으로 다시 작성하는 경우 새 후보를 보관한다. 교사가 아동별 후보를 반영할 때 대상과 본문 버전을 확인한다. 관찰일지는 출처 알림장 버전을 기록하고, 날짜별 본문 편집에는 현재 개정 값을 사용한다.

## 6. 실패 처리

| 실패 | 대응 |
| --- | --- |
| 녹음 업로드 실패 | 기기 파일을 보존하고 자동 재시도 또는 보관함 새로고침으로 다시 전송한다. 같은 업로드에는 같은 멱등 키를 사용한다. |
| 전사 실패 | 실패한 녹음을 표시한다. 교사가 해당 녹음을 재시도하거나 명시적으로 제외할 수 있다. 공급자와 데모 전사문이 모두 없으면 `STT_NOT_CONFIGURED`를 반환한다. |
| 대상 아동이나 맥락이 불명확함 | 필요한 내용을 교사에게 확인한다. 확인되지 않은 인용을 특정 아동에게 추측해 배정하지 않는다. |
| 생성 실패 또는 버전 충돌 | 작업 상태나 오류를 앱에 표시한다. 오래된 알림장 버전과 관찰일지 개정 값으로 수정할 때는 최신 상태를 다시 확인한다. |
| 서버 재시작 | 저장된 상태를 기준으로 중단된 작업과 전사 상태를 복구 처리한다. |

## 7. 가드레일

- 사실 보존, 아동별 사실 분리, 부상·다툼의 사실 보존, 교사 확정은 [SPEC 6절](SPEC.md)과 [작업 규칙](../AGENTS.md)의 기준을 따른다. 초기 계약의 문장별 `observation_ids`, `missing_evidence`와 특이사항 출력 형식은 SPEC 5-3절에서 확인한다.
- 현재 v2의 생성 근거는 교사가 입력한 텍스트, 선택 녹음에서 확인한 내용, 추가 확인 답변이다. 교사 글쓰기 예시와 이전 알림장은 표현 참고 자료다. 녹음 경로는 전사문 인용을 확인하고, 일부 근거 없는 감정 표현과 교사 주도 표현은 서버가 경고한다. 구조 검사와 사실의 의미 판정은 구분한다.
- 교사 인증과 자료 소유권을 검사한다. 원음은 STT에만 전달한다. 텍스트 AI에는 작업에 따라 전사문·교사 입력·아동 정보가 전달될 수 있으며 API 키는 서버에서 관리한다.
- 교사가 저장된 알림장을 직접 확정한다. 현재 화면은 기록 텍스트를 복사할 수 있다. 보호자 자동 발송은 제품 범위 밖이다.

## 8. 관측

텍스트 AI 호출은 작업 종류, 모델, 성공·오류, 입력·출력 토큰, 캐시 토큰과 지연 시간을 기록한다. v2 사용량 API에서 호출 수와 오류 수 등의 집계를 조회할 수 있다. 실제 비용과 생성 문장의 의미 품질은 별도 검증 항목이다. 기존 골든 케이스의 기대 사실과 금지 사실은 유지한다.

## 9. 비범위

기기 내 전사·전체 가명 처리와 실명 복원, 보호자 자동 발송, 외부 알림장 앱 연동, 사진 정리·분류, 상담·발달 기록은 [SPEC 4절](SPEC.md)의 MVP 범위 밖이다.
