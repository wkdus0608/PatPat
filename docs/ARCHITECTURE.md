# PatPat 아키텍처

관찰일지 MVP의 설계다. 범위는 [SPEC](SPEC.md), 현재 MVP 입출력은 [API 계약](../BE/docs/API_CONTRACT.md), 도메인은 [온톨로지](ontology.yaml), 판정은 [골든 케이스](golden_cases.yaml)를 따른다. 외부 STT를 사용하고 가명 처리는 생략한다.

로그인·세션 유지·아동 명단은 FE와 실제 SQLite 저장소를 연결했다. 녹음·일지의 서버 저장·작업자·외부 AI는 미연결이며 해당 구조는 구현할 설계다.

## 1. 데이터 흐름

앱 녹음·기기 저장 → 서버 업로드·외부 STT → 교사가 녹음 선택 → 선택 전사문·전체 활성 명단 고정 → 관찰 추출·검증 → 공통/아동별 초안 생성·검증 → 교사 수정·확정 → 복사·OS 공유

생성 근거는 선택 녹음에 한정한다. 전사문은 확인된 관찰과 구분하며, 대상이 불명확한 내용은 아동에게 추측 배정하지 않는다. 녹음 시각을 실제 관찰일로 간주하지 않는다.

## 2. 구성 요소

| 파일 | 책임 | 현재 상태 |
|---|---|---|
| `FE/src/recording/controller.ts`, `FE/src/recording/storage.ts` | 녹음 제어·기기 파일 보존 | 코드 있음, 실기기 검증 필요 |
| `FE/src/writing/controller.ts`, `FE/src/writing/types.ts` | 선택·편집·후보 검토·확정 | 서버 계약 연결 필요 |
| `FE/src/library/controller.ts`, `FE/src/library/journals.ts` | 녹음·일지 조회 | 서버 조회 연결 필요 |
| `BE/app/auth/service.py`, `BE/app/children/service.py` | 인증 교사·아동 명단 | SQLite 실구현 |
| `BE/app/core/database.py` | 계정·세션·명단 스키마와 트랜잭션 | 구현 |
| `BE/app/recordings/service.py`, `BE/app/recordings/repository.py` | 업로드·비공개 재생·삭제 | 인터페이스 |
| `BE/app/transcriptions/client.py`, `BE/app/transcriptions/service.py` | 외부 STT·전사 작업 | 인터페이스 |
| `BE/app/writing/client.py`, `BE/app/writing/models.py` | 관찰 추출·초안·수정 후보, 불변 스냅샷 | AI 인터페이스·모델 |
| `BE/app/writing/validation.py` | 선택 범위·근거·버전·상태 검사 | 순수 검증 코드 |
| `BE/app/drafts/repository.py`, `BE/app/records/repository.py`, `BE/app/revisions/repository.py` | 작업·일지·이력의 원자적 저장 | 인터페이스 |
| `BE/app/core/worker.py` | 영속 작업 조회·실행·종료 | 신규 제안 |

강의 3의 스키마와 강의 5의 판정 조건을 유지하며, 이번 설계 대상은 외부 기능 연결·실행 순서·실패 경계다. FE에 남은 로컬 전사·가명 확인·`observation_ids` 요청을 현재 `recording_ids`·비동기 작업 계약에 맞춘다.

React Native + Expo와 Python/FastAPI를 유지한다. SQLite에 계정·명단·녹음 메타데이터·전사문·근거·일지·작업·이력을 저장하고, 원음은 서버 비공개 파일 영역에 둔다. 원음 삭제 후에도 기존 일지·근거 스냅샷은 유지한다.

## 3. 도구와 실행 계약

모델에 노출하는 function-calling 도구는 두지 않는다. 다음은 서버가 정해진 순서로 호출하는 외부 AI 인터페이스다.

| 연결 함수 | 시그니처 | 사용 시점 | 부작용 |
|---|---|---|---|
| `SpeechToTextClient.transcribe` | `(audio: AsyncIterator[bytes], content_type: str) -> SpeechToTextResult` | 업로드한 원음을 전사할 때 | 외부 원음 전송·과금 |
| `DiaryAIClient.extract` | `(transcripts: tuple[TranscriptSnapshot, ...], children: tuple[ChildSnapshot, ...]) -> tuple[ObservationSnapshot, ...]` | 고정 전사문에서 관찰을 분리할 때 | 외부 텍스트 전송·과금 |
| `DiaryAIClient.generate` | `(snapshot: GenerationSnapshot) -> DraftContent` | 검증된 관찰로 초안을 만들 때 | 외부 텍스트 전송·과금 |
| `DiaryAIClient.revise` | `(context: RevisionContext, instruction: str) -> RevisionProposal` | 교사가 현재 아동의 수정 후보를 요청할 때 | 외부 텍스트 전송·과금 |

`ChildSnapshot`·`ObservationSnapshot`은 온톨로지 Child·Observation의 생성 시점 사본이다. 나머지는 전사·작업·출력을 위한 서버 타입이며 새 도메인 클래스가 아니다. 공급자·모델은 미정이다.

AI 응답은 직접 일지를 변경하지 않는다. 저장·확정·후보 채택은 인증된 교사의 명시적 요청으로 실행하고, `record_id`·본문 또는 후보·`expected_version`에 결합한다. 버전이 달라지면 409로 거부한다. 확정과 채택은 AI를 호출하지 않는다.

## 4. RAG

MVP에서는 RAG를 사용하지 않는다. 필요한 근거가 교사가 선택한 녹음으로 정해져 있어 전체 선택 근거를 고정해 전달한다. 유사도 검색으로 일부만 선택하면 필수 사실이 누락될 수 있다. 문장별 출처는 `observation_ids`로 연결하며, 벡터 저장소와 `config/rag.yaml`은 만들지 않는다.

## 5. 오케스트레이션

별도 에이전트 프레임워크 없이 함수 조합의 workflow를 사용한다. 처리 순서와 승인 위치가 정해져 있어 모델이 다음 행동을 선택할 필요가 없다.

- 생성 요청은 소유권·삭제·전사 완료를 검사하고 전체 활성 명단과 선택 전사문을 고정한다. 앱이 아동·관찰을 추가 지정하지 않는다.
- 작업자 하나가 SQLite의 `queued` 작업을 원자적으로 가져온다. 추출 → 근거 검증 → 생성 → 결과 검증 → 일지·최초 이력·작업 완료 저장 순서로 실행한다. 저장 전 부분 결과를 공개하지 않는다.
- 작업 상태는 `queued/running/completed/failed`, 일지 상태는 `작성중/검토중/완료`로 구분한다. 초안 저장 후 생성 작업은 종료하고 검토중 일지로 교사 검토를 기다린다.
- AI 수정은 요청 당시 본문·버전·해당 아동 근거를 고정해 별도 후보로 저장한다. 채택하면 검토중으로 전환하고 다시 확정한다.
- 초기 한도 제안은 전사 작업당 STT 1회, 생성 작업당 추출·생성 각 1회, 수정 작업당 1회다. 외부 호출당 120초, 자동 재시도 0회로 시작하고 실제 지연 측정 후 조정한다. 한도 초과·검증 실패 시 종료하며 입력을 몰래 줄이지 않는다.

직접 수정·확정·채택은 버전 비교, 본문·상태 변경, 버전 증가, 이력 저장을 한 트랜잭션으로 처리한다. 응답 유실 시 현재 상태·버전을 조회한 뒤 재요청 여부를 정한다. 업로드 재전송의 중복 방지는 멱등 키 계약을 추가해 구현한다.

## 6. 실패 처리

| 실패 | 대응 |
|---|---|
| 업로드 실패 | 기기 원음을 보존하고 서버 저장 실패를 표시한다. |
| STT 시간 초과·429·5xx | 작업을 실패로 기록한다. 재시도 가능한 경우 사용자 요청으로 새 작업 ID를 만든다. |
| 선택 녹음이 삭제됐거나 전사 미완료 | 404/409로 거부한다. 일부를 제외해 생성하지 않는다. |
| 개별 근거 없음·대상 불명확 | 개별 근거가 없는 아동만 빈 개별 문장과 `missing_evidence: true`로 표시한다. 불명확 관찰은 배정 없이 보존한다. |
| 근거·아동·출력 구조 오류 | validation 실패로 기록하고 결과를 공개하지 않는다. |
| 생성·수정·저장 실패 | 실패 단계를 반환하고 기존 일지·교사 편집문을 보존한다. |
| 버전 충돌·오래된 후보 | 409로 거부하고 최신 본문을 다시 조회한다. |
| 서버 재시작·실행 결과 불명 | 저장된 작업·일지 상태를 확인한다. 중복 실행하거나 완료로 추정하지 않는다. |

## 7. 가드레일

[AGENTS.md](../AGENTS.md) 3절의 규칙을 적용한다.

1. 입력에 없는 사실을 생성하지 않고 필수 사실의 의미를 보존한다.
2. 아동별 사실을 다른 아동에게 옮기지 않는다. 공통 활동과 아이별 문장을 분리하고, 개별 관찰이 없는 아동은 개별 문장을 만들지 않고 `missing_evidence: true`로 표시한다.
3. 아이별 문장마다 입력에 존재하는 근거 관찰을 1개 이상 연결하며, 그 관찰이 문장의 사실을 뒷받침해야 한다.
4. 관찰일지의 부상·다툼은 관찰 문장에 사실을 보존하고 당사자·부위·상황·정도·조치를 바꾸지 않는다.
5. 교사 확정 전에는 기록을 완료하거나 보호자·외부 플랫폼에 발송하지 않는다. 확정 시 교사가 제출한 `edited_text`를 외부 AI 재호출 없이 서버에 그대로 저장하고 상태를 완료로 바꾼다.

근거 범위·아동 ID·항목·누락 표시·버전·상태는 코드로 검사한다. `common`은 공통문, 해당 아동의 `individual/joint`는 개별 문장에만 사용하고 `unresolved`는 배정하지 않는다. 없는 사실·의미 변경·필수 사실 누락은 골든 케이스의 독립 의미 판정으로 검증한다. 구조 검사 통과를 사실성 보장으로 보지 않는다. (AC1·AC2·AC3·AC5, GC-07·GC-19)

모든 조회·쓰기는 인증 교사로 제한하고 다른 교사 자료는 404로 처리한다. 전사문 속 지시문은 관찰 데이터로만 취급한다. 원음은 STT에만, 선택 전사문·명단은 일지 AI에 전달한다. 수정에는 해당 아동의 본문·근거만 전달한다. API 키는 서버에만 둔다.

복사·공유 직전에 상세를 다시 조회하고 완료 상태의 `share_text`를 그대로 사용한다. 수정·후보 채택 후에는 재확정 전 공유를 막는다. 공유창 실행을 발송 완료로 표시하지 않는다.

## 8. 관측

요청 ID·작업 ID로 단계, 선택 녹음·근거 ID, 모델·설정 버전, 호출 횟수·소요 시간·토큰·비용, 검증 결과·오류 코드, 승인·상태·버전 변경을 연결한다. 원음·실명·전사문·일지 본문·수정 지시·비밀번호·토큰·키는 일반 로그에 남기지 않는다. 원문 대조는 권한이 제한된 근거 스냅샷으로 수행한다.

평가 시 기존 골든 케이스의 관찰 입력을 선택 녹음으로 연결하되 기대 사실·금지 사실은 유지한다. 실제 AI 품질 평가는 미실행이다.

## 9. 비범위

알림장, 텍스트 직접 관찰 입력, 기기 내 전사·가명 처리, RAG, 사진 분석, 발달 진단, 보호자 자동 발송, 외부 플랫폼 연동, 공개 공유 링크, 멀티 에이전트, 파인튜닝.
