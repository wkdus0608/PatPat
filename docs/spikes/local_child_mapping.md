# 스파이크 — 로컬 아동 매핑 정확성

가설 ID: SP-02 / 상태: 실험 계획, 미실행 / 수정일: 2026-09-30
연결: [SPEC](../SPEC.md) 4절·AC3·AC10, [온톨로지](../ontology.yaml) Child·Observation

팀의 개인정보 회의 결정과 사용자 지시를 근거로 작성했다. 아래 시간·합격선은 실행 전에 팀이 확정할 초안이며, 측정 결과가 아니다.

## 1. 가장 위험한 가정

**로컬 AI 전사·가명 처리에서 이름이 헷갈려도 다른 아동의 코드로 바꾸지 않고, 구분할 근거가 없으면 교사 확인을 요청할 수 있다.**

- 실패 영향: 이름이 잘못 치환되면 이후 분류·기록·실명 복원까지 다른 아이의 사실이 된다. 외부 모델의 분류가 정확해도 바로잡을 수 없다.
- 근거 부족: 로컬 모델·음성·매핑 구현이 없으며, 비슷한 이름과 동명이인을 처리한 결과도 없다.
- 대체 비용: 교사가 입력마다 아동을 직접 선택·확인해야 하므로 추가 작업이 생긴다.
- 우선 선정 이유: 기존 SP-01은 이미 가명 처리된 텍스트의 분류다. 이번에는 그 앞 단계의 잘못된 이름 치환을 분리해 검증한다.

대상은 로컬 전사 → 이름 인식 → 로컬 DB 코드 치환 → 로컬 실명 복원이다. 외부 AI 분류·초안 생성은 실행하지 않는다.

## 2. 시간 제한

가상 음성 준비·정답 작성·실행·채점을 포함해 최대 6시간이다. 외부 API 호출과 비용은 0으로 제한한다.

6시간 경과 또는 평가 30건의 3회 실행·채점 완료 중 먼저 오는 시점에 멈춘다. 준비물 부족이나 미완료는 판단 보류로 기록한다.

## 3. 성공 조건 (실험 전에 확정)

**30건 중 27건 이상(90%) 통과하고, 다른 아동으로의 매핑·복원은 0건이어야 한다.**

- 평가 단위: 메모 1건과 입력 방식·가상 이름·로컬 매핑의 묶음. 명확한 이름, 비슷한 이름, 동명이인, 불명확한 발음, 여러 아동 메모를 각 6건씩 만든다.
- 입력 구성: 명확한 이름·비슷한 이름·동명이인·여러 아동 그룹은 텍스트 3건과 가상 음성 3건씩, 불명확한 발음 그룹은 가상 음성 6건이다. 준비용 5건과 평가용 30건을 분리한다.
- 건별 판정: 식별 가능한 입력은 모든 이름·코드·복원 이름이 정답과 같고 이름 외의 사실도 보존돼야 한다. 주체가 모호한 입력은 임의 치환 없이 외부 호출을 차단하고 교사 확인을 요청해야 한다.
- 반복: 각 메모를 같은 초기 매핑에서 3회 실행한다. 3회 모두 기준을 만족해야 메모 1건을 통과로 센다.
- 치명 오류: 한 번이라도 다른 아동 코드로 치환하거나 다른 이름으로 복원하면 채택하지 않는다. 동명이인은 이름만으로 선택하지 않는다.
- 집계: 전사·실행 오류는 해당 건의 실패다. 30건을 끝내지 못하면 완료 건만으로 합격을 선언하지 않는다.

코드 비교는 자동 검사하고, 음성의 실제 발화·주체·관찰 의미는 사람이 대조한다. 전사 오탈자만으로 아동 연결의 정확성을 판단하지 않는다.

## 4. 방법

1. **정답 만들기:** 팀원 2명이 가상 메모·음성과 로컬 매핑을 보고 각각 이름·정답 코드·확인 필요 여부를 기록한다. 답이 다른 건은 함께 확인해 합의하고 사람 간 불일치 건수를 남긴다.
2. **로컬 출력 만들기:** 준비용 5건으로 연결을 확인한다. 로컬 모델·버전·프롬프트·전사 설정을 고정한 뒤 평가 30건을 각각 3회 처리하고 전사문·치환문·복원문을 저장한다. 평가 정답은 모델에 주지 않는다.
3. **대조와 기록:** 원음·원문에서 최초로 주체가 바뀐 단계와 실제 출력 예를 기록한다. 외부 호출 경로는 수집용 대역으로 교체해 차단 여부만 확인하고 실제 네트워크 호출은 하지 않는다.

| 실행 준비 | 현재 상태 |
|---|---|
| 로컬 모델·버전·설정·실행 환경 | 미선정 |
| 가상 데이터·음성·매핑·파일 버전 | 미준비 |
| 독립 라벨·합의 정답 | 미작성 |
| 팀의 기준 확정·실행 코드·명령 | 미확정·미실행 |

## 5. 결과

| 항목 | 결과 |
|---|---|
| 평가 완료·통과 건수 | 미측정 / 목표 30건, 기준 27건 이상 |
| 잘못된 아동 매핑·복원 건수 | 미측정 / 기준 0건 |
| 확인 필요 요청·사람 간 라벨 불일치 | 미측정 |
| 소요 시간·외부 호출 건수 | 미측정 / 상한 6시간, 외부 호출 0건 |
| 실제 전사·치환·복원 출력과 채점 파일 | 미생성 |
| 실험 판정 | 미실행 |

오류는 전사로 인한 이름 변경, 잘못된 코드 선택, 모호한 주체 추측, 복원 오류, 과도한 확인 요청, 실행 오류로 구분한다. 사람 간 라벨 불일치와 모델 오류는 별도로 센다.

## 6. 판단과 재도전 조건

현재 판단: **보류 — 모델·데이터·실제 출력이 없다.** 문서 작성만으로 로컬 매핑의 정확성을 확인한 것은 아니다.

- **기준 충족:** 평가한 이름·입력 조건에서 로컬 매핑 방식을 채택할 근거로 삼고 SPEC 4절·AC10에 실험 근거를 연결한다.
- **기준 미달·치명 오류:** 해당 조건의 자동 치환을 채택하지 않는다. 교사 확인이 필요한 범위와 매핑 절차를 정리해 SPEC과 관련 골든 케이스에 반영한다.
- **미완료:** 준비 부족과 완료 건수를 기록하고 보류한다. 개념이 바뀌지 않으면 온톨로지에 속성을 추가하지 않는다.

재도전은 실패한 이름·발음·주체 조건의 처리 방식을 보완한 뒤 새로운 평가 데이터로 진행한다. 바꾼 조건과 회차는 이 절 아래에 남긴다.
