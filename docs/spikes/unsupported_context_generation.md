# 스파이크 — 없는 사실과 빈 맥락의 생성 방지

가설 ID: SP-03 / 상태: 실험 계획, 미실행 / 수정일: 2026-09-30
연결: [SPEC](../SPEC.md) AC1·AC2·AC4·AC6·AC7, [온톨로지](../ontology.yaml) Observation·ChildcareRecord

사용자가 지적한 사실 생성·맥락 보완 위험과 조사 로그 2·3·5·9를 근거로 작성했다. 시간·합격선은 실행 전에 확정할 초안이며, 결과는 아직 없다.

## 1. 가장 위험한 가정

**알림장·관찰일지 생성 AI가 입력의 빈 맥락을 추측해 채우지 않고, 확인된 사실만 근거와 연결해 작성할 수 있다.**

- 실패 영향: 없던 말·감정·부상 원인·교사 조치가 기록되면 실제와 다른 상황이 보호자에게 전달된다. 자연스러운 문장이라 교사가 놓칠 수도 있다.
- 근거 부족: 현재 골든 케이스는 판정 데이터다. 실제 생성 모델의 반복 출력에서 빈 맥락이 유지되는지는 확인하지 않았다.
- 대체 비용: 교사가 생성 문장마다 원문을 다시 확인하거나 근거 문장을 직접 조합해야 한다.
- 우선 선정 이유: SP-01의 아동별 분류가 맞아도 생성 단계에서 새 사실이 붙을 수 있다. 분류 정확도와 구분해 검증한다.

입력은 로컬에서 가명 처리된 관찰이다. SPEC의 `common_text`, `individual_sentences`, `special_notes`, `missing_evidence`와 근거 연결을 검사한다. 입력 관찰 자체의 진위는 이번 실험 범위가 아니다.

## 2. 시간 제한

준비·정답 작성·모델 실행·의미 판정을 포함해 최대 6시간, 외부 API 예산 최대 10,000원이다.

6시간 경과, 예산 도달, 평가 30건의 3회 실행·채점 완료 중 먼저 오는 시점에 멈춘다. 미완료는 판단 보류로 기록한다.

## 3. 성공 조건 (실험 전에 확정)

**30건 중 27건 이상(90%) 통과하고, 근거 없는 사실·맥락의 추가는 0건이어야 한다.**

- 평가 단위: 초안 요청 1건. 관찰 없음, 공통 활동만 있음, 주체 불명확, 짧은 관찰, 부상·다툼, 부정·정정 표현을 각 5건씩 구성한다. 알림장·관찰일지는 각각 15건이다. 알림장은 대상일 관찰, 관찰일지는 여러 날짜의 누적 관찰을 사용하며, 기간 밖 저장 관찰과 안부 문구로 사실을 채우는 오류도 검사한다.
- 데이터 분리: 준비용 5건과 평가용 30건을 따로 만든다. 가명 코드·가상 관찰만 사용하고 골든 케이스를 평가 데이터로 그대로 복제하지 않는다.
- 건별 판정: 필수 사실이 모두 보존되고 모든 사실 주장이 입력으로 뒷받침돼야 한다. 개별 근거가 없으면 개별 문장 없이 `missing_evidence: true`여야 한다. 부상·다툼은 민감 항목으로 분리한다.
- 근거 판정: 아이별 문장의 `observation_ids`가 존재하고 실제로 그 주장을 뒷받침해야 한다. 번호만 붙인 문장은 통과시키지 않는다. 공통 문장·특이사항의 주장도 입력과 대조한다.
- 반복: 요청마다 같은 입력으로 3회 실행한다. 3회 모두 통과해야 해당 요청을 통과로 센다. 뜻을 보존한 표현 차이는 허용한다.
- 치명 오류: 없는 행동·말·감정·원인·상황·조치를 한 번이라도 덧붙이면 채택하지 않는다. 다른 아동의 사실이나 입력과 반대되는 주장도 치명 오류다.
- 집계: 호출·형식 오류와 필수 사실 누락은 실패로 센다. 30건 미완료는 보류이며, 금지 사실 목록에 없다는 이유로 새 사실을 허용하지 않는다.

예: “C01이 넘어짐”만 있으면 넘어짐만 기록한다. 장소·원인·울음·다친 부위·처치는 생성하지 않는다. 주체가 불명확한 사실을 특정 아동에게 붙이지 않는다.

## 4. 방법

1. **정답 만들기:** 팀원 2명이 각각 입력의 필수 사실·근거·비어 있어야 할 내용을 정리한다. 불일치한 건은 원문으로 합의하고 사람 간 라벨 불일치를 기록한다.
2. **모델 출력 만들기:** 외부 모델 1개로 준비용 5건을 확인한다. 모델·버전·프롬프트·설정을 고정하고 평가 요청마다 3회 생성한다. 평가 중 정답 제공·프롬프트 수정은 하지 않는다.
3. **대조와 기록:** 필드·근거 번호는 자동 검사하고 팀원 2명이 문장의 사실과 입력을 대조한다. 90개 출력 중 하나라도 치명 오류가 있으면 전체 채택 조건을 미충족으로 판정한다.

| 실행 준비 | 현재 상태 |
|---|---|
| 외부 모델·버전·프롬프트·설정·실행 환경 | 미선정 |
| 준비·평가 데이터와 파일 버전 | 미준비 |
| 독립 라벨·합의 정답 | 미작성 |
| 팀의 기준 확정·실행 코드·명령 | 미확정·미실행 |

## 5. 결과

| 항목 | 결과 |
|---|---|
| 평가 완료·통과 건수 | 미측정 / 목표 30건, 기준 27건 이상 |
| 근거 없는 사실·맥락 추가 건수 | 미측정 / 기준 0건 |
| 필수 사실 누락·근거 불일치 건수 | 미측정 |
| 사람 간 라벨 불일치 | 미측정 |
| 소요 시간·API 비용 | 미측정 / 상한 6시간·10,000원 |
| 실제 출력·합의 정답·채점 파일 | 미생성 |
| 실험 판정 | 미실행 |

오류는 행동·발화·감정 추가, 원인·조치 추측, 주체 추측, 근거 불일치, 사실 누락, 민감 항목 분리 실패, 호출·형식 오류로 구분한다. 오류 예에는 원문과 실제 생성문을 함께 남긴다.

## 6. 판단과 재도전 조건

현재 판단: **보류 — 평가 데이터·정답·모델 출력이 없다.** 이번 기준은 실험의 채택 판단용이며 실제 현장의 오류가 0임을 보장하지 않는다.

- **기준 충족:** 평가한 입력 조건에서 근거 기반 생성 방식의 채택 근거를 남기고 SPEC의 관련 AC에 연결한다.
- **기준 미달·치명 오류:** 해당 생성 방식을 채택하지 않는다. 추가된 사실의 유형과 근거 검증 방식을 보완하고 SPEC·골든 케이스에 필요한 변경을 기록한다.
- **미완료:** 완료 건수와 준비 부족을 적고 보류한다. 관찰·기록 개념이 바뀌는 경우에만 온톨로지를 수정한다.

재도전은 오류 유형을 보완할 입력·생성·검증 조건을 정한 뒤 새 평가 데이터로 진행한다. 합격선을 사후에 낮추지 않고 회차는 이 절 아래에 남긴다.
