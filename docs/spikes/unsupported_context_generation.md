# 확인된 관찰을 사실 그대로 알림장 문장으로 바꿀 수 있는가

연결: SPEC AC1·AC2·AC3 및 AC4의 사실 보존 / Child·Observation·DailyNote
조사 근거: 로그 9·관찰 3의 공통 내용에 아이별 한 문장을 추가하고 확인되지 않는 행동은 제외하는 작성 방식

## 1. 검증할 기술 가정

사람이 아동과 사실을 확인한 짧은 관찰을 입력하면, 생성 모델이 맥락을 추측하지 않고 필수 사실을 보존하는 알림장 문장으로 바꿀 수 있다.

“C01이 넘어짐”만 있으면 장소·원인·울음·부위·교사 조치를 추가하지 않아야 한다. 이 가정이 실패하면 교사가 원문과 생성문을 일일이 대조해야 하므로 생성 방식의 채택을 재검토한다.

후보 생성기만 검사한다. 음성 전사·이름 인식·관찰 구조화·공통 활동 분리·관찰일지 항목·저장·확정·외부 전달 경계는 이 실험의 범위 밖이며 별도 검증이 필요하다.

## 2. 입력과 출력

- 입력: 가상 아동 코드와 관찰 ID가 있는 확인된 관찰. 아동 연결과 유효 사실은 사람이 미리 확정하며, `scope: individual` 관찰만 사용한다.
- 출력: 아동별 후보 문장과 문장을 뒷받침하는 관찰 ID. 실험용 형식은 `{sentences: [{child_id, text, observation_ids}]}`로 고정한다.
- 이 형식은 제품의 `/drafts` 응답이 아니다. 부상 문장은 향후 `special_notes`에 사용할 내용 후보로 검사한다. 특이사항 분리·제품 필드·근거 부족 처리는 골든 케이스로 검사하며 제품 API에 필드를 추가하지 않는다.
- 문장은 필수 사실을 모두 담되 간결하게 쓴다. 문장 수나 원문과의 문자열 일치를 합격 조건으로 삼지 않는다.

## 3. 제한과 평가 데이터

- 준비·실행·채점 : 최대 6시간
- 외부 API 비용 : 최대 10,000원
- 실행 전에 팀이 상한·데이터·판정 기준을 확정하고, 상한에 도달하면 중단해 미완료로 기록

준비용 3건과 별도 평가용 12건을 만든다. 평가용은 다음 네 유형을 각 3건씩 구성한다.

| 유형 | 확인할 실패 |
|---|---|
| 행동만 있고 감정은 없는 관찰 | 즐거움·뿌듯함·웃음 등 관찰하지 않은 반응을 추가함 |
| 일부 정보만 있는 부상 관찰 | 없는 장소·원인·부위·조치 등을 채움 |
| 부정·정정 표현이 있는 관찰 | 부정을 뒤집거나 폐기된 주장을 다시 넣음 |
| 여러 아동에게 서로 다른 사실이 있는 관찰 | 다른 아동의 사실을 옮기거나 개별 차이를 지움 |

같은 조건으로 입력마다 3회 생성해 총 36개 생성 응답을 검사한다.
한 응답에 여러 아동의 문장이 있어도 생성 응답 1개로 센다.

## 4. 방법과 채택 기준

팀원이 필수 사실·금지 사실·근거 ID를 작성하고, 차이는 입력과 대조해 평가 전에 합의한다.

- 입력된 필수 사실을 빠짐없이 보존해야 한다. (단, 의미가 같다면 표현이나 어휘의 차이는 허용한다.)
- 입력에 없는 사실, 다른 아동의 사실, 입력과 반대되는 내용, 정정으로 폐기된 주장이 포함되지 않아야 한다.
- 문장에 연결된 관찰 ID가 실제로 해당 아동과 문장의 사실을 뒷받침해야 한다. (존재하는 ID를 형식적으로 매핑한 것은 불합격 처리한다.)
- 서로 다른 행동을 한 아동은 각자의 행동이 문장에 정확히 반영되어야 하며, 같은 내용을 어휘만 바꾸어 개별화한 것은 인정하지 않는다.

## 5. 결과와 후속 결정

- 데이터·모델·실행 도구: 미준비
- 완료·통과 응답 수, 사실 추가·변경·누락·아동 혼입: 미측정
- 사람 간 판정 불일치·실제 출력·시간·비용: 미측정
- 현재 판정: 미실행 · 채택 보류

기준을 충족하면 평가한 조건에서 후보 생성 방식을 채택할 근거로 삼는다. 전체 AC 충족·현장 오류 0건·작성 시간 단축의 증거로 확대하지 않는다.

기준에 미달하면 자유 생성 방식의 채택을 보류하고, 확인된 관찰의 표현을 제한적으로 바꾸거나 조립한 뒤 교사가 수정하는 방식으로 SPEC의 생성 계약을 조정한다. 재도전은 오류 원인을 줄이는 변경 후 별도 평가 데이터로 진행하고 변경 이유를 기록한다.
