# 스파이크 — 외부 AI 전달 데이터 경계

가설 ID: SP-04 / 상태: 실험 계획, 미실행 / 수정일: 2026-09-30
연결: [SPEC](../SPEC.md) 4절·AC10, [골든 케이스](../golden_cases.yaml) GC-15·GC-16

팀의 개인정보 회의 결정과 사용자 지시를 근거로 작성했다. 아래 기준은 실행 전 확정할 초안이며, 실제 요청 수집이나 유출 여부 검증은 아직 하지 않았다.

## 1. 가장 위험한 가정

**정상·실패·복원·교사 수정 경로 모두에서 외부 AI 요청을 가명 텍스트로 제한하고, 가명 처리가 불완전하면 호출을 막을 수 있다.**

- 실패 영향: 초안이 정확해도 원본 음성·실명·매핑표가 전달되면 로컬 AI를 사용하는 개인정보 처리 목적이 무너진다.
- 근거 부족: 현재 SPEC과 골든 케이스에 원칙만 있고, 실제 전송 직전 요청을 수집한 결과는 없다.
- 대체 비용: 모든 내용을 로컬에서 생성하거나 교사가 직접 가명 처리해야 하므로 모델 운영·입력 작업 부담이 늘어난다.
- 우선 선정 이유: SP-02는 아동 연결의 정확성이다. 정확한 매핑 결과를 얻어도 다른 호출 경로에서 원본이 전달될 수 있어 따로 검사한다.

대상은 외부 AI 전송 직전의 요청 경계다. 실제 외부 서비스는 수집용 대역으로 교체하고 원본을 외부로 전송하지 않는다. 이름 인식의 품질 전체는 SP-02에서 검증한다.

## 2. 시간 제한

데이터·정답·수집 대역 준비와 검사·기록을 포함해 최대 6시간이다. 실제 외부 API 호출과 비용은 0으로 제한한다.

6시간 경과 또는 30건의 경로 검사 완료 중 먼저 오는 시점에 멈춘다. 준비물 부족이나 미완료는 판단 보류다.

## 3. 성공 조건 (실험 전에 확정)

**30건 중 27건 이상(90%)이 기대 경로와 일치하고, 금지 데이터가 포함된 외부 요청 시도는 0건이어야 한다.**

- 평가 단위: 입력부터 종료까지의 경로 1건. 정상 가명 텍스트, 정상 가상 음성, 이름 일부만 치환됨, 가명 처리 실패, 실명 복원본, 교사 수정본을 각 5건씩 구성한다.
- 데이터 분리: 준비용 5건과 평가용 30건을 분리한다. 가상 이름·음성·매핑만 사용하며, 금지 데이터의 정답 목록은 검사용으로만 둔다.
- 정상 경로: 음성은 로컬 전사를 거치고 가명 처리된 텍스트로 분류·초안 생성 요청이 수집돼야 한다. 원본 음성·실명·매핑표는 어떤 요청에도 없어야 한다.
- 실패 경로: 이름이 남거나 가명 처리에 실패하면 외부 요청은 0건이고 교사 확인이 필요해야 한다. 실명 복원·교사 수정·확정 경로도 외부 AI 재호출이 0건이어야 한다.
- 건별 판정: 정상 경로는 기대 요청이 실제로 수집돼야 통과한다. 모든 요청을 막기만 한 구현은 정상 경로 실패다. 같은 건의 재시도·오류 처리 요청도 빠짐없이 검사한다.
- 치명 오류: 금지 데이터가 외부 전송용 요청에 한 번이라도 포함되면 채택하지 않는다. 실명 복원본·수정본의 외부 AI 재호출도 치명 오류다.
- 집계: 검사 누락·수집 실패는 해당 건 실패다. 30건을 끝내지 못하면 완료 건만으로 합격을 선언하지 않는다.

요청 본문뿐 아니라 헤더·URL·첨부도 검사한다. 이름의 이스케이프·인코딩을 해제한 값, 원본 음성 바이트·첨부 참조, 매핑 구조를 대조해 단순 문자열 검사의 누락을 줄인다.

## 4. 방법

1. **정답 만들기:** 팀원 2명이 각 사례의 허용 데이터·금지 데이터·예상 호출·교사 확인 여부를 독립적으로 정리한다. 차이는 합의하고 사람 간 불일치 건수를 기록한다.
2. **경로 실행:** 준비용 5건으로 수집 대역을 확인한다. 로컬 모델·버전·설정과 전송 코드를 고정하고 평가 경로마다 1회 실행한다. 오류·재시도 경로의 요청도 전송 직전에 수집하며 실제 네트워크 전송은 하지 않는다.
3. **대조와 기록:** 요청 전체와 호출 순서를 정답에 대조한다. 복원·수정 경로에는 고정된 가명 초안 응답을 사용한다. 요청이 실제 수집되는지 준비 단계에서 확인해 감시 장치 고장과 호출 차단을 구분한다.

| 실행 준비 | 현재 상태 |
|---|---|
| 로컬 모델·설정·전송 구현·실행 환경 | 미선정 |
| 가상 데이터·음성·매핑·파일 버전 | 미준비 |
| 독립 라벨·합의 정답·수집 대역 | 미작성·미준비 |
| 팀의 기준 확정·실행 코드·명령 | 미확정·미실행 |

## 5. 결과

| 항목 | 결과 |
|---|---|
| 평가 완료·통과 건수 | 미측정 / 목표 30건, 기준 27건 이상 |
| 금지 데이터 요청·금지 재호출 건수 | 미측정 / 기준 0건 |
| 정상 요청·차단 경로별 통과 건수 | 미측정 |
| 사람 간 라벨 불일치 | 미측정 |
| 소요 시간·실제 외부 호출 | 미측정 / 상한 6시간, 외부 호출 0건 |
| 수집 요청·합의 정답·채점 파일 | 미생성 |
| 실험 판정 | 미실행 |

오류는 실명 잔존, 원본 음성 포함, 매핑표 포함, 실패 후 호출, 복원·수정본 재호출, 정상 호출 누락, 수집 오류로 구분한다. 대역 검사만으로 배포 환경의 모든 외부 통신을 검증했다고 보고하지 않는다.

## 6. 판단과 재도전 조건

현재 판단: **보류 — 전송 구현·수집 요청·정답이 없다.** 실험 계획의 작성은 개인정보 처리 경계의 통과를 뜻하지 않는다.

- **기준 충족:** 평가한 경로에서 전송 경계의 채택 근거를 남기고 SPEC 4절·AC10에 실험 근거를 연결한다.
- **기준 미달·치명 오류:** 외부 AI 연결 방식을 채택하지 않는다. 가명 검증·호출 차단·재호출 경계를 보완하고 SPEC과 관련 골든 케이스에 변경 이유를 기록한다.
- **미완료:** 준비 부족과 확인한 경로만 기록하고 보류한다. 이 처리를 이유로 도메인 클래스를 추가하지 않는다.

재도전은 누출·우회 경로와 수집 누락을 보완한 뒤 새로운 평가 데이터로 진행한다. 실행 조건과 회차는 이 절 아래에 남긴다.
