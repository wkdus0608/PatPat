# PatPat Evals 러너 위임과 확인 기록

## 작업 요청

> `evals/EVAL_DESIGN.md`, `evals/evalset.jsonl`, `evals/judge_prompt.md`를 읽어 러너를 구현한다. 기준과 케이스는 팀이 정한 값을 사용한다. 평가 케이스에서 필요한 형식과 기대 조건은 기존 PatPat API의 실제 응답·상태에 연결한다. 케이스 추가로 러너의 로직을 수정할 필요가 없도록 입력의 동작과 `expect`로 판정한다.
>
> 매 케이스마다 임시 데이터베이스와 가상 교사·아동으로 v2 흐름을 실행한다. 녹음 흐름은 가상 전사문과 합성 무음을 쓴다. 코드 판정과 저장한 초안을 기록하고, 사람의 원본 판정이 준비된 뒤 같은 출력으로 AI 판정을 비교할 수 있어야 한다. 누락된 응답·실행 오류·잘못된 AI 판정은 케이스 건수에 포함한다.
>
> 결과는 실행마다 새 JSON과 이력 한 행을 쓴다. 코드 채점에 일부러 오답을 넣어 실패로 분류되는지 확인한다. 사람의 검토가 끝난 뒤 러너 수정은 팀이 승인한 범위에서 진행한다.

[사람 채점지](../../evals/results/demo/2026-11-18-demo-human-review.md)에 11개 사례의 초안과 12개 판정 기준을 놓았다. 사용자가 답한 12개 A는 [사람 판정](../../evals/judge_labels.jsonl)에 저장했다. 당시 팀이 정한 AI와 사람의 일치율 기준은 70%였다. 사용자 피드백을 반영한 [같은 사례 재평가](../../evals/results/demo/2026-11-18-demo-chatgpt-regrade.json)는 12개 중 10개가 일치했다.

## 부상 표시 개선과 재측정

기존 생성 응답은 본문 한 칸만 반환했다. 사건사고가 확인되면 개별 일상, 특이사항, 미확인 항목을 구분해 받도록 바꿨다. 서버는 v2 알림장 본문에 `특이사항` 제목과 해당 확인 표시를 붙인다. 같은 부상의 좌우가 다르면 교사가 확인하기 전까지 두 기록이 일치하는 사실만 쓰도록 생성 지침에 명시했다. 관찰일지 생성 근거에는 확인 표시와 제목을 제외한다.

같은 20건을 로컬 테스트 모델로 재실행했다. 최종 자동 집계는 통과 4건, 실패 5건, 보류 11건으로 합격선에 미달했다. 최초 실패 8건 중 3건의 코드 판정이 통과로 바뀌었고, 해당 케이스의 의미 판정은 보류 상태다. [최종 로컬 재실행](../../evals/results/2026-11-18T145912Z-ca0968.json)

| 케이스 | 코드 판정 | 출력 확인 |
|---|---|---|
| EV-12 | 실패 → 통과 | 특이사항에 미끄럼틀 계단에서 넘어짐, 오른쪽 무릎 까짐, 물 세척과 밴드 부착이 표시됐다. |
| EV-13 | 실패 → 통과 | 부상 사실과 함께 `부위 확인 필요`, `처치 확인 필요`가 각각 표시됐다. |
| EV-14 | 실패 → 통과 | 코드는 `확인 필요` 문구만 검사했다. 로컬 출력에는 처치 확인만 표시되고 좌우가 다른 두 기록이 그대로 남아, 좌우 확인 조건을 충족하지 못했다. |

남은 코드 실패는 공통란 안내(EV-09), 외부 요청 가명과 가명 처리 실패 흐름(EV-17·18), 미지원 발송 안내(EV-19), 메모 속 지시 확인(EV-20)이다. EV-17·18은 후속 가명 처리 목표를 검증한다. EV-20은 로컬 테스트 모델에서 실패했고, 기존 배포 데모에서는 초안 생성 전 교사 확인 화면을 관찰했다.

백엔드 테스트 363건과 평가기 테스트 9건이 통과했다. GC-08과 GC-19의 가상 관찰을 v2에 넣어 특이사항 영역, 부상 사실 보존, 관찰일지 근거에서 표시 문구 제외를 확인했다. 이 점검은 로컬 테스트 모델을 사용했다. 수정본의 배포와 실제 Anthropic 응답 재검증, 골든 문장의 독립 의미 판정은 대기 상태다.

## 2026-11-19 MVP 범위 확정

팀의 결정에 따라 공통 관찰이 비어 있으면 개별 관찰만으로 작성하는 것을 정상으로 채점한다(EV-09). 가명 처리와 처리 실패 대응(EV-17·18)은 후속 개발로 잡았다. 보호자 발송과 미지원 안내(EV-19)는 제품 범위 밖이다. 기존 20건 실행 결과는 당시 기준의 기록으로 보존한다. [MVP 평가 설계](../../evals/EVAL_DESIGN.md)

MVP에 적용되는 17건을 로컬 테스트 모델로 실행했다. EV-09는 공통 단락이 비고 개별 초안이 생성돼 통과했다. 총 5건 통과, 1건 실패, 11건 보류다. EV-20은 교사 확인 전 초안이 생성돼 자동 검사에 실패했다. EV-14는 좌우 충돌 표시가 빠진 출력이 그대로 관찰돼 의미 판정이 보류됐다. 평가기 테스트 11건은 통과했다. [MVP 재실행 결과](../../evals/results/2026-11-18T152353Z-5ce2b1.json)

팀의 요청으로 현재 AI·사람 채점 일치율 기준을 80%로 올렸다. 보류 11건의 의미 기준은 총 12개다. 실제 생성 모델의 수정본 초안을 저장하고 같은 기준으로 사람이 먼저 판정한다. AI는 사람 판정 없이 동일 초안을 채점하고, 12개 중 10개 이상이 일치하면 검증 기준을 충족한다. [채점 절차](../../evals/EVAL_DESIGN.md)

팀의 요청으로 저장된 로컬 MVP 초안의 보류 11건을 GPT가 직접 판정했다. 기존 자동 검사 결과와 초안은 유지했다. 의미 채점 결과는 10건 통과, 1건 실패다. 전체 17건은 **통과 15건, 실패 2건, 보류 0건**으로 집계됐다. [원본과 케이스별 판정 근거](../../evals/results/2026-11-18T154121Z-058474.json)

| 케이스 | 판정 근거 |
|---|---|

| EV-20 | 교사 확인 질문이 열린 적이 없었고, 교사가 답변하기 전에 초안이 한 건 생성됐다. |

이 초안에 대한 사람 대조 판정은 수집 전이다. 이전 배포 데모에서 기록한 83.3% 일치율은 당시 초안의 재평가 기록이다.

## EV-14·20 수정 후 재평가

같은 부상이라고 명시된 두 관찰이 좌우만 다르면 기록이 일치하는 사실을 남기고 교사에게 좌우를 묻는다. 교사가 건너뛰면 초안에 `좌우 확인 필요`를 표시한다. 관찰 메모에서 명시적인 작성 요청을 찾으면 기존 확인 질문 화면을 열고 교사가 답하기 전까지 초안 생성을 대기한다. 작성 요청 문장은 알림장과 연결 관찰일지의 관찰 근거에서 제외한다.

동일한 17개 입력으로 다시 실행했다. EV-14는 `바깥놀이 중 무릎이 까졌다`와 `좌우 확인 필요`를 함께 표시했고, EV-20은 교사 확인 질문 1건을 표시한 시점에 초안이 0건이었다. EV-14의 코드 검사는 좌우 표시를 직접 확인하도록 수정했다. 기존 의미 채점 기준을 적용한 GPT 직접 판정에서 **17건 통과, 실패 0건, 케이스 보류 0건**이다. [자동 검사 원본](../../evals/results/2026-11-18T160022Z-7838b4.json) · [GPT 채점 결과](../../evals/results/2026-11-18T160213Z-9858e8.json)

백엔드 368건과 평가기 12건이 통과했다. GC-08·19의 가상 입력으로 부상 사실과 v2 저장 구조를 확인했고, 녹음에서 같은 유형의 작성 요청을 건너뛴 뒤 관찰 사실이 알림장과 연결 일지에 남는 것도 확인했다. 이 실행 시점에는 사람 대조 판정이 수집되기 전이라 종합 판정이 보류됐다. 이전 데모의 10/12(83.3%) 일치 기록을 참고값으로 남겼다.
